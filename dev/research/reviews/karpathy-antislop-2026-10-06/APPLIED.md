## 승인한 UI 변경

**B. 키보드 포커스.** 기존 링의 색·두께 2px을 유지하고 불투명하게 표시한다. 페이지 배경에 대한 대비는 라이트 1.89:1 → 6.19:1, 다크 1.69:1 → 4.62:1이다. 공유 Button과 viewTabs, 닫기, 도우미의 개별 덮어쓰기까지 확인했다.

**C. 모바일 터치.** 화면 폭이 768px 미만이면 VS 바꾸기·공유·초기화 버튼을 32px → 44px, 상세창 닫기의 조작 영역을 16px → 44px로 늘렸다. 아이콘은 16px을 유지한다. VS 버튼 간격은 4px이다. 768px 이상에서는 기존 32px·16px을 유지한다. 모바일 챔피언 탭은 Enter·Space로 선택하고, 태블릿의 룬은 터치로 상세창을 열 수 있다.

**D. 자료 오류.** 아이템·룬·소환사 주문의 적재 중, 실패, 유효한 빈 목록을 구분한다. 실패에는 기존 번역의 오류 문구와 실제 재요청하는 버튼을 사용했다. 언어와 탭을 바꾼 뒤 늦게 끝난 요청이 새 화면을 덮지 않는다. 정상 화면 구성은 기존 방식이다.

기능 복구도 같은 오류 안내 방식으로 처리했다. 챔피언 상세 실패는 탭을 보존하고 재시도한다. 페이지 JS를 못 받으면 메뉴가 남고 다시 불러올 수 있다. 도우미 자료 실패는 저장된 대화를 지우지 않고 재시도로 복구한다. 모바일 메뉴·도우미·아이템 상세·선택창·도움말의 Escape, 포커스 복귀와 스크롤 복원을 확인했다. 정확히 768px에서 모바일 메뉴와 데스크톱 레일이 겹치던 경계도 맞췄다.

## JS 크기와 파일 분리

홈페이지를 새 브라우저 컨텍스트에서 열고, 동의 기록과 서비스 워커가 없는 상태로 `networkidle`까지 요청한 JS 파일을 합산했다. 이전 빌드와 최종 빌드를 같은 방법으로 비교했다.

| 측정 | 이전 | 적용 후 |
| --- | ---: | ---: |
| 처음 요청한 JS 전체 | 998,026 bytes | 666,346 bytes |
| 파일별 독립 gzip 합계 | 345,215 bytes | 217,054 bytes |
| 진입 JS 파일 | 626,837 bytes | 498,403 bytes |

초기 JS 원본 크기는 **33.23%**, 독립 gzip 합계는 **37.12%** 줄었다. [이전 요청 목록](applied-evidence/network-before.json)과 [적용 후 요청 목록](applied-evidence/network-after.json)에 실제 파일별 크기가 있다. gzip은 Node의 동일 설정으로 계산한 비교값이며 실제 HTTP 전송량·체감 속도를 측정한 값은 아니다.

도우미 버튼은 작은 `AdvisorLauncher`로 분리하고, 무거운 위젯은 처음 사용할 때 동적으로 불러온다. 닫아도 위젯을 유지하므로 대화·모델 상태가 남는다. 이미 모델 사용에 동의한 사용자는 기존의 백그라운드 적재를 유지한다. 실패한 모듈 URL은 다시 불러오기로 복구한다. 신규 동의 없이 모델 파일을 내려받지 않는다.

600kB 경고 기준을 올리거나 임의의 vendor 분할로 숫자만 줄이지 않았다. 최종 빌드에는 그 기준을 초과하는 JS 청크가 없다. **PWA 설치는 기존 정책에 따라 모든 JS 청크를 미리 캐시하므로, 오프라인 설치 전체 다운로드가 33% 줄었다는 뜻은 아니다.** 초기 요청과 실행 경로를 줄인 결과다.

썸네일 생성기 진입 파일은 **617줄 → 105줄**이다. 목록·이미지·시트/인덱스·발행을 `dev/scripts/data-pipeline/thumbnail*.ts`의 네 모듈로 나눴다. 전체 코드량을 줄이는 분할은 아니며, 실패 처리와 책임을 따로 검토할 수 있게 했다. 실제 sharp 픽셀을 사용한 테스트로 셀 순서, 격자, P·Q·W·E·R 슬롯과 인덱스를 확인했다.

## 재현해 수정한 코드 문제

### 데이터·오프라인 캐시

- `sessionStorage` 속성 접근이 차단되어도 선택적 캐시 때문에 앱 시작이 실패하지 않는다.
- HTTP 성공이어도 JSON·스키마·챔피언 ID가 틀리면 정상 데이터로 보관하지 않는다. 변환 계약이 있는 소비자는 보관 전에 검증한다. 챔피언의 빈 시뮬레이션 곡선은 거부하고, 의도적으로 빈 폼 쿨타임은 허용한다.
- Workbox의 CacheFirst가 잘못된 응답을 늦게 보관할 수 있어, 해당 경로의 재시도만 고유 쿼리로 원본에서 다시 받는다. 다른 오프라인 자료는 지우지 않고, 정상 응답은 표준 URL로 보관한다.
- 새 PWA 릴리스 준비 중 잘못된 패치·언어·챔피언 자료를 찾으면 현재 릴리스를 유지한다. 자료를 고친 뒤 재시도하면 새 릴리스로 전환한다. 패치 노트 소비자도 기존 decoder를 보관 전 검증에 연결했다.

### 도우미·저장 기록·생성 중지

- 실패한 모델 Promise를 재사용하던 문제를 수정했다. 모델·judge·임베딩 실패 시 관련 적재 상태를 초기화한다.
- worker 오류, 메시지 역직렬화 오류, 생성/전송의 동기 실패가 대기 요청을 영구히 붙잡지 않는다. 종료·언마운트 시 대기 요청과 타이머를 정리하고, 오래된 worker의 응답은 무시한다.
- precomputed 응답의 네트워크 오류·503·깨진 JSON은 재시도한다. 의도적인 404·410 음수 캐시는 유지한다.
- 손상된 저장 기록은 메모리에서 유효한 구조만 복원한다. 과거 정상 기록은 보존하며 검증 때문에 저장소를 덮거나 지우지 않는다.
- 모델 적재 대기 중 또는 worker 큐에서 대기 중에 중지한 질문은 나중에 생성되지 않는다. 새 질문은 정상 처리한다.
- 질문 한 개가 입력 예산 **1,900 토큰을 초과**하면 짧게 다시 작성하라는 오류를 반환한다. 정확히 1,900 토큰은 허용한다. 질문을 조용히 잘라 다른 질문으로 만들지 않는다.

### 계산·표시·HTML

- bonusMana·bonusAttackSpeed를 총량으로 오해하지 않도록 기존 번역의 추가 능력치 표기를 사용한다.
- 계산 토큰의 덧셈·뺄셈·곱셈·나눗셈, 중첩 계산 참조와 랭크·레벨 범위를 보존한다. 0으로 나누거나 지원하지 않는 형태는 잘못된 0을 만들지 않고 미해결/진단으로 남긴다. 생성된 게임 데이터는 다시 만들지 않았다.
- HTML의 이미지는 해당 앱의 숫자 버전 stat 아이콘 경로만 허용한다. protocol-relative·역슬래시·경로 이동·data·javascript URL을 거부하고 실제 stat 이미지는 표시한다.
- 중국어 아이템 검색에서 한자를 제거하던 정규화를 수정했다. 한글 초성 검색도 유지한다.

### 생성·연구 보조 스크립트

- 정적 자료와 썸네일은 임시 위치에 생성·검증한 뒤 교체한다. 가져오기·검증·발행 실패 시 기존 자료를 보존하고 교체 실패를 원복한다. 정리 작업은 성공 후 숫자 버전 디렉터리만 대상으로 한다.
- ORT 파일이 같은 길이라도 내용이 다르면 SHA256으로 찾아 다시 복사한다.
- manifest가 없는 패치 탐색은 연도와 패치 번호를 숫자로 정렬한다. 예를 들어 26.10은 25.24와 26.9보다 최신이다.
- Ollama 스트림이 `done: true` 없이 끝나면 성공한 답으로 처리하지 않는다.

## 전체 코드 점검의 범위

소스·스크립트·테스트·E2E **892개 파일, 88,384줄**을 인벤토리와 구문 검사 대상으로 삼았다. 실행 코드·입력 계약·캐시·저장·비동기 정리·렌더 경계는 담당을 나눠 검토했다. 주 에이전트는 통합 컴포넌트와 실제 실행을 다시 확인했다.

| 범위 | 파일 | 전문 또는 주요 코드·경계 검토 | 부분 검토 |
| --- | ---: | ---: | ---: |
| 앱 `src` | 368 | 263 | 4 |
| `scripts` | 356 | 55 | 11 |
| `tests`·`e2e` | 168 | 4 | 0 |

나머지 파일에는 자동 스캔과 해당 실행 검증을 적용했다. **892개를 모두 줄마다 수동으로 읽었거나 모든 버그가 없다는 결과가 아니다.** advisor의 일부 표시·타입·데이터 파일은 AST와 경계 검색으로 확인했고, 연구·학습 스크립트는 구문과 선택한 흐름 검토에 머문다. [파일별 기록](applied-evidence/coverage-files.json)은 검토 수준, 해시, 이후 변경 여부를 구분한다. 개별 담당 기록에는 재현과 반례도 남겼다.

Python **120개**는 AST 구문을 확인했으며 프로그램을 실행하지 않았다. public의 생성 자료·이미지, 의존성, lockfile, 연구 결과물과 vendored cache는 수동 코드 점검 대상에서 제외했다. 실행 데이터 계약은 별도의 data 테스트로 확인했다.

400줄·100줄 제한을 넘는 기존 코드도 기록했다. `context`, `grounding`, `prose`, 챔피언 사실 모델, 계산 파서와 번역 계약은 서로의 데이터·분기 관계가 강해 이번 오류 수정과 함께 대규모 분할하지 않았다. 이들은 다음 구조 개선 후보이며, 줄 수만 맞추기 위한 기계적 분할은 하지 않았다. 파일별 크기와 함수 위치는 [복잡도 기록](applied-evidence/coverage-summary.json)에 있다.

## 적용하지 않은 디자인과 남은 후보

**E. 이전 패치 대화의 출처.** 옛 답변을 현재 자료로 복원하면, 저장된 문장과 현재 카드가 다른 패치일 수 있는데 표기는 현재 패치만 보여 줄 수 있다. 기존 답을 보존하면서 각각의 작성 패치와 현재 자료 패치를 표시하는 [Before/After 시안](history-patch-proposal.html)을 만들었다. 38·40은 재현 예시라고 명시한 숫자이며 새 게임 통계가 아니다. 사용자가 고르기 전에는 앱의 표기를 바꾸지 않는다. 이 문제는 B·C·D나 저장 기록 구조 검증으로 해결됐다고 간주하지 않는다.

추가 후보는 모델 상태 해제 후 실제 GPU 메모리 반환, 고정 ORT/model runtime 캐시의 SDK 업그레이드 정책, 도우미의 독립 자료 요청을 병렬로 시작할 여지다. 측정·재현이 아직 없어 확정 오류로 적거나 추측만으로 변경하지 않았다.

이 작업은 로컬에 적용했다. 배포·커밋·외부 메시지는 수행하지 않았다. 기존 LLM 평가·프로토콜·LoRA·생성·lockfile 등 동시 작업 변경을 보존했다.
