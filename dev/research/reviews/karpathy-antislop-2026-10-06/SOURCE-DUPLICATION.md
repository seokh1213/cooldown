# 원본 코드·자료·문서 정리

2026-10-06. 첫 정리에서 유지보수 가치가 확인된 중복 3곳을 공통화했다. 제품 소스 8개 파일에서 1,407줄을 1,352줄로 줄였다. 새 공통 저장소 파일 1개를 포함한 순감소는 55줄이다. UI 디자인·JSX·CSS·드래그 동작은 변경하지 않았다.

## 후속 개선

사용자 승인에 따라 발견 내용을 실제 수정했다. 아래의 첫 정리 수치·발견 기록과 후속 결과는 구분한다.

- **조사 패치와 보존:** 26.18 원본 두 개를 보존하고 26.19 조사를 새로 실행했다. 자리표시자는 18개 스킬·6패치에서 복구 0건/미해결 18건, 소실 문장은 70패치에서 26개 스킬·35문장이다. 다운로드 실패는 0건이며 과거 조사 결과를 최신 결과로 이름만 바꾸지 않았다. 재실행은 완성된 임시 파일을 발행하기 전에 이전 원문을 history에 보존한다. 부분 조사는 실제 게임 ID를 검증하고 partial에 저장해 전체 최신 결과를 덮어쓰지 않는다. 결측 0건도 빈 결과를 발행하며 scan은 쓰지 않는다.
- **노트 참조:** 19개 플레이북의 생성 노트 21개에서 본문에 없는 이름 34개를 작성용 reviewRefs로 옮겼다. 이름과 다른 필드는 보존했고 생성된 본문 365개는 동일하다. 실행 번들에는 작성용 이름이 들어가지 않는다. 생성 후 실제 본문의 refs/avoid 이름·충돌 검증과 작성용 이름의 존재·구매 가능 검증을 유지한다. 팁 11건·플레이북 4,078건의 llm:validate 불일치는 34→0건이다.
- **형태 상세:** 현재 원본으로 렉사이 Q/W/E·렐 W·클레드 Q를 세 언어에서 연결했다. 9개 상세의 형태 부분만 갱신하고 필수 아이콘 10개를 기존 64×64 WebP·품질 82로 생성했다. 렉사이의 독립 쿨타임과 터널 재이용, 렐의 공유 비용, 클레드의 발사 간격과 탄환 재충전을 구분한다. 렐의 공통 Q/E/R은 복제하지 않는다.
- **클레드 사용 조건:** E/R에 탑승 상태에서만 사용할 수 있다는 조건을 세 언어의 본문과 정상 재생성 경로에 반영했다. 직접 근거는 [Riot 소개문 원문 보존본](https://web.archive.org/web/20160801083653id_/http://na.leagueoflegends.com/en/page/champion-reveal-kled-cantankerous-cavalier)의 “Mounted Only” 표기다. 2016년 발표문이며 현행 BIN에는 직접적인 차단 조건 필드가 없다. 현재 대체 스킬은 KledRiderQ만 제공하는 구조와도 대조했으나 이를 직접 차단 조건의 증명으로 취급하지 않는다.
- **도우미 형태 선택:** 특정 형태를 물어도 기본 형태 수치가 나오는 오류를 수정했다. 현재 형태의 본문·쿨타임·재충전을 사실 카드에 포함하고 명확한 형태를 선택하면 답과 참조 카드가 같은 형태를 쓴다. 모호하거나 상충하는 형태는 확인하며 다른 형태의 사거리·요약·기본 피해 수치를 빌려 쓰지 않는다. 기본 질문과 옛 저장본을 바꾸지 않는다.
- **클레드 콤보 재검수:** E/R 원문이 바뀌자 기존 콤보의 해시 검증이 발행을 막았다. 공식 원문·현재 스킬 본문·게시된 콤보 순서를 대조하고 탑승 유지·W 준비·E1 대상과 3초 이내 E2 조건을 보강한 뒤 클레드만 재검수일과 해시를 갱신했다. 다른 172챔피언과 전역 검수일은 보존하며 이후 원문 변경도 계속 거부한다.
- **승인 경계:** 첫 수정 직후에는 원문이 바뀐 클레드 Q/E/R·렉사이 Q/W/E·렐 W의 7개를 제외하고 858개 승인을 유지했다. 이후 7개를 현재 원문으로 재작성하고 [독립 검수](../../champion-mechanics/26.19-v3/reports/changed-slots-independent-review.json)를 거쳐 `26.19-v3`의 865개 승인을 실제 앱에 연결했다. 7개 슬롯의 규칙 50개와 미해결 원문 항목 10개를 확인했으며, 산탄 적중 순서·렐의 삭제된 self slow·클레드 R 수치 참조를 정정했다. 현재 원문·승인 집합과 실제 적재된 규칙의 ID·출처 지문·본문을 대조하고 이후 변경도 자동 승인하지 않는다.
- **미사용 코드:** 앱·워커·CLI·테스트 소비자를 확인한 뒤 옛 commentaryPrompt와 feedback 모듈을 제거했다. 피드백 파일을 읽는 수동 변환기는 필요한 타입을 내부에 두어 유지했다. 호출 없는 지식 렌더러, viewport wrapper, rune query, URL·아이콘·수치 helper도 제거했다. 사용되는 토큰화·자료 생성·현재/과거 디코더를 합치지 않는다. 정적 연결만으로 모든 코드 줄의 필요성을 증명했다는 뜻은 아니다.
- **번역 검수:** 고정 26.19를 입력 manifest의 패치 전달로 바꿨다. 기존 2인자 호출은 특정 패치를 주장하지 않는다. 검수 runner 25개는 통과했고 새 등록 테스트는 추가하지 않았다.
- **테스트 유지보수:** 형태 자료의 언어×챔피언 등록 21개를 하나의 전수 검사로 묶고 제이스 레벨 표도 세 언어를 한 검사에서 확인한다. 삭제한 해설 코드만 확인하던 등록 검사 2개를 제거했다. 현재 형태 선택은 실제 7챔피언×3언어 원문을 한 회귀 검사로 확인한다. 기존 브라우저 검사 안에 새 형태와 이미지 확인을 넣어 E2E 등록 수를 늘리지 않았다.

답변 표시의 기존 2초 목표도 보강했다. 타이머 호출 횟수만 누적하던 코드는 callback이 늦어지면 표시 시간을 늘렸다. 실제 경과 시간으로 따라잡도록 바꾸고, 기존 hook harness에서 지연·완료·다음 답변·해제를 한 회귀로 확인했다. 최초 전체 E2E의 첫 답변 완료 5초 시간 초과와 별개로 재현한 결함이며, 해당 단일 실패의 원인을 확정했다고 주장하지 않는다.

작업 중 원격에 추가된 영상 판정·후속 대화 변경도 보존해 합쳤다. 영상 질문 161개와 저장 복원 대화 12개를 모두 확인하면서 등록 테스트 173개를 2개로 묶었다. 질문·세션은 각각 독립 context를 쓰고 실패 문맥을 오류에 포함한다. 의미상 검증과 자료를 삭제하지 않았다.

진행 중인 별도 품질·학습·원격 평가 도구와 캐시는 이 커밋에 포함하지 않는다. 앱이 실제 참조하는 QA 그래프와 해당 소스·회귀 검사는 함께 포함한다. 제외된 도구를 현재 실행 명령이나 존재하는 문서 링크로 안내하지 않도록 연결을 맞췄다.

## Kled 재발 조사와 추가 정정

원격 `Update Static Data` [37404456577](https://github.com/seokh1213/cooldown/actions/runs/37404456577)과 [37430174120](https://github.com/seokh1213/cooldown/actions/runs/37430174120)은 성공했지만 같은 Kled 본문 변경을 [이슈 39](https://github.com/seokh1213/cooldown/issues/39)에 반복 보고했다. E/R의 탑승 전용 문장을 추가한 뒤 콤보 2개만 재검수하고 챔피언 지문과 플레이북 22개 항목을 갱신하지 않은 것이 원인이다.

이번에는 노트 24개를 모두 읽고 W를 직접 켠다는 설명, E2 자유 이탈, 탑승 중 용기 충전, 미니언 일반 공격의 용기 획득, 후반 기본 공격 피해 감소와 주변 적 수에 따른 자동 용기 증가를 정정했다. 16레벨부터 미탑승 기본 공격의 챔피언 피해 감소가 없다는 [Riot 25.14](https://www.leagueoflegends.com/en-us/news/game-updates/patch-25-14-notes/)와 현재 26.19 본문을 대조했다. 26.17 통계를 담은 4개 노트는 당시 자료와 검수 패치를 유지했다.

E/R 본문 변경으로 무효화된 군중 제어 지문을 현재 원문에 맞게 검수했다. 알려진 미니언·몬스터·자신·아군 효과를 챔피언 군중 제어로 세지 않도록 생성 규칙을 좁혔다. Kled 탈출 노트는 탑승 E/R, 동일 대상 E2와 미탑승 Q 반동·탄환 상태를 보존하는 수동 노트로 바꿨으며 같은 분류의 생성 노트가 중복 발행되지 않게 했다.

Kled 수동 노트 21개와 원자 68개, 영어·중국어 다듬은 번역 각 21개를 함께 갱신했다. 노트별 한국어 본문 SHA-256인 `sourceDigests`가 본문 변경·삭제를 감지하면 해당 번역을 발행에서 제외한다. 이 검수와 지문 보호의 범위는 Kled 21개이며 다른 챔피언의 기존 번역에 자동 승인을 부여하지 않았다. 현재 v3의 865개 승인은 변경 감지에서 모두 재사용 가능하고 재작성 대기는 0개다. 최종 실행 결과는 [후속 검증 기록](FOLLOWUP-VERIFICATION.md)에 정리한다.

## 점검 범위와 기준

`src`와 `scripts`의 원본을 AST와 검색으로 조사하고, 후보의 호출 경로·검증 계약·예외·기존 테스트를 직접 비교했다. 자동 생성 코드, 번역 레코드, 타입 선언, 설치된 의존성, 빌드·모델·연구 산출물은 중복 판단에서 제외했다. 모든 원본 줄을 사람이 다시 읽었다거나 모든 중복을 제거했다는 의미는 아니다.

같은 이유로 함께 바뀌어야 하는 로직을 공통화했다. 모양이 비슷해도 데이터 수명·신뢰 경계·실패 정책이 다른 로직은 유지했다. 단순 getter, 짧은 CLI 인자 조회와 정규식은 공통화로 절약하는 양보다 호출 추적 비용이 커 우선순위에서 제외했다.

AST 재스캔 시점의 원본 코드 파일은 741개다. TS/JS 605개와 Python 122개를 파싱했다.
TS/JS 함수·콜백 5,881개에서 비단순 후보 1,278개, Python 비단순 함수 190개를 비교했다.
독립적인 동일 AST 묶음 3개와 근접 후보 15쌍을 검토했고 Python의 동일 함수 묶음은 0개였다.
이는 함수 단위의 비교이며 모듈 전체의 임의 코드 조각이나 모든 의미상 중복을 증명하는 검사는 아니다.

400줄을 넘는 유지보수 코드 11개와 100줄을 넘는 TS/JS 함수·컴포넌트 33개를 책임 검토 대상으로 기록했다.
가장 긴 파일은 `calculationPartEvaluator.ts` 626줄, `prose.ts` 578줄, `grounding.ts` 572줄이다.
그 밖에 `facts`, `facts-analysis`, `context`, `variableReplacer`, `fetch-ability-fallbacks`,
`translate-matchups`, `precompute-matchups`, `offline-classifier/train.py`가 해당한다.
파일 길이는 오류 개수가 아니며 JSX·계산식 분기의 책임을 숫자만 맞추려고 쪼개지 않았다.

## 적용한 변경

### 1. 정적 데이터 저장소의 캐시·검증·동시 요청

`ChampionRepository`와 `GameDataRepository`에 반복되던 버전 검증, 캐시 재사용, 동시 요청 공유, 실패한 요청 정리를 [StaticDataRepository](../../../../src/infrastructure/repositories/staticDataRepository.ts)로 모았다. 캐시 키·URL 6종과 기존 public API는 유지했다. 챔피언 상세·프로필의 ID 검증 및 종류별 디코더는 각 저장소가 계속 소유한다.

HTTP 캐시에 쓰기 전 검증과 저장소 캐시에 쓰기 전 검증은 모두 필요하다. 실제 HTTP 클라이언트는 전자를 실행하지만 주입한 클라이언트는 콜백을 생략할 수 있으므로 후자도 유지했다. 성공한 manifest Promise를 계속 재사용하는 `ManifestRepository`는 다른 수명 정책을 갖고 있어 합치지 않았다.

독립 검토에서 public API, 키·URL, 요청 공유·재시도·검증 순서의 회귀를 찾지 못했다. 원본 사본과 API 비교 증거는 `/tmp/cooldown-source-refactor-20261006/repository-before/`와 `repository-api-comparison.json`에 있다.

### 2. PC·모바일의 스킬 랭크별 쿨타임 계산

두 `SkillsSection`의 동일한 `maxLevel`·`skillRows` 계산을 기존 [utils.ts](../../../../src/features/champions/comparison/utils.ts)의 `buildSkillRows(champions)`로 추출했다. 각 화면은 자기 `useMemo`와 렌더링을 유지한다. 별도 UI 컴포넌트나 viewport 옵션을 만들지 않았다.

원래 계산과 빈 챔피언, 스킬 없음, 빈 스킬, 5·3랭크 혼합·0초·재충전 우선 경계를 비교해 결과가 같음을 확인했다. AST 토큰 비교에서도 계산과 import를 제외한 두 컴포넌트의 JSX·CSS·DnD가 같았다. 기존 ability-form 테스트 24개가 변경 전후 모두 통과했다. 새 파일·유지보수 테스트는 추가하지 않았다.

### 3. 답변·비교표의 다국어 스킬 수치 포맷

[spellAnswer.ts](../../../../src/features/advisor/answers/spellAnswer.ts)의 `spellFocusValue`가 스킬 사실·강조 수치·비교표에 쓰는 값을 함께 만든다. 기존 `answer.ts` export는 re-export로 유지했다. 런타임 순환 참조는 만들지 않았으며 `spellAnswer.ts`의 answer 타입 참조는 type-only다.

행 순서, 충전·재충전·연속 시전 간격, 단일·랭크별 사거리, 비어 있는 값, CC 전용 행은 각 기존 표시 계약에 남겼다. 26.19 패치의 3언어·519개 카드·2,595개 스킬에서 만든 18,684개 출력 레코드가 변경 전후 바이트 단위로 같았다. 기존 관련 테스트 51개도 변경 전후 통과했다. 유지보수 테스트는 추가하지 않았다.

## 별도로 재현해 수정한 오류

기존 프로필 저장소는 `cache.get()`을 복구용 `try` 밖에서 실행했다. 메모리에 손상된 JSON 구조나 다른 챔피언 ID가 남으면 디코더가 던진 예외 때문에 정상 데이터를 다시 받지 못했다.

공통 저장소는 캐시 디코드·ID·버전 검증 실패를 캐시 삭제 후 재요청으로 복구한다. 다운로드 실패와 잘못된 서버 응답은 계속 호출자에게 실패로 전달한다. 손상 캐시와 다른 ID 캐시를 확인하는 회귀 테스트 1개를 추가했고, 원본에서 실패한 뒤 수정 후 관련 29개가 통과했다. 재요청 성공 뒤 캐시를 재사용해 불필요한 두 번째 요청이 없다는 것도 확인한다.

## 합치지 않는 것이 좋은 코드

- **과거 대화 snapshot과 현재 데이터 디코더:** 저장 당시 카드·패치·언어의 불변 계약과 현재 네트워크 입력 검증은 서로 다르다. 현재 데이터 조회 훅으로 과거 카드를 통합하면 다시 최신 카드가 섞일 수 있다.
- **정적 데이터 발행과 썸네일 발행:** manifest 마지막 교체 조건과 이미지·색인 일괄 rollback 조건이 다르다. 범용 transaction 옵션을 만들면 실패 상태의 조합이 늘어난다.
- **원자적 덮어쓰기·불변 archive·staging·원격 연구 패키지 IO:** 파일 연산이 비슷해도 수명과 원자성 조건이 다르다.
- **필수 자료 HTTP retry와 선택 metadata 조회:** 하나는 retry 후 실패를 전달하고 다른 하나는 부가 자료가 없어도 진행한다.
- **모델 backend·Tensor·평가 golden:** 실행 라이브러리와 메모리 해제 조건이 다르고, 기대값 검증 코드는 실제 실행 코드와 독립이어야 한다.

## public/data 통합 검토

조사 당시 배포 데이터의 보관 패치는 26.19 하나이며 1,584개 파일과 31개 묶음 시나리오를 비교했다.

다음 수치는 gzip level 9의 로컬 측정이며 CDN·Brotli·실제 지연이나 JS heap 측정은 아니다.

- **전체 1파일:** gzip 15,699,832바이트, JSON 본문 76,625,690바이트다. 파일 수를 줄이려고 사용하지 않는 언어·챔피언까지 첫 로딩에 받게 만들지 않았다.
- **한국어 일반 게임 자료 350파일:** 한 묶음은 gzip 504,061바이트다. 현재 챔피언 목록 색인은 5,862바이트, 상세 1개의 중앙값은 3,287바이트, 프로필 1개의 중앙값은 779바이트다. 서로 다른 요청 범위를 비교한 수치다.
- **한국어 상성 170파일:** 한 묶음은 gzip 3,629,927바이트다. 현재 내 챔피언의 상성 파일 하나만 받으며 중앙값은 21,253바이트다. 전체 상성 수집을 초기 요청으로 바꾸지 않았다.
- **한정된 미래 후보:** 도우미가 함께 쓰는 현재 언어의 카드·아이템·룬·소환사 주문 4개만 묶으면 초기 JSON 요청은 9→6개다. 한국어 gzip은 376,880→365,810바이트지만 별도 파일의 공백 제거 효과를 제외한 묶음 절약은 1,159바이트다. 실제 요청 지연 개선을 측정하기 전에는 새 pack을 추가할 근거가 약하다.

`advisor-knowledge.json`은 이미 도우미용 지식의 단일 배포 번들이다. 편집용 지식·기초 문서는 생성 입력이며 상세·프로필·사실 카드·상성은 소비자와 계약이 달라 삭제하지 않는다.
