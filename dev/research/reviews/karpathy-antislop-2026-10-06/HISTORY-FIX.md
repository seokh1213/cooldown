# 과거 대화와 당시 카드 복원

**새로 저장하는 답변은 당시 카드와 출처를 함께 보존한다. 카드 원본이 없는 기존 기록도 대화 자체는 삭제하지 않는다.**

사용자가 요청한 동작은 과거 답변과 과거 카드의 복원이다. 앞선 E 시안의 현재 카드 대체 방향은 채택하지 않았다. 기존 카드 배치·색·크기를 유지하고, 구분에 필요한 패치 표기와 실패 안내만 추가했다.

## 원인과 변경

이전 저장 형식은 챔피언 ID와 일부 답변 값만 남겼다. 복원하면서 현재 `cardById`와 `ruleIndex`를 조회해 옛 답변과 최신 카드가 섞였다. 사라진 ID는 질문과 답변을 함께 삭제했고, 다시 저장하면 다른 패치의 기억 정보도 사라졌다.

이제 새 답변에 카드·스킬·규칙·비교·후보·아이템 원본과 생성 시작 당시 패치·언어·Data Dragon 버전을 저장한다. 카드 원본은 복제해 원래 자료의 변경과 분리하고, 복원할 때 중첩 구조와 카드 ID 연결을 검증한다. 정규화 상세 자료도 다운로드에 성공하면 같은 출처인지 검증한 뒤 함께 저장한다.

복원한 카드는 저장된 기본·상세 자료만 표시한다. 현재 상세 자료를 다시 받아 옛 마나·스킬·툴팁을 덮지 않는다. 같은 챔피언의 다른 패치는 별도 자료 탭으로 남고, 중복 탭에는 패치를 보인다. 같은 패치의 출처가 언어나 자료 버전으로 구분되면 해당 값도 표시한다. 일반 탭의 이름은 유지한다.

카드에서 현재 앱 화면으로 가는 링크는 “현재 자료로 이동”이라고 표시한다. 옛 카드의 패치 표시는 당시 출처를 따른다. 기존 기록에 출처가 없으면 저장된 기억의 패치를 사용하고, 그마저 없으면 패치 미상으로 표시한다.

## 기존 기록과 저장 실패

**기존 저장 기록에 당시 카드 원본이 없으면 정확한 복원은 불가능하다.** 현재 카드로 대체하지 않고 당시 질문과 답문을 보존하며, 카드 원본이 없다는 안내를 표시한다. 원본 없이도 내용이 완결되는 기존 아이템·전문 답은 복원할 수 있다. 깨진 카드 원본도 같은 방식으로 답문을 보존한다.

복원한 발화를 다시 저장해도 원래 카드 ID·기억·패치·원문을 유지한다. 다른 패치의 기억은 새 질문의 현재 자료 해석에 사용하지 않지만, 저장 원문에서 지우지 않는다. 최신 자료 요청이 실패하거나 지연되어도 저장된 대화는 즉시 열 수 있다.

카드 원본을 저장해 이전보다 저장량이 늘어난다. `localStorage` 저장 공간 부족이나 접근 차단이 생기면 실패 안내와 재시도 버튼을 표시한다. 미저장 대화는 현재 세션에서 유지하고, 페이지를 닫으면 새 답변을 잃을 수 있음을 안내한다. 용량 문제를 숨기려고 기존 대화를 추가로 삭제하지 않는다. 기존 보관 한도인 **최근 20개 대화, 대화당 80개 발화**는 유지한다.

당시 상세 자료 다운로드가 실패한 경우에는 저장된 기본 카드로 표시한다. 이미지 파일 자체를 대화에 복제하지 않으므로 옛 버전 이미지의 이용 가능성은 해당 자산 보관 상태에 따른다.

## 검증

**단위·데이터 2,289/2,289, 전체 브라우저 188/188 통과.** 타입·lint·production build도 통과했으며, 마지막 현재 자료 이동 검사는 별도로 5/5 통과했다.

검증 결과는 [증거 폴더](history-evidence/)와 [Delivery Gate](HISTORY-DELIVERY-GATE.md)에 기록한다.

원본 구조 검증은 실제 세 언어 카드 519개와 모든 스킬을 검사했다. 회귀 검사는 다른 패치·삭제된 챔피언·깨진 원본·여러 카드 중 일부 실패·원문 재저장·생성 도중 출처 변경·상세 출처 불일치·저장 용량 실패와 재시도를 포함한다.

브라우저에서 실제 새 답변 저장과 새로고침, 과거 기본·상세 수치 전환, 현재 상세 요청 0건, 최신 자료 실패 중 옛 답문 복원, 저장 실패 후 키보드 재시도를 확인했다. 360·390·768·1024·1440px의 두 테마에서 카드·원본 없음 상태 20개, 저장 실패 상태 4개를 검사했다. 예시 601·602·111·222는 분리 동작을 검증하기 위해 명시적으로 만든 테스트 값이며 배포 데이터는 수정하지 않았다.

일반 자료 탭 이름과 같은 챔피언의 스킬 자료 재사용도 회귀 검사에 포함한다. 기존 대화 테스트는 새 정책에 맞춰 최신 자료를 기다리지 않는 복원과, 새 질문이 자료 준비를 기다리는 동작을 검증한다. 아이템 키보드 검사는 보이는 즉시 입력하던 경합을 줄이기 위해 실제 포커스와 열기 애니메이션 완료를 확인한 뒤 Escape를 입력한다.

## 파일 정리와의 관계

파일 수를 줄이는 후보는 별도 [파일·테스트 정리 결과](FILE-NECESSITY.md)에 정리했다. 카드 복원 작업 당시에는 미사용 5개를 삭제하지 않았으며, 후속 승인 후 정리에서 제거했다. 이번 카드 복원 코드는 저장 검증·상세 로딩·React 훅·참조 컨텍스트의 책임을 나눴다. `history.ts`는 292줄, `useAdvisorHistory.ts`는 123줄이며 기존 `AdvisorPanel.tsx`는 400줄을 유지한다.
