# 26.20 스킬 틱 전수조사

173챔피언의 P/Q/W/E/R 865슬롯을 Riot 툴팁과 LoL Wiki의 1,071개 스킬 문서 및 애니 소환수 문서 1개에 대조했다. 136슬롯에 확인된 반복 판정 145개를 추가했다. 6슬롯은 불확실한 이유를 표시하고, 나머지 723슬롯은 해당 자료에 스킬 자체의 피해·회복 틱이 명시되지 않은 것으로 분류했다.

136은 모든 항목이 완전히 밝혀졌다는 뜻이 아니다. 간격만 확인되면 간격만 제공하며, 지속시간이나 횟수는 비워둔다. `not_documented`도 틱이 절대 없다는 뜻이 아니다.

## 조사 범위와 근거

- 피해·회복, 연속 타격, 자원·중첩 변화, 보호막 및 명시적인 강화·감소 주기를 조사했다. 각 효과의 이름으로 피해 틱과 다른 반복 판정을 구분했다.
- 재충전 쿨타임, 서버 공통 통계 갱신, 시야·애니메이션·AI 탐색 타이머, 일반 소환수 평타 간격은 지속 피해 틱으로 분류하지 않았다. 티버의 피해 오라는 별도로 포함했다.
- MediaWiki API로 현재 문서와 리다이렉트를 수집했다. 모든 슬롯에서 주 문서를 확보했다. 보조 별칭 12개는 없는 문서로 남으며, 해당 슬롯의 주 문서 누락과 구분한다.
- `audit.json`은 865슬롯의 문서 URL, 위키 리비전 및 영구 링크, 원문 SHA-256, 검토 필드 SHA-256, 수치 탐색 표식을 보존한다. 긴 위키 원문은 저장소 및 앱에 포함하지 않는다.
- 앱에 넣는 값은 `dev/data/knowledge/ability-ticks.json`의 검수 데이터다. 본문에서 ‘초’만 추출하거나 모델이 숫자를 생성하는 방식으로 만들지 않았다.
- 문서 검수 결과이며 게임 클라이언트의 프레임·타격 로그를 직접 계측한 결과는 아니다. 경계 시점·접촉 유지 여부의 예외를 문구로 함께 제공한다.

## 확정하지 않은 항목

- 브랜드 P: 4초 총피해와 틱당 피해 표기의 산술이 일치하지 않는다. 중첩별 적용 시점도 달라 횟수와 틱당 피해를 확정하지 않았다.
- 블라디미르 E: 미확인 주기는 충전 중 자신의 체력 소모다. 방출 피해는 같은 적에게 한 번만 적용된다.
- 케인 P: 전투 이탈 70초 뒤 내부 자원 초당 0.8 회복은 명시되나 실제 갱신 간격은 없다.
- 람머스 Q: 초당 이동 속도 증가량과 최대 6초 지속을 1초 갱신이라고 해석하지 않았다.
- 럼블 P: 기본 스킬 중단 4초 또는 R 중단 2초 뒤 열기 초당 10 감소는 명시되나 실제 갱신 간격은 없다.
- 사일러스 R: 레넥톤 R을 훔쳤을 때 마나 20 + 초당 5라는 조건부 효과의 실제 갱신 간격이 없다.

## 계산 시 주의한 사례

- 코르키 E: 0.25초 간격, 4초, 계속 적중하면 16틱. 표시 총피해 ÷ 16은 방어력 적용 전 1틱 피해다. 4틱에 최대 저항 감소, 마지막 적중 후 2초의 감소 잔류는 추가 피해 시간이 아니다.
- 코르키 W: 0.5초 간격, 불길 2.5초 = 5틱분. 이탈 뒤 피해 1초 잔류와 경계 판정 때문에 실제 적중 횟수를 5회로 보장하지 않는다.
- 카시오페아 W: 5/19초, 약 0.2632초 간격. 19틱 및 간헐적 18틱 사례를 제공한다. 0.25초·20틱으로 반올림하지 않는다.
- 워윅 R: 6틱의 홀수 피해 2/9, 짝수 1/9. 적중 시 효과는 1·3·5틱이다.
- 가렌 E·벨베스 E·루시안 R: 공격 속도나 치명타 등에 따라 횟수·간격이 달라진다. 고정 숫자로 대체하지 않는다.
- 말자하 R: 제압 피해 0.25초/2.5초/10틱과 바닥 지대 0.5초/5초/10틱을 분리한다.
- 우디르 각성 Q: 즉시 1회 + 0.2초마다 5회 = 총 6회다. 지속시간을 간격으로 나누어 5회로 만들지 않는다.
- 피들스틱 W·소라카 Q: 끝 틱 추가 피해 또는 회복량 분포가 달라 총량을 횟수로 균등 분할하지 않는다.
- 벨코즈 R: 피해 0.2초와 패시브 중첩 0.7초를 구분한다. 문서 2.6초와 공식 툴팁 2.5초가 달라 지속시간·총횟수는 확정하지 않는다.
- 멜 E: 피해 0.125초와 이탈 후 0.25초 잔류만 제공한다. 속박 지속시간 1.5초를 장판 지속시간으로 사용하지 않는다.
- 제이스 W·니달리 W·흐웨이 QE: 형태나 하위 스킬을 구분한다. 다른 형태에 동일 틱을 복사하지 않는다.

## 변경 및 갱신 절차

1. `npm run llm:ticks:collect -- /tmp/cooldown-tick-sources-<patch>.json`으로 현재 문서를 모은다. 출처는 재수집되지만 숫자를 자동 승인하지 않는다.
2. 원문·공식 툴팁을 대조해 `dev/data/knowledge/ability-ticks.json`을 수정하고, 새 패치의 검토 해시를 보존한다. 미확인은 이유와 함께 남긴다. `npm run llm:ticks:record -- /tmp/cooldown-tick-sources-<patch>.json`으로 원문을 제외한 조사 기록을 생성한다.
3. `npm run llm:build -- --lang ko_KR`, `en_US`, `zh_CN`을 차례로 실행한다. 패치 또는 한국어 툴팁의 정확한 SHA-256이 달라지면 이전 값 대신 미확인 상태를 생성한다.
4. `npm run llm:prepare-release`로 배포와 같은 번들·번역·상성 유지·콤보 검수 단계를 실행한 뒤 `npm run llm:ticks:audit`와 `npm test`를 실행한다. 모든 슬롯, 언어, 형태, 기록 복원, 버전 및 본문 변경 시 차단을 검사한다.
5. `npm run build` 후 `npm run test:e2e -- --workers=2`로 웹 전체를 검사한다. 틱 집중 확인에는 `npx playwright test dev/tests/e2e/advisor-multi-skill-reference.spec.ts`도 사용할 수 있다. 실제 브라우저와 배포본도 확인한다.
6. `npm run llm:test:audit`로 테스트 목록을 갱신하고 기존 품질 회귀를 통과시킨 뒤 master에 반영한다. Advisor Regression Actions에 틱 데이터 검사를 추가했다.

## 구현·검증 기록

카드와 채팅은 동일한 구조화 데이터와 번역을 사용한다. 틱 정보는 접힌 ‘스킬 정보’ 밖에 표시하고, 근거 문서 링크를 제공한다. ‘W, E 틱’처럼 끝에 붙은 공통 조회 항목을 앞 스킬에도 적용하며, ‘W는?’ 후속 질문에도 틱 주제를 유지한다. 답변을 챔피언 이름별로 분기하지 않는다.

테스트: 틱 단위·대화 통합은 24개다. 확인·미확인 142슬롯 전체 조회, 세 언어 일치, 변신 형태, 모델 사용 여부에 따른 같은 근거 조회, 저장·복원 및 이름 속 음절 오인 방지가 포함된다. 기존 영상 팁 테스트로 ‘피들스틱’의 ‘틱’ 오인을 발견해 고쳤다. ‘내 E와 R이 쿨타임인데 어떻게 해?’를 수치 조회로 잘못 분리하는 경우도 기존 회귀로 발견해 막았다.

전체 자동 테스트는 배포 파이프라인 수정 뒤 1,489/1,489, 웹 전체는 로컬 및 GitHub에서 216/216, lint·타입 검사·프로덕션 빌드 통과. 집중 브라우저 검증 4/4 통과: 390/1280px, 다크 모드, 단일 카드와 자료 패널, 기록 복원, 후속 질문, 알려진/미확인/미기재 값, 키보드 근거 펼침, 44px 출처 링크를 확인했다. 실제 사용자 Chrome의 로컬 및 배포 화면에서도 원래 W·E 질문과 ‘그럼 E는 몇 틱?’ 답변을 확인했다.

전체 품질 회귀는 5,893건 실측, 인프라 12/12, 누락·신규 실패·잘못 수락한 수치 0건이다. 통과 5,796건, 기존 실패 77건, 수동 검수 20건을 그대로 보존했다. 틱 메타데이터 때문에 dataHash가 변경되어 저장소 절차대로 전체 실측 기준을 갱신했다. [기준 갱신 근거와 실패 목록](baseline-refresh.json)에 상세히 기록했다. 출처 색상과 배포 파이프라인까지 반영한 최종 앱 소스의 전체 회귀도 master Actions에서 통과했다. 기존 실패·수동 검수는 해결하거나 승인한 것이 아니며 자동 채택 상태도 여전히 needs-review다.

UI 검수 기준: 기존 스킬 표 배치 유지, 틱 표제 중복 없음, 모바일 가로 넘침 없음, 출처 키보드 접근, 출처 링크 높이 44px 이상, 밝은·어두운 테마, 오류 없는 페이지. 의미 없는 장식·새 색상·애니메이션은 추가하지 않는다.

UI 세부 검증과 Delivery Gate는 [화면 검증 기록](ui-verification.md)을 참고한다. 최종 배포 근거는 아래 기록과 [검증 요약](deployment-verification.json)에 보존했다.

## 배포 파이프라인의 메타데이터 오인 수정

첫 [Update Static Data 실행](https://github.com/seokh1213/cooldown/actions/runs/37899833332)은 배포용 자료 재생성 뒤 데이터 검사에서 실패했다. 로컬 첫 전체 테스트는 저장된 번들을 사용해 이 재생성 차이를 드러내지 못했다. 실패 로그와 보존된 combo-compatibility-review 산출물에서 기존 355개 콤보 모두가 P/Q/W/E/R의 `source-content` 변경으로 잘못 격리된 것을 확인했다. 이후 상성 유지 단계가 관련 사전 답변도 제외했다.

원인은 콤보의 공식 툴팁·수치 스냅샷에 앱용 `ticks` 검수 주석까지 포함해 비교한 것이다. 콤보 지문에서 최상위·변신 형태의 이 주석만 제외했다. 원래 툴팁, 지속시간, 스탯, 미분류 CDragon 수치가 바뀌면 보류하는 기존 검사는 유지한다. 주석의 최신성은 별도 틱 자료의 패치·툴팁 해시 검사에서 다룬다. 게임 내 원천 데이터 변경을 무시하거나 콤보를 일괄 재승인하지 않는다.

실제 배포 재생성을 로컬에서 실행해 콤보 355개 변경 없음·검수 대기 0개, 상성 5,839쌍 유지·제외 0쌍을 확인했다. 생성된 public 자료도 커밋된 파일과 일치했다. 틱 주석 추가 시 유지 및 실제 지속시간 변경 시 보류하는 회귀 테스트를 추가했고, 실제 생성기의 격리 테스트에도 틱 주석을 넣었다. 관련 콤보 테스트 21/21 통과.

배포와 Advisor Regression 양쪽에서 같은 `npm run llm:prepare-release`를 사용한다. 앞으로 자료·모델 변경 시 이 명령을 먼저 실행해 배포용 재생성 뒤의 답변을 로컬에서도 검사한다.

## 기존 웹 테스트의 고정 가정 수정

두 번째 [배포 실행](https://github.com/seokh1213/cooldown/actions/runs/37901187491)은 데이터 검사와 틱 테스트를 통과했으나 기존 웹 테스트 4건에서 실패했다. 콤보 테스트는 dialog 안의 외부 링크가 무조건 0개라고 가정했고, 공통 스킬 테스트는 펼침 항목이 무조건 2개이며 첫 번째가 스킬 정보라고 가정했다. 새 ‘틱 근거’가 추가되어 이 가정이 맞지 않았다.

콤보 테스트는 틱 자료 영역의 검수 Wiki 링크만 허용하며 나머지 외부 링크와 복사 본문의 URL 제한은 계속 검사한다. 공통 스킬 테스트는 항목 위치 대신 ‘스킬 정보’·‘설명 전문’의 정확한 이름으로 열림·내용·상태 유지를 확인한다. 틱 근거 자체의 링크·키보드·접근성은 새 틱 테스트에서 검사한다.

전체 216건을 로컬에서도 실행했다. 첫 실행은 215건 통과, 기존 모바일 키보드 테스트 1건이 병렬 실행의 창 닫힘·포커스 복원 순서에서 실패했다. 해당 항목은 단독 실행에서 통과했고, 선택창이 닫힌 상태를 기다린 뒤 키 입력을 검사하도록 보완했다. 배포 전 체크 절차는 집중 4건에 더해 웹 전체 검사도 실행하도록 명시했다.
