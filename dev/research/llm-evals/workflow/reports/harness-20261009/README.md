# 배포 전 하네스 보강과 점화 자료 교정

## 인수 조건

1. 새 평가 파일의 등록 누락은 배포 자료를 생성하기 전에 실패한다. 목록·질문·정답을 자동 수정하지 않는다.
2. 배포 자료 준비 뒤 콤보·상성 자료가 누락되면 같은 복사본의 데이터 검사에서 실패한다. 실패 뒤 빌드·배포로 진행하지 않는다.
3. 작업 폴더의 미커밋 수정으로 푸시할 커밋의 실패를 숨길 수 없다. 성공·실패·정상 중단 후 임시 clone을 제거하며 worktree를 추가하지 않는다.
4. 훅에 전달된 Git 저장소·작업 폴더·인덱스 환경변수를 임시 clone의 명령으로 넘기지 않는다. [Git 훅 공식 문서](https://git-scm.com/docs/githooks)의 다른 저장소 호출 조건을 따른다.
5. 화면·자료·모델·E2E·빌드 설정·의존성이 바뀌면 전체 브라우저 시험을 자동 추가한다. 중간 커밋의 변경도 원격 기준 SHA부터 비교한다. 재시도는 0회이며 기존 서버를 재사용하지 않는다.
6. 점화 카드·답변은 세 언어에서 약 1초 간격·총 5틱의 결론만 전달한다. 영상 수치와 검증 한계는 연구 기록에 보존한다. 5.28초를 마지막 피해 시각으로 표시하거나 관측 간격을 숫자형 고정 서버 주기로 등록하지 않는다.
7. 전체 회귀를 새 자료로 실측하고 이전 실패·수동 검토 목록과 비교한 뒤 기준을 갱신한다. CI 해시 조건을 완화하지 않는다.

## 구현

`check:release`의 준비·검증 단계를 로컬 훅과 배포·브랜치 Actions가 공유한다. 훅은 로컬 Git 객체로 푸시 대상 커밋만 임시 clone하고 의존성을 공유한다. 기존 작업 폴더는 배포 준비의 출력 대상이 아니다. 성공·실패 단계와 소요 시간은 `dev/research/.cache/preflight`에 남는다.

점화의 교정 문장·세 언어 번역·출처·검토일은 `dev/data/knowledge/rule-corrections.json`에 있다. 원문과 문서가 정확히 일치할 때만 교정한다. 관측 원본은 [영상 분석](../../../../ability-ticks/ignite-video-20261009/README.md)을 따른다.

## 검증 기록

- 실패 재현·격리·중단·여러 커밋·Git 환경 격리와 규칙 교정 단위 시험 10/10 통과.
- 전 챔피언 틱 조회 및 점화 세 언어·모델 사용 여부의 데이터 시험 25/25 통과.
- 초기 점화 카드·대화 저장 복원·가로 넘침을 390px와 1280px에서 재시도 없이 2/2 통과했다. 이후 사용자 요청에 따라 제품 문구를 결론 한 문장으로 줄이고 같은 검증을 갱신했다.
- 실제 실패 커밋 `1e80e0a5b0ee8bdafd0197e0ea5776048dedf74b`를 임시 clone에서 재검사했다. `Inventory changed (9 added, 0 removed)`로 자료 준비 전에 중단됨을 확인했고 임시 clone을 회수했다.
- 전체 회귀 5,893건을 새 자료로 재측정했다. 성공 5,796건·기존 실패 77건·수동 검토 20건, 인프라 12/12, unsafeNumeric 0건이다. 질문·채점기 해시는 그대로이고 모든 행의 통과 여부와 검사 항목도 그대로다. 응답 문자열이 달라진 10건은 점화 교정 문장만 바뀌었으며 다른 문자는 동일하다.
- [기준 갱신 근거](baseline-update.json)에 전후 파일·자료·질문·채점기 해시와 변경 행을 보존하고 완결된 실측 결과로 baseline을 갱신했다. 데이터 해시 비교 조건과 과거 실패·수동 검토 상태는 변경하지 않았다. 모델의 품질 승인을 의미하지 않는다.
- 타입 검사·lint, actionlint 1.7.12의 변경한 Actions 세 파일 검사를 통과했다. 푸시별 전체 단계·소요 시간은 `dev/research/.cache/preflight/push-<commit>.json`, 원격 단계 결과는 Actions의 `release-validation`과 `advisor-regression` artifact로 확인한다.
- 커밋 `4387d1686c921e78265b4c2e8eaffbe31409dddf`의 실제 푸시 훅에서 전체 12단계가 통과했다. 브라우저 시험 223/223건은 재시도 없이 6.1분, 준비·검사를 합친 전체는 약 8.7분이었다. 다만 검사 중 GitHub SSH 연결이 먼저 닫혀 전송은 종료 코드 141로 실패했다.
- 저장소 로컬 SSH 명령에 연결 유지 30초·미응답 6회 옵션을 적용한 뒤 커밋 `b29906fa44cd5cb88ab1207210a2ae350b872ead`로 정상 푸시를 완료했다. 재실행에서도 12/12단계·브라우저 223/223건이 재시도 없이 통과했고 전체 소요 시간은 518.3초였다. [푸시 검증 결과](push-validation.json)에 실제 커밋·단계별 결과·소요 시간을 보존했다.
- 같은 커밋의 원격 배포 준비 2/2단계와 공통 검증 8/8단계도 통과했다. 실행별 최종 결과와 artifact는 [배포 Actions](https://github.com/seokh1213/cooldown/actions/runs/37941059416)와 [전체 품질 회귀 Actions](https://github.com/seokh1213/cooldown/actions/runs/37941059063)에서 확인한다.
- 전체 품질 회귀 Actions는 성공했다. 배포 Actions는 브라우저 222건 성공·1건 재시도 성공(flaky)으로 배포를 중단했다. 새 `failOnFlakyTests` 조건이 불안정한 통과를 잡은 실제 사례다. 실패 위치는 `advisor-history-snapshots.spec.ts`의 저장 재시도 클릭이다.
- 해당 시험은 첫 저장 실패 직후 저장 차단을 먼저 해제해, 아직 진행 중인 답변·상세 자동 저장이 성공하며 재시도 버튼을 제거할 수 있었다. 완성된 답문을 먼저 확인하고 실제 버튼의 클릭 capture 단계에서 차단을 해제하도록 장애 주입을 수정했다. 같은 클릭 안에서 복구와 재시도가 일어나며 앱의 정상 자동 저장은 변경하지 않는다. CI 조건·재시도 0회·2 workers로 12회 반복해 12/12건을 39.8초에 통과했다.

## 제품 문구

사용자 검토 후 카드와 답변에는 “점화는 약 1초 간격으로 총 5틱의 피해를 줍니다.”만 넣는다. 영어·중국어도 같은 길이의 결론으로 맞춘다. 영상의 95×5=475, 화면상 간격, 촬영 패치·서버 타이머의 미확인 범위는 영상 분석 기록에 보존하며 제품 설명에 반복하지 않는다. 숫자형 고정 틱 간격은 추가하지 않는다.

이 문구로 관련 단위·데이터 28/28건과 390px·1280px 브라우저 2/2건을 재시도 없이 통과했다. 실제 로컬 Chrome의 새 대화에서도 짧은 결론을 확인했고 영상 설명·계측 범위가 표시되지 않음을 확인했다.

전체 회귀 5,893건과 인프라 12/12를 다시 실측했다. 성공 5,796건·기존 실패 77건·수동 검토 20건, unsafeNumeric 0건으로 이전과 같았다. 변경 응답 10건은 이전의 긴 점화 문장만 짧은 결론으로 교체됐고, 나머지 모든 응답 문자·통과 여부·검사 항목이 동일했다. [짧은 문구의 기준 갱신 근거](concise-update.json)에 전후 해시와 변경 행을 보존했다.

커밋 `8847d72a9214e2d177aca7c9deb4780e946e7c4d`의 [배포 Actions](https://github.com/seokh1213/cooldown/actions/runs/37947837623)와 [전체 품질 회귀 Actions](https://github.com/seokh1213/cooldown/actions/runs/37947837589)는 모두 성공했다. 배포 서버의 `release.json`에서 예상 releaseId `a5d58450b75b9b52fe76a7b5c580fb0c`를 확인했다. 이어진 사용자 검토에서 규칙 전체 나열을 줄이는 [질문별 답변 개선](../rule-focus-20261010/README.md)을 진행했다.
