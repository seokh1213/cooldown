## 이번에 내릴 수 있는 결론

**낱문장 원자를 곧바로 답변으로 쓰는 방식은 이번 세트에서도 나빴다.** 원문 노트를 복원하면
상대 적용 조건은 보존하지만, 사용자가 말한 스킬 부재까지 행동에 반영하지는 못했다.
`조건 → 이유 → 행동 → 필요한 내 스킬`을 함께 묶으면 직접성과 실행 가능성이 좋아지는 사례가
여러 상대에서 있었다. 그러나 맞는 묶음이 없을 때 현행으로 돌아가는 답은 여전히 실패한다.
따라서 조건 묶음 전체를 서비스 답변으로 전환할 근거는 아직 부족하다.

[manual-review.json](manual-review.json): 개선·동등·퇴행·실패를 의도적으로 고른 16턴을 구현자가

“블리츠 그랩이 빠지면 아무 위협도 없다”, “다리우스 모든 콤보는 E로 시작한다” 같은 과도한
원문 단정도 발견했다. 그대로 복사하고 출처 지문이 맞더라도 좋은 답은 아니다. 블리츠는
Q 이외의 스킬도 있으며 [Riot 공식 페이지](https://www.leagueoflegends.com/en-us/champions/blitzcrank/)도
별도의 광역 피해·침묵 기능을 설명한다. 적용 조건 검증과 게임 사실 검수는 각각 필요하다.

## 적용한 코드와 적용하지 않은 실험

앱의 공통 대화 흐름에는 아래 수정이 들어갔다.

- “Q가 있으면 어떻게 싸워?”, “내 E도 없는데 어떻게 해?”를 수치 비교·스킬 설명 대신 상황 조언으로 읽는다.
- “Q는 돌아왔어”는 상태 복원, “둘 중 더 빨리 돌아?”는 쿨타임 비교로 구분한다.
- 문장의 스킬 언급 위치마다 주인과 상태를 연결한다. 내 E 부재가 상대 R 부재로 옮겨 붙지 않는다.
- 이름으로 말한 “재사용 대기 중”, “사용 가능”과 실제 상태·가정을 구별한다.
- “가렌 대 다리우스”, “피오라 대 다리우스로 돌아가자”의 관점을 보존하며 명시적인 내 챔피언 지칭을 우선한다.
- 은행 읽기만 평가에서 주입한다. 앱과 평가가 같은 답문·혼합 요청·기억 조립 함수를 사용한다.

조건 묶음은 연구 경로에 있다. 생성 모델을 호출하지 않으며 서비스 답변 선택기에 연결하지 않았다.
0.8B의 역할을 이번 결과로 변경하지 않았다. 비교는 오프라인 판정기에서 실행했으며 실제 0.8B
그래프의 새 재측정이나 영어·중국어 조건 묶음 평가는 아니다. 기존 세 언어 회귀 질문은 포함했다.

Chrome의 실제 입력창에서는 실명 대화→상대 Q 부재→내 E 부재→두 조건 정정→새로고침→이유 질문,
내 매혹/상대 궁을 섞은 문장, 조언과 쿨타임 혼합 요청을 확인했다. 조건 묶음의 답은 Node에서
비교했으며 Chrome에는 공통 흐름 수정만 적용했다. 화면 근거는 [browser-checks.json](browser-checks.json).

## 이후 구조

1. 원자는 검색 색인으로 쓴다. 짧은 문장만으로 답을 끝내지 않는다.
2. 답변 단위는 조건·이유·행동·필요 스킬·선행 조건·출처를 함께 보관한다.
3. 내 스킬이 없으면 실행 불가능한 행동을 제외하고, 근거 있는 대안을 찾는다.
4. 대안도 없으면 현재 조건에서 확정할 수 없는 부분을 알린다. 모순된 현행 문단으로 무조건 복귀하면 안 된다.
5. 상대별 공통 단위와 내 챔피언의 행동 단위를 연결하여 확장한다. 모든 쌍을 손으로 작성하는 방식은 확대 비용이 크다.

이번 세트로 판단할 수 있는 것은 이 구조의 필요성과 여러 구체 사례의 개선이다. 모든 챔피언의
자동 아톰화, 좋은 자유 생성, 충분한 대안 지식이 갖춰졌다는 의미는 아니다.
