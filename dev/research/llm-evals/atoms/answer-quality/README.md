# 답변의 직접성과 로컬 실행 속도 — 2026-10-01

남아 있던 대안 선택과 과한 단정 문제를 앱에 적용했다. 모델 가중치와 자유 생성 설정은 바꾸지 않았다.
원문 문단을 조건·이유·행동과 함께 고르는 방식이며, 수동 작성한 11상성 아톰은 연구 경로에 남는다.

## 바뀐 답변

- 쓰레쉬 Q 없음 + 진입 질문: 랜턴을 본인 진입기로 제시하지 않고 E의 밀기·당기기 원문을 고른다. 가까운 상대라는 전제는 유지한다.
- 쓰레쉬 Q/E, 레오나 Q/E/R 없음: 해당 진입을 권할 수 없는 이유를 말하고, 확인되는 방어·거리 관리 조언을 별도 제목으로 보여 준다.
- 잭스 Q/E 없음 + 딜 교환: R 설명 대신 `평타 → W → 평타`와 급소·짧은 교환 원문을 고른다.
- 아리 E 없음 + 제드 R 대응: 무관한 파밍으로 채우지 않고, 그 조건에서 다른 R 대응 근거를 찾지 못했다고 말한다.
- E만 돌아왔고 R은 없음: 군중 제어 원문의 수단을 `아리 E 매혹`으로 연결한다. R 상태는 남는다.
- 한타의 아군 역할 조건이 독립된 경우는 가지별로 검사한다. Q 공격 가지가 막혀도 아군이 뒤에서 싸울 때의 E·W 보호 조건과 행동은 함께 남기고, 표시한 한타 주제도 기억한다.
- `모든 콤보는 E로 시작`, `후속 스킬 전부 확정` 같은 전투 보장을 제외한다. 카드에 명시된 효과·스킬 순서는 유지한다.
- 쓰레쉬 R 벽을 아군이 깨고 탈출한다는 문장은 카드의 적 챔피언 통과 조건과 충돌하므로 제외한다.

영어 쉼표가 조건 설명을 별개 질문으로 나누던 문제, 수치 조회 뒤 `궁 대응은?`이 이전 쿨타임
카드로 돌아가던 문제도 수정했다. 일상어 `반격 타이밍`을 잭스 E 사용으로 읽지 않으며,
아군의 돌진 효과를 내 이동기로 쓰지 않는다. 영어·중국어 군중 제어도 같은 스킬 부재 검사를 거친다.

## 비교

기존 228턴과 새 8대화 20턴을 **각 대화가 자기 답변·기억을 이어 가며** 실행했다.
새 질문은 기존 실패의 변형이며 수정에 사용했다. 독립·맹검 평가가 아니다.

|---|---:|---:|

이는 문자열·경로·상태 검사이며 전체 답변 정확도가 아니다. `before.json`은 수정 전 조립 경로에서
저장한 실제 대화다. 긍정 검사 한 곳을 원문의 일반 CC 표현과 실제 스킬 이름을 함께 받도록
정정하고, 영어 표현 순서를 바로잡았다. 영어·중국어의 불가능한 CC 사용 금지도 추가했다.
**이전 저장 응답에도 최종 검사 52개를 똑같이 적용했으며 응답은 재생성하지 않았다.**

기존 228턴의 경로 225/227·상태 48/48은 유지했다. 내용 검사도 191/208 → 191/208이다.
한 건은 아리 E 없는 제드 R 질문에서 예전 파밍 답에 붙던 `거리/피/파밍` 낱말 검사를 잃었다.
새 경로는 해당 궁에 대한 근거 부족을 정확히 말하므로 예전 긍정 표현을 채우지 않는다.
대신 쓰레쉬 Q 없는 한타에서 아군 보호 조건과 E·W 조언을 남기는 검사가 새로 통과했다.
나머지 두 경로 미통과는 이전과 같은, 주인을 말하지 않은 Q 쿨타임·사거리의 확인 질문이다.

## 실행 속도와 0.8B

`replay-quality.ts`는 한 번에 앱의 한 경로만 실행하고 카드·은행을 캐시한다.
이전처럼 3방법 × 2기억 정책을 모두 반복하거나 같은 답을 검사·조립용으로 두 번 만들지 않는다.
248턴 재생은 약 1초, 턴 중앙값 약 3ms였다. 데이터 읽기를 포함한 재생 시간이지만
프로세스 시작·브라우저·다운로드·모델 추론 시간은 포함하지 않는다. 원본 시간은 `after.json`이다.

로컬 Ollama `qwen3.5:0.8b`에는 6상황에서 사용 가능한 원문 노트 ID를 골라 보게 했다.
사전에 정한 선택 기준은 3/6 통과했다. 첫 적재 포함 약 4.6초, 적재 뒤 요청은 0.27~0.36초였다.
랜턴을 진입 대안으로 고르거나, 제드 R 질문에 무관한 W/E 노트를 고르는 오류가 있었다.
작은 작성자 평가이며 일반 성능 추정은 아니다. Ollama Q8 기본 모델은 앱의 q4+판정 어댑터와
같은 실행물이 아니다. 이 결과로 앱 판정 모델의 성능을 주장하지 않는다.

따라서 이번 앱 개선은 코드의 조건·주제 선택에 적용했고, 0.8B 노트 선택은 실험 기록만 남겼다.
Ollama 실험을 다시 실행할 필요 없이 저장된 결과로 검토할 수 있다.
