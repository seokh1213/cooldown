# 답변 실행 조건 검사 — 2026-10-01

앞선 실험에서 발견한 네 복귀 실패를 고쳤다. **기존 답 은행·노트·실험 아톰의 복귀 답**에
같은 실행 조건 검사를 넣었다. 조건 묶음 자체는 연구 경로에 두고, 기존 앱 답변의 검사는 적용했다.

## 어떻게 바뀌었나

1. 현재 카드와 원문 관점으로 `requirements`를 붙인다. 슬롯, 이름, `Q로`, `EQR` 표기를 받는다.
2. 사용자가 없다고 말한 스킬을 요구하면 조건·이유·행동 문단 전체를 제외한다.
3. `selectPlaybook`으로 같은 상대에 적용되는 원문 대안을 찾는다. 원문의 선행 조건은 유지한다.
4. 대안도 없으면 근거 부족을 알린다. 명시적인 한타·라인전·성장 구간 요청을 다른 주제로 채우지 않는다.

상대 E 설명, 내 E 사용 금지, 내 E가 돌아온 뒤 행동은 현재 내 E 사용 지시와 구분한다.
군중 제어·이동기라는 추상적 행동도 내 카드의 실제 스킬로 연결한다. 과거 아톰 파일에
`actionRequirements`가 없어도 같은 검사로 복원하며 출처 변동 검사는 계속 적용한다.

대화 기억에서도 `내 E와 R이 없어`를 함께 추출하고, E만 정정하면 R 상태는 남긴다.
수치 조회 뒤 상황 조언으로 돌아갈 수 있게 했고, `어떻게 버텨?`, `그래도 들어가?`,
`내 E도 없는데 콤보 알려줘`를 스킬 설명·쿨타임 표로 잘못 읽는 경로를 고쳤다.
아톰 선택에서는 질문이 지목한 R 대응을 W 조건을 함께 가진 다른 단위보다 우선한다.

## 비교 범위

- 기존 158턴 + 새 12대화 52턴 = **65대화 210턴**.
- 별도 6대화 18턴을 더해 총 **228턴**. 신드라·노틸러스·케이틀린과 정정·수치 조회를 포함한다.
- 같은 입력 기억으로 비교하는 실행과, 각 방법이 자기 답변·기억을 이어가는 실행을 모두 보존했다.
- 새 질문은 기존 웹 질문의 스킬 부재·상대 기술 회피·짧은 교환 패턴을 변형했다. 새 외부 전략을 작성하지 않았다.
- 모두 오프라인 판정기로 실행했다. 0.8B 추론·자유 생성은 이번 비교에 포함하지 않았다.

### 각 방법이 자기 기억을 이어간 210턴

| 방법 | 내용 조건 /192 | 알려진 네 실패 차단 | 대안 노트를 사용한 턴 | 근거 부족 답 |
|---|---:|---:|---:|---:|
| 공통 대화 수정 후, 실행 조건 검사 전 | 143 | 0/4 | 0 | 0 |
| 기존 답 + 실행 조건 검사 | 175 | 4/4 | 32 | 2 |
| 조건 묶음 + 실행 조건 검사 | 185 | 4/4 | 32 | 2 |

**문자열로 정한 내용 검사이며 전체 답변 정확도나 독립적인 품질 평가가 아니다.**
192개는 이전 내용 검사 140개, 새 금지 표현 검사 48개, 네 실패의 별도 검사다.
새 52턴의 금지 표현 검사는 26/48 → 48/48이었다. 경로 208/209, 사전 상태 항목 44/44였다.
경로 한 건은 `Q 쿨타임도 알려줘`에서 어느 챔피언의 Q인지 되묻는 답이다.
`supported-or-abstain` 한 턴은 경로 채점에서 제외하고 내용 검사를 유지했다.

공유 기억 비교의 내용·경로·상태 점수는 같았다. 실제 진행의 근거 부족 답은 공유 기억에서는
1턴, 각 방법의 기억에서는 2턴이었다. 이는 보여 준 주제 기록의 차이까지 포함한 결과다.

### 별도 18턴

실행 조건 관련 금지 표현 9/16 → 16/16, 상태 4/4, 경로 17/18.
7턴에서 기존 노트 대안을 썼고 1턴은 근거 부족을 알렸다.
처음 실행에서 `어떻게 버텨?`를 스킬 카드로 읽는 실패가 드러나 공통 문형을 수정했다.
**수정 뒤 수치는 맹검 결과가 아니다.** 첫 결과는 `first-holdout-results.json`에 보존했다.
남은 경로 항목은 `Q 사거리도 알려줘`에서 쓰레쉬/모르가나 중 누구인지 확인하는 답이다.

최초 탐색 실행 `first-results.json`은 새 질문 ID가 예전 질문과 겹쳐 예전 채점 규칙이 섞였다.
진단 기록으로만 보존하며 비교표에는 사용하지 않는다. 새 질문 ID를 `a01`~`a12`로 분리한
`reviewed-results.json`이 위 비교의 원본이다. 공통 흐름은 세 방법 모두 동일하므로 표는
검사 단계의 효과를 비교하며, 수정 전 전체 앱과의 완전한 A/B는 아니다.

## 원문 검토

`manual-review.json`은 알려진 실패·정정·복수 부재·대안 부족을 포함한 12턴을 구현자가 검토한
기록이다. 자동 점수를 품질 점수로 바꾸지 않았다.

- 아리 E 없음: 불가능한 매혹 사용 대신 Q 견제·파밍과 그림자 범위 회피.
- 쓰레쉬 Q 없음: Q 진입 콤보를 제외하고 랜턴의 아군 클릭 조건·속박 회피를 유지.
- 베인 Q 없음: 벽 각을 만드는 Q 콤보를 제외하고 상대 Q/E 회피 원문을 유지.
- E가 돌아오고 R은 여전히 없음: R 진입 대신 E→W→Q 원문 콤보를 선택할 수 있다.

**대안이 항상 좋은 직답은 아니다.** 잭스 Q/E 부재에서 R 설명은 여전히 일반적이고,
레오나 W 노트는 이미 붙어 있다는 조건이 필요하다. 제드 궁 질문의 파밍 조언도 궁을 맞은
순간의 대응을 완전히 설명하지는 못한다. 또한 기존 다리우스 노트의 `모든 콤보는 E로 시작`
같은 과도한 단정은 이번 실행 조건 검사로 진위를 검증하지 않았다.

호환 계층은 기존 산문의 스킬 참조를 보수적으로 구조화한다. 모든 자연어 행동의 의미를
증명하지 않으며, 단어만 생략한 표현·다른 언어·추가 전제에서 빠뜨림이나 과도한 제외가
있을 수 있다. 전체 배포는 기존 답의 실행 조건 검사에 한정했고 아톰 답변 전환은 하지 않았다.
