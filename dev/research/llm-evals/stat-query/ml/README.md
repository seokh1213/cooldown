# 능력치 항목 분류: 규칙과 로지스틱 비교

이 문서는 2026-10-01 조회 해석기 실험이다. 2026-10-02 실제 앱의 답변·기억·브라우저로 확인한 후속 결과는 [APP_TEST.md](./APP_TEST.md)에 있다.

## 결론

직접 작성한 단일 질문 195개에서 기존 조회 규칙은 129개, 규칙이 조회를 만들지 못한 경우에만 자모·문맥 로지스틱을 사용하면 164개를 맞췄다. 하지만 예측을 이어받는 8개 대화 36턴에서는 22개에서 24개로 소폭 개선됐다. 모델만으로 규칙을 교체하면 첫 질문의 누락이 뒤의 대상·레벨·항목 기억까지 영향을 줬다.

전통 ML로 오타와 낯선 표현의 항목 분류를 보완할 가능성은 확인했다. 현재 자료만으로 앱에 적용하기에는 여러 턴 개선과 이름 오타 처리가 부족하다. 첫 실험은 재현 가능한 연구 코드와 결과를 저장했으며 앱의 조회 규칙, 기존 판정기, 0.8B 모델은 변경하지 않았다.

## 실험 구성

- 기존 앱의 능력치 조회 규칙을 기준으로 사용했다. 기준 코드: `5eca96ff1`.
- 모델의 출력은 체력·체력 재생·방어력·마법 저항력·공격력·공격 속도·이동 속도, 이전 항목 유지, 다른 질문의 9개 분류다.
- 글자 모델: 글자 2~5그램 TF-IDF + 다중 클래스 로지스틱.
- 자모·문맥 모델: 글자 TF-IDF + 한글 초성·중성·종성 TF-IDF + 활성 문맥과 글자 2~3그램의 결합 특징 + 로지스틱.
- 인식한 챔피언 이름은 가린다. 문맥 특징에는 활성 주제, 명시한 이름 수, 스킬 슬롯 여부를 넣는다. 정답 항목을 특징에 넣지 않는다.
- 이름 오타는 기존 `suggestChampions` 후보 찾기를 공통으로 사용한다. 유일한 후보만 보정한다. 이름 보정은 로지스틱의 학습 대상이 아니다.
- 모델이 항목을 고르면 대상과 레벨은 실제 `resolveStatQuery`로 얻는다. 스킬·아이템·다른 질문의 차단도 이 코드에서 적용한다. 실제 능력치 수치는 학습하지 않는다.
- 비교 대상 수에 제한을 추가하지 않았다. 자료가 있는 1·6·11·18레벨을 사용한다.

`규칙 + 모델`은 규칙이 조회를 만들면 곧바로 반환한다. 규칙이 조회를 못 만들었을 때 모델을 호출하고, 확신이 낮으면 조회를 만들지 않는다. 이미 잘못 만든 규칙의 항목을 모델로 덮어쓰지는 않는다.

## 학습과 평가 분리

| 구분 | 수 |
| --- | ---: |
| 학습 입력 | 885 |
| 개발 입력 | 93 |
| 고정 평가 입력 | 195 |
| 원본 표현 계열 | 175 |
| 별도 이름 평가 | 20 |
| 별도 대화 | 8개 / 36턴 |

표현을 먼저 train/dev/test로 나눴다. 학습 표현 안에서만 띄어쓰기 제거, 한 글자 삭제, 한글 음절 치환을 증강했다. 원본 표현 계열과 띄어쓰기를 지운 실제 질문+활성 문맥의 split 간 중복은 모두 0이다. 서로 비슷한 뜻의 독립적으로 작성한 문장은 존재한다. 실제 사용자 표본이나 독립적인 블라인드 평가가 아니다.

학습·개발 자료만으로 C를 선택하고, 개발 자료에서 오인 비용을 누락 비용보다 크게 두어 거절 기준을 골랐다. 평가 문항과 대화를 보고 C나 기준을 다시 조정하지 않았다.

| 모델 | C | 개발 macro F1 | 최소 확신 | 1·2위 최소 차이 |
| --- | ---: | ---: | ---: | ---: |
| 글자 | 1 | 0.735 | 0 | 0.2 |
| 자모·문맥 | 3 | 0.833 | 0.8 | 0 |

확신 수치는 보정된 정확도 확률이 아니다. 0.8 이상이라는 이유로 실제 질문의 80%를 맞힌다고 해석할 수 없다.

## 단일 질문 결과

전체 조회 정확도는 항목·대상·레벨이 모두 일치하거나, 다른 질문에서 조회를 만들지 않은 경우를 센다. 195개 중 능력치 조회 133개, 다른 질문 62개다. 각 질문에는 정해진 이전 기억을 제공한다. 이 실험에서는 대상과 레벨이 맞아 항목 정확도와 전체 조회 정확도가 같았다. 이름은 아래 별도 평가로 확인했다.

| 방법 | 전체 조회 / 195 | 능력치 조회 / 133 | 다른 질문을 조회로 오인 / 62 | 조회 누락 / 133 | 여러 턴 / 36 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 현행 규칙 | 129 (66.2%) | 67 | 0 | 60 | 22 |
| 규칙 + 공통 이름 보정 | 129 (66.2%) | 67 | 0 | 60 | 22 |
| 글자 로지스틱 | 133 (68.2%) | 75 | 4 | 58 | 11 |
| 자모·문맥 로지스틱 | 146 (74.9%) | 84 | 0 | 49 | 7 |
| 규칙 + 글자 보조 | 153 (78.5%) | 95 | 4 | 32 | 24 |
| **규칙 + 자모·문맥 보조** | **164 (84.1%)** | **102** | **0** | **25** | **24** |

오타로 분류한 42개 문항은 현행 6개, 자모·문맥 보조 20개를 맞췄다. 보조 방식에도 조회 누락 25개와 잘못된 항목 6개가 남았다. 다른 질문 62개에서 오인 0건이라는 결과는 일반적인 모든 질문의 오인율이 0이라는 증거가 아니다.

개선 예:

- `그럼 공걱속도는?` → 공격 속도, 이전 대상과 레벨 유지.
- `그럼 마법 저향력은?` → 마법 저항력.
- `그럼 기본 스탯에서 가만히 있을 때 피가 차는 양` → 체력 재생.

남은 오류:

- `체럭`, `체려 재생` 등은 여전히 확신이 낮아 누락한다.
- `체력 회븍량`, `health regneration`은 기존 규칙이 체력으로 확정한다. 보조 모델은 기존 조회를 덮어쓰지 않아 오류가 유지된다.
- 같은 오타라도 이름·레벨·후속 문장의 표현이 달라지면 결과가 달라진다.

## 여러 턴 결과

매 턴 정답 기억을 넣지 않고 각 방식이 실제 만든 조회를 다음 턴에 이어받았다. 명시한 챔피언과 스킬 슬롯으로 주제를 바꾸면 앱의 스킬 기억 전환을 사용했다. 스킬 회복과 기본 재생의 구분, 항목 정정, 레벨 변경, 한 명으로 축소, 이름 오타, 10명, 영어·중국어를 포함했다.

| 대화 | 턴 수 | 현행 | 규칙 + 자모·문맥 |
| --- | ---: | ---: | ---: |
| 사용자 보고 3턴 + 레벨·공속 오타·한 명 축소 | 6 | 4 | 6 |
| 레벨·대상·항목 오타 | 5 | 2 | 2 |
| 기본 재생 → R 회복 → 기본 재생 | 5 | 5 | 5 |
| 이름과 체력 오타 → 마저 → 레벨 → 한 명 | 4 | 0 | 0 |
| 체력 → 회복량 정정 → 물약 → 방어력 | 4 | 4 | 4 |
| 10명 → 레벨 → 공속 오타 → 한 명 | 4 | 2 | 2 |
| 영어 체력 → 재생 오타 → 레벨 → 한 명 | 4 | 1 | 1 |
| 중국어 체력 → 재생 → 레벨 → 한 명 | 4 | 4 | 4 |
| 합계 | 36 | 22 | 24 |

모든 턴을 맞춘 대화는 현행 3/8, 보조 4/8이다. 사용자 보고의 원래 3턴은 현행 수정본에서 이미 맞췄다. 보조 방식의 추가 개선은 이어서 넣은 공속 오타와 그 다음 대상 축소다.

이는 **조회 해석기의 대화 재생**이다. 실제 브라우저, 최종 답변 문장, 아이템·상대법 등 모든 앱 경로의 기억 전환을 실행한 품질 평가가 아니다. 특히 모델만 쓰는 방식의 첫 질문 누락은 이후 대상 기억을 만들지 못하게 하므로 단일 질문보다 결과가 크게 낮아졌다.

## 이름 오타

20개 중 정답은 기존 이름 인식 12개, 기존 후보 보정을 먼저 사용하면 15개다. 정상·오타 이름이 있는 11개 중 3개에서 6개로 늘었고, 일반어 9개에서는 잘못된 보정이 없었다. `아니 회복량`을 `아리`로 바꾸지 않았다.

실패: `재이스 체력`, `갈렌 방어력`, `wuknog armor`, `yasou health`, `lux and wuknog attack speed`. 기존 이름 후보의 위치 규칙이 이름 뒤의 스탯 명사를 충분히 처리하지 못했다. 이 이름 평가셋을 보고 규칙을 수정한 뒤 같은 수치를 검증 성적으로 제시하지 않았다.

## 속도와 검증

- 로컬 CPU에서 두 모델의 특징 생성·개발 기준 선택·학습·파일 저장은 총 약 1.44초였다. 자료 작성과 전체 실험 소요 시간은 포함하지 않는다.
- 모델 JSON은 글자 약 1.10MB, 자모·문맥 약 3.07MB다. 앱용으로 경량화한 모델 크기가 아니다.
- Node에서 현재 규칙은 중앙값 약 1.92ms, 자모·문맥 보조는 약 6.48ms, 95백분위 약 12.05ms였다. 이름 후보 찾기와 조회 해석을 포함하며 모델 파일 최초 읽기, 브라우저, 다운로드는 포함하지 않는다. 작은 로컬 측정이므로 고정 성능으로 보장하지 않는다.
- 보조 방식은 195개 중 122개에서 모델을 호출했다. 규칙이 조회를 만든 73개에서는 호출을 생략했다.
- 두 모델의 개발 입력 93개씩에서 Python과 Node 확률 차이를 검증했다. 최대 차이 `8.88e-16`.
- 집중 시험 8개, 스크립트 타입 검사, 변경한 TypeScript 린트 통과.
- 실험 어댑터가 분류한 항목을 실제 조회 계약에 반영하고, 일반어 이름 보정·조회 차단·기억 유지·특징 마스킹·계산 정규화·split 중복 차단을 시험했다.

## 재실행

저장 파일: `questions.jsonl`은 고정 입력·정답·특징, `dataset.json`은 분할 감사, `training.json`은 학습 조건, 두 모델 JSON과 parity JSON은 가중치와 계산 검증 자료, `results.json`과 `replay.json`은 개별 결과까지 포함한다. 실행은 저장 결과를 갱신한다.

```sh
node --import tsx dev/scripts/advisor/stat-classifier/build.ts
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 uv run --python 3.13 \
  --with scikit-learn==1.9.0 --with numpy==2.4.2 \
  python dev/scripts/advisor/stat-classifier/train.py
node --import tsx dev/scripts/advisor/stat-classifier/evaluate.ts
node --import tsx dev/scripts/advisor/stat-classifier/replay.ts
node --import tsx --test dev/tests/data/stat-classifier-experiment.test.ts
npm run type-check:scripts
npx eslint dev/scripts/advisor/stat-classifier/*.ts \
  dev/tests/data/stat-classifier-experiment.test.ts --max-warnings 0
```

이번 실행: Python 3.13.15, scikit-learn 1.9.0, NumPy 2.4.2. Python 버전·의존성·하드웨어가 달라지면 수치 오차와 실행 시간이 달라질 수 있다.
