# 다국어 요청 판정기 비교

초기 배포에서는 문자 특징을 사용하는 로지스틱 회귀를 먼저 적용했다. 그때 임베딩이나 kNN과 비교해서 선택한 것은 아니다. 이번에는 같은 자료로 10가지 조합을 비교하고, 후보 두 개를 실제 대화 코드에 주입했다. 아래 임베딩 모델은 운영 앱에 연결하지 않았다.

## 자료와 선택 기준

- 학습 예시 665개, 설정 선택용 개발 문장 73개, 기존 회귀 시험 66개를 사용했다. 운영 분류기는 같은 학습 예시를 이름 개수 0·1·2 상태로 증강한 기존 가중치 그대로 평가했다.
- 추가 질문은 한국어·영어·중국어 각각 33개, 합계 99개다. 언어마다 요청 범위 11가지에 3개씩 넣었다. 98개는 새 표현이고, 1개는 알려진 R 스킬정보 오분류 사례다.
- 모든 후보는 챔피언 이름을 마스킹한 같은 질문을 받는다. 정규화 후 학습 문장과 평가 문장의 정확한 중복이 없음을 검사한다.
- 로지스틱·SVM의 C와 kNN의 k는 개발 자료의 macro F1로만 선택한다. 회귀 시험과 추가 질문의 점수를 보고 다시 설정을 고르지 않았다.
- 아래 정답 수는 기각 전 가장 높은 점수의 범위 판정이다. 운영에서는 확률 0.6 이상, 1·2위 차이 0.2 이상일 때만 채택한다. 채택 수와 오답 수는 JSON에 별도로 기록했다.

## 결과

| 특징과 판정기 | 선택된 설정 | 기존 시험 / 66 | 추가 질문 / 99 |
| --- | --- | ---: | ---: |
| 현재 문자 해시 + 로지스틱 | 운영 fp16 가중치 | 64 | 75 |
| 문자 TF-IDF + 로지스틱 | C=2 | 62 | 83 |
| 문자 TF-IDF + SVM | C=0.5, 3-fold 확률 보정 | 61 | 81 |
| 문자 TF-IDF + kNN | k=5 | 53 | 79 |
| Arctic 임베딩 + kNN | k=1 | 62 | 86 |
| Arctic 임베딩 + 로지스틱 | C=8 | 65 | 96 |
| Arctic 임베딩 + 클래스 중심 | 정규화한 평균 벡터 | 59 | 88 |
| E5-small 임베딩 + kNN | k=3 | 57 | 84 |
| E5-small 임베딩 + 로지스틱 | C=32 | 63 | 91 |
| E5-small 임베딩 + 클래스 중심 | 정규화한 평균 벡터 | 55 | 80 |

kNN은 cosine 거리와 거리 가중 투표를 사용했다. 클래스 중심은 각 범위의 평균 벡터와 가장 가까운 범위를 고른다. 임베딩 벡터는 정규화했고, 로지스틱과 SVM에는 클래스 균형 가중치를 적용했다.

### 언어별 추가 질문

| 판정기 | 한국어 / 33 | 영어 / 33 | 중국어 / 33 |
| --- | ---: | ---: | ---: |
| 현재 | 28 | 21 | 26 |
| Arctic + 로지스틱 | 33 | 32 | 31 |
| E5-small + 로지스틱 | 31 | 30 | 30 |

단어가 겹치는 정도보다 질문의 의미를 벡터로 표현하는 방식이 새 표현에서 좋았다. 이 자료에서는 임베딩 위에 로지스틱 회귀를 학습하는 방식이 kNN보다 정확했다.

같은 운영 기각 기준을 적용하면 추가 질문에서 현재 방식은 56개를 채택해 3개가 틀렸다. Arctic 로지스틱은 88개 중 3개, E5 로지스틱은 71개 중 1개가 틀렸다. kNN의 투표 비율은 보정된 확률이 아니다. 특히 k=1은 모든 질문에 투표 비율 1을 주므로, 이를 확신으로 해석하면 안 된다. 클래스 중심의 유사도 변환도 확률로 해석하지 않았다.

## 실제 대화에서의 차이

한국어·영어·중국어에 대해 각각 아래 세 대화를 실행했다. 모델마다 9개 대화, 33턴이다.

1. 소개 → 전체 스탯 → R 정보 → 스킬 전체로 정정 → 기본 정보와 스킬을 함께 요청
2. Q → W → E → R 스킬정보 요청
3. 오공의 짧은 딜교 순서 → 상대 피오라 W를 먼저 쓰게 하는 방법

앱의 `answerDialogue`, 계획기, 답변 작성, 대화 저장·복원 코드를 그대로 사용했다. 다음 턴은 직전 답변과 기억을 저장했다가 복원한 상태로 실행한다. 교체한 것은 요청 범위 판정기이며, 노트 주제 판정과 나머지 경로는 기존 구현이다.

| 판정기 | 범위·주제·대상 조건 충족 / 33 | 한국어 / 11 | 영어 / 11 | 중국어 / 11 |
| --- | ---: | ---: | ---: | ---: |
| 현재 | 27 | 9 | 9 | 9 |
| Arctic + 로지스틱 | 30 | 11 | 9 | 10 |
| E5-small + 로지스틱 | 28 | 9 | 9 | 10 |

모든 방식이 Q/W/E/R 전환 12턴은 통과했다. 상성 응답은 상대 관점의 챔피언 노트와 오공·피오라 상성 카드를 모두 허용했다. 전체 스탯은 현재 질의에서 제공하는 7개 항목, 콤보는 콤보 주제 선택을 확인했다. 이 표는 요청 처리 조건의 통과 수이며, 문장 전체의 유용성이나 게임 지식 정확도 점수가 아니다. 일반 운용 노트에도 콤보 내용이 포함될 수 있다.

실패는 두 갈래였다. 하나는 “스탯은 알고 있으니 스킬 전체를 설명해줘”의 부정을 판정기가 놓치는 경우다. 다른 하나는 확신이 낮아 판정을 넘긴 뒤 기존 경로가 소개 요청을 스킬 소개로, 콤보 요청을 일반 운용 노트로 보내는 경우다. `flows.json`에는 채택한 판정과 실제 답변을 함께 남겨 구분할 수 있다. 분류기만 교체하면 대화 오류가 모두 해결된다는 결과는 아니다.

## 크기와 속도

| 임베딩 모델 | 임베딩 가중치 크기 | 로컬 문장 인코딩 중앙값 | 분류 헤드 |
| --- | ---: | ---: | ---: |
| Snowflake Arctic embed2, Ollama F16 | 약 1.16 GB | 약 16 ms | 45,100 bytes |
| multilingual E5-small, ONNX q8 | 약 118 MB | 약 5 ms | 16,940 bytes |

Arctic은 로컬 Ollama, E5는 Node CPU에서 측정했다. 모델 준비 후 20문장의 문장 하나씩 인코딩 시간을 측정했고, 다운로드·초기화 시간과 분류 헤드 시간은 제외했다. 모바일 브라우저의 다운로드·메모리·추론 시간은 아직 측정하지 않았다. E5 가중치 외에도 토크나이저 등 파일이 필요하다.

Arctic 태그의 실제 digest와 E5의 고정 revision은 각 JSON에 기록했다. 벡터 캐시는 모델 식별자와 입력을 기준으로 재사용한다. `classifierBytes`는 Python 객체의 pickle 크기로, 브라우저 배포 파일 크기를 의미하지 않는다. 위의 분류 헤드 크기는 실제 내보낸 float32 바이너리 크기다. 현재 앱의 622,592바이트는 범위와 노트 주제 두 판정기를 합친 크기다.

## 결정과 남은 일

요청 범위 판정의 다음 후보는 **의미 임베딩 + 로지스틱 회귀**로 정한다. kNN은 이 자료에서 정확도가 낮고 투표 비율을 확률로 쓸 수 없어 우선 선택하지 않는다. Arctic은 품질 비교 기준으로 쓰고, 브라우저 후보인 E5는 크기와 실제 대화에서의 개선 폭을 확인한 뒤 운영 도입을 판단해야 한다.

운영 도입 전에 낮은 확신을 기존 낱말 규칙으로 보내는 의도 판단 경로를 정리해야 한다. 학습된 판정과 대화 상태가 다음 행동을 정하고, 애매한 경우에는 선택지를 제시하는 방향이 맞다. 대상·스탯·슬롯·조건 추출은 이번 범위 분류 실험으로 검증한 것이 아니며, 별도 학습과 평가가 필요하다.

현재 배포는 문자 로지스틱 판정기를 사용한다. 스킬 카드 재사용과 모든 스킬 상세 정보 노출은 배포했지만, 이번 임베딩 후보는 연구 스크립트에만 연결했다. 이 10조합 비교에는 LoRA와 생성 LLM 판정을 포함하지 않았다. 후속 [부정·정정 시험](negation/README.md)에서 예시 보강과 로컬 0.8B JSON 판정을, [낮은 확신 전달 시험](hybrid/README.md)에서 두 판정기를 함께 쓰는 정책을 비교했다. 임베딩 인코더 자체는 딥러닝이며, 그 위의 로지스틱·kNN 판정기가 전통적인 ML이다.

## 한계

수작업 예시 모음의 결과다. 기존 66개 시험은 이전 개선에서도 사용한 회귀 자료라서 독립적인 실사용 정확도 추정으로 볼 수 없다. 추가 질문은 언어와 범위가 균등하지만 실제 질문 빈도를 반영하지 않으며, 대화 시험은 오공·피오라 중심의 작은 모음이다. 오타 전체, 복합 상황, 모든 챔피언, 모든 상태 추출의 품질을 증명하지 않는다.

## 재현

설치된 프로젝트 의존성, 로컬 Ollama의 `snowflake-arctic-embed2:latest`, 모델 파일을 처음 받을 네트워크가 필요하다. 명령은 프로젝트 루트에서 순서대로 실행한다. `uv`가 Python 실험 의존성을 고정하며, Transformers.js는 프로젝트 설치본을 사용한다.

```sh
uv run --python 3.13 --with numpy==2.5.3 --with scikit-learn==1.9.1 python dev/scripts/advisor/offline-classifier/compare-request.py
npx tsx dev/scripts/advisor/offline-classifier/embed-request-small.ts
uv run --python 3.13 --with numpy==2.5.3 --with scikit-learn==1.9.1 python dev/scripts/advisor/offline-classifier/compare-request-small.py
npx tsx dev/scripts/advisor/offline-classifier/compare-request-flow.ts
npm run type-check:scripts
npx eslint dev/scripts/advisor/offline-classifier/embed-request-small.ts dev/scripts/advisor/offline-classifier/compare-request-flow.ts --max-warnings 0
```

모델과 벡터 캐시는 Git에서 제외한 `dev/research/.cache/request-comparison`에 저장한다. 캐시를 사용한 실행의 `encodeBatchSeconds`는 새 벡터 계산 시간만 나타내므로 전체 자료 인코딩 시간으로 해석하면 안 된다. `report.json`, `e5-small-report.json`, `flows.json`에는 입력 또는 실행 코드의 해시와 오류 사례를 기록했다.
