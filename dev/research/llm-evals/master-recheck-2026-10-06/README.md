# 현재 master의 수치 QA 재측정, 2026-10-06

최신 master `7dbef37f92768896b2566cebab7f48a85f2798b7`의 실제 대화·요청 분류·검색이
선택한 근거까지 반영하면 **현행 Qwen 58/132 (43.9%)**, **새 QA Qwen 78/132 (59.1%)**다.
같은 최신 라우팅을 두 모델에 적용했으며 차이는 **20문항, 15.2%p**다.
이 점수는 고정된 수치 질문에서 선택된 문서를 읽고 숫자·단위를 추출하는 시험이며,
최종 카드 답변의 정확도나 전체 챗봇 품질 점수가 아니다.

앞선 **92/132**는 이전 평가 경로가 선택한 문서를 고정한 새 QA 모델 점수다. 그 문서를
그대로 주면 현재 master는 **67/132**, 새 QA 모델은 **92/132**다. master 원본 graph로
132문항을 다시 평가했으며 132개 답이 이전 baseline과 모두 같았다. 모델 가중치는
바뀌지 않았지만 최신 대화 경로는 일부 문서 선택·공개를 달리했다.

| 비교 조건 | 현재 master | 새 QA Qwen |

## 최신 경로의 확인과 원인 분리

commit의 `answerDialogue`, 오프라인 request classifier, 0.8B 생성 fallback,
원래 판정 헤드와 벡터 검색을 실제로 실행했다. 질문별 대화 이력과 챔피언 선택은 비웠다.
request fallback은 master 모델과 native chat template을 사용해 실제 WebGPU에서
69번 생성했고, JSON 범위 검사에 55개가 채택됐다. 모두 1개 이상의 실제 생성 토큰과
0보다 큰 프롬프트 길이를 검증했다. 초기 토큰화 오류·0토큰 시도는 결과에서 제외했다.

최신 경로의 정답 문서 도달은 **92/132**, 답변 문구의 정답 문자열 포함은 **90/132**다.
문구 포함은 여러 숫자 중 정답도 들어 있는지를 재는 지표라 수치 QA 정답과 다르다.
기존 `planAnswer` 평가 경로의 문서 도달 112/132와 바로 비교해 모든 차이를 새 분류기
탓으로 돌리지 않았다. 같은 최신 대화 코드에서 분류기만 바꿔 별도로 확인했다:

- 새 request 분류를 모두 끄면 정답 문서 106/132, 문구 포함 104/132.
- 오프라인 request 분류만 사용하면 역시 106/132, 104/132.
- model fallback까지 켜면 92/132, 90/132.

따라서 이 도메인 수치 질문에서는 model fallback을 켤 때 문서 도달이 순감 **14개**였다.
이 결과는 챔피언 상담 등 다른 요청 범위의 분류 성능으로 일반화하지 않는다.
추가 QA 학습보다 먼저 이 경로의 근거 누락을 점검할 이유가 있다.

새 문맥 132개 중 **109개는 이전 프롬프트 토큰과 완전히 같아** immutable graph의
기존 deterministic 응답을 재사용했다. master 응답은 이번에 재평가한 기록이다.
달라진 **23개를 각 모델로 다시 평가**했고, 그중 22개는 선택 문서가 없어 평가 규칙에
따라 NOT_FOUND를 반환했다. 정답·정답 문장 위치로 문맥을 고르지 않는다.
기반·새 QA graph와 tokenizer는 기존 실행의 같은 파일이며 모델 가중치를 변경하지 않았다.

최신 흐름에서도 문서 숫자 검사로 걸러지지 않는 오답은 현행 21개, 새 QA 12개다.
근거가 있다는 검사만으로 새 QA를 자동 공개할 수 없다는 제한은 남는다.

## master 변경과 비교 조건

`git fetch origin master` 후 HEAD와 origin/master가 위 commit으로 같음을 확인했다.
수정 중인 로컬 파일을 제외하기 위해 별도 detached worktree에서 commit 소스와 자료를
읽었다. 최신 변경은 낮은 확신의 요청을 기존 0.8B로 보완하는 요청 범위 분류와 워커
검사다. 배포 모델 graph는 기존 graph와 SHA-256이 같다:
`f2713e76dd9d2ea14e177fb027923c0392c00f18a134f7222ee99d2ab0490f40`.

132문항은 기존 source commit `4d6267596bb9ee9f9a35877dce09377574ac1084`의
한국어 새 수치 질문 중 상충하는 값의 4문항을 제외한 고정 목록이다. 최신 master의
`planAnswer`와 실제 분류·벡터 검색을 이전과 같은 단일 턴 평가 경로에 연결하니, 선택한
문서와 전체 근거가 **132/132 모두 이전과 같았다**. 정답 문서 도달은 112/132,
앱 문구의 정답 문자열 포함은 110/132로, 정확한 수치 답변 점수와 구분한다.

전처리는 질문만으로 1,300자 문맥을 선택한다. 토큰화·프롬프트·greedy·최대 생성
24토큰·양끝 공백만 제거하는 정답 비교와 Mac WebGPU backend는 기존 평가와 같다.
이전 고정 근거의 새 QA graph `qa_scale=1` 결과 92/132는 완료한 파일럿에서 가져왔다.
master는 QA adapter가 없는 원본 graph로 132문항을 재평가했다. 최신 근거의 78/132는
위의 109개 입력 일치 검증과 23개 변경 입력 재평가를 합친 점수다.

| 같은 132문항 수치 QA | master 재측정 | 새 QA Qwen |
| --- | ---: | ---: |
| 정확한 숫자·단위 | 67/132 | 92/132 |
| 정확도 | 50.8% | 69.7% |

master의 65개 오류는 거절 10개, 단위·표기 18개, 잘못 고른 값 37개다. 새 QA도
검사를 통과한 오답 15개가 있어 기본 응답 교체의 충분조건이 아니다. 최신 게임 규칙,

## 결정 제안: 요청 분류와 QA 학습을 분리

새 QA adapter는 같은 근거·같은 라우팅에서 수치 추출이 개선되어 우선 후보로 유지한다.
이는 전체 챗봇이나 자유 대화 모델을 대체하라는 결론이 아니다. 최신 흐름의 검사 통과 오답
12개가 남으므로 자동 숫자 응답의 기본 활성화는 보류한다.

요청 분류 보완은 전 유형에서 나빠진 변경이 아니다. 별도로 보존한
`dev/research/llm-evals/request-classifier/comparison/hybrid/`의 운영 채택 시험에서는
챔피언 대화 27→31/33, 최종 프롬프트 고정 뒤 새 변형 7→12/18로 개선됐고 두 모음에서
기존 정답의 회귀는 0개였다. 이 수치는 해당 연구 기록에서 확인했으며 이번에 그 51건을
재실행한 것은 아니다. 수치 QA 문서 도달 106→92/132와 다른 평가 기준이므로 합산하지 않는다.

현재 권고는 Qwen3.5 0.8B를 유지하고 새 QA adapter를 수치 추출 후보로 채택하며,
검증된 수치·규칙 조회가 요청 범위 판정 때문에 기각되는 회귀를 먼저 수정하는 것이다.
범위 보완을 전역으로 끄거나 master 전체를 되돌리는 결정은 현재 근거로 정당화하지 않는다.
수정 뒤에는 수치 QA와 챔피언 대화 두 모음을 따로 평가하고, 튜닝에 쓰지 않은 추가 질문으로
최종 검증한다. 기존 정답 보존·수치 정답 증가·잘못된 답 공개 감소를 함께 확인한 뒤
QA 적용 범위를 제한해 활성화한다. 이 절은 제안이며 운영 코드나 기본 모델을 변경하지 않았다.
