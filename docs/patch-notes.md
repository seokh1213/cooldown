# 패치 변경 내역

2026-10-08 기준 구현과 보관 자료를 확인했다. 현재 기능·JSON 계약은 이 문서,
남은 작업은 [제품 로드맵](product-roadmap.md), 릴리스는 [데이터·PWA 갱신](data-and-updates.md)에서 관리한다.

`/patch-notes`는 최신 패치의 변경 목록으로 열린다. 26.19·26.20과 앞으로의 현재
패치는 공식 원문의 협곡 챔피언·아이템·게임 체계 변경을 표시한다. 전후 수치,
계수·조건, 동작 변경을 함께 보존하며 자연어 요약이나 LLM 추론을 사용하지 않는다.
이전 패치들은 보관한 게임 데이터의 숫자 비교를 유지한다.

## 공식 원문 보완, 2026-10-08

26.20은 챔피언 16종 중 9종·15개 수치만 표시하고 변경 아이템 3종을 모두 놓쳤다.
26.19는 마스터 이의 쿨타임 반환 방식·순간이동 체계 변경을 누락했으며 오로라 R과
일부 복합 수치를 공식 표기대로 재현하지 못했다. 원인은 수치 키 허용 목록,
스킬 내부 값·계산식만 수집하는 범위, 서로 다른 배열 랭크 규칙이다.
아이템 스킬 가속은 `mAbilityHasteMod` 대신 `AbilityHasteMod`를 읽던 오류도 고쳤다.

공식 사이트의 sitemap에서 URL을 찾아 한국어·영어·대만 중국어 원문을 수집한다.
Next 데이터의 본문을 추출하고 협곡의 Champions·Items·Systems 목록만 구조화한다.
공식 HTML의 중복 heading ID를 식별자로 사용하지 않는다. 다른 모드·스킨·클라이언트
공지·일반 버그 수정은 포함하지 않으며, 점수판 숫자 숨김 목록 15종도 밸런스에서 제외한다.
중국어 변경 문장은 대만 공식 원문이며 챔피언명·스킬명은 기존 현지화 자료를 유지한다.

26.19 원문 41행은 챔피언 17종·아이템 2종·게임 체계 1종의 43개 표시 항목으로,
26.20 원문 34행은 챔피언 16종·아이템 3종의 34개 항목으로 보존한다.
41→43은 공통 아이템 2행을 세계 지도집·룬 나침반으로 각각 나눈 결과다.
순간이동의 비상단 변경 없음도 원문 조건과 함께 표시한다.

`data/patch-notes/official/<patch>.json`은 언어별 공식 URL·본문 SHA-256·수집 시각·
추출한 전후 문장·제외 목록을 보관한다. 원문 전체 HTML은 저장소에 복제하지 않는다.
숫자 비교용 원본·스냅샷은 수정하지 않는다. 공개 보고서의 `officialSource`와
`valueType: "text"`로 공식 출처와 게임 데이터 숫자를 구분한다. 기존 보고서도 계속 읽는다.
`gameDataKey`는 스킬 아이콘·스탯 글리프 연결용이며 공식 수치의 출처를 대체하지 않는다.

3언어의 대상·섹션·행 수와 전후 숫자를 검증하고, 원문 행의 공개 보고서 누락을
데이터 테스트에서 거부한다. 번역의 문장 순서 차이는 허용하되 숫자의 집합은 같아야 한다.
원문이나 번역이 준비되지 않으면 현재 패치 생성은 실패하며 불완전한 보고서를 새로 배포하지 않는다.
이미 보관한 같은 패치 원문은 재사용한다. 같은 패치의 추가 공지·핫픽스 갱신은 이번 범위에 없다.

## 표시 방식

챔피언 초상·이름 → 스킬 아이콘·이름 → 변경 항목과 이전·현재 수치의 순서로
읽는다. 공식 패치 노트처럼 챔피언별로 구분하면서 제목 아래 간격과 챔피언
사이 여백을 줄였다. 1440 × 1050 화면에서 첫 수치는 약 760px에서 500px로
올라왔다. 모바일은 항목 아래 전후 숫자를 가깝게 붙인다.

PC 오른쪽에 버전 목차를 고정하고 목차 안에서 과거 기록을 스크롤한다.
모바일은 상단 드롭다운에서 패치를 선택한다. 실제 보고서가 있는 패치만 표시하며,
비교 기준만 보관한 버전의 안내 화면은 만들지 않는다. 내부 원본 링크,
다운로드, 출처 판본 목록은 사용자 화면에 표시하지 않는다.

챔피언명·스킬명은 수집 당시의 현지화 이름을 보관한다. 초상·스킬 아이콘은
현재 앱에 설치된 이미지 판본을 기본값으로 사용한다. 변경 수치의 실제 스킬
경로에 별도 아이콘이 있으면 해당 패치의 이미지를 수집해 로컬 WebP로 보관한다.
아펠리오스의 다섯 무기와 엘리스의 거미 W 등을 슬롯별 기본 이미지와 구분한다.
R에 저장된 라이즈 Q 효과·엘리스 패시브는 화면의 Q·P 소속을 유지한다.
현재 별도 이미지 47개를 보관하며, 같은 이미지는 내용 해시로 중복 저장하지 않는다.

챔피언 요약은 실제 링크다. 선택한 패치와 `#patch-<championId>`를 URL에 넣는다.
직접 열기·새로고침·뒤로가기·앞으로가기에서 데이터 로딩 후 해당 챔피언으로
이동하며, 버전을 바꾸면 기존 프래그먼트를 지운다. PC와 모바일에서 동일하게 동작한다.

기본 능력치와 아이템 스탯에는 앱의 공통 스탯 글리프를 붙인다. 번역 문자열이
아닌 수치 키로 아이콘을 선택한다. 공식 원문이 있는 패치는 선택한 패치·언어의
공식 글로 연결하고, 과거 숫자 비교 패치는 공식 게임 업데이트 목록으로 연결한다.

스킬 제목은 기존 `SkillTooltip` 컴포넌트를 쓴다. PC는 호버 미리보기와 클릭
상세창, 모바일은 탭 상세창을 제공한다. 미리보기는 하나만 열리며 같은 Q 슬롯의
개별 무기도 독립적으로 구분한다. 상세창·Escape로 닫은 미리보기가 포커스 복귀로
다시 뜨지 않고, 실제 포인터 이동으로 다시 열 수 있다. 화면 크기를 모바일로
바꾸면 호버 미리보기를 닫는다. 모바일 스킬 버튼은 높이 44px 이상이며 상세창은
화면 양옆 16px 안쪽에 두고 본문을 스크롤한다. 좁은 화면에서는 쿨타임·소모량을
제목 아래에 표시한다.

과거 숫자 비교 보고서는 기본 능력치, 재사용 대기시간, 피해량, 계수, 지속시간, 소모량을 고정 용어로
표시한다. 챔피언 능력치·스킬 수치와 협곡 아이템 능력치가 비교 범위다.
버그 수정, 게임 체계, 스킬 구조 변경의 의미나 변경 의도는 해석하지 않는다.
상향·하향은 항목에 등록한 숫자의 방향 규칙으로만 판정한다.

공식 원문을 보완하기 전 숫자 비교 보고서는 수집한 게임 파라미터와 공식 노트의
값이 다를 수 있고, 등록하지 않은 필드는 보고서에서 제외된다. 예를 들어
오로라 R의 CDragon `AreaDuration` 배열은 26.18에
`[1.75,2.5,3.25,4,…]`, 26.19에 `[2.5,3,3.5,4,…]`이며, 현재 파서는
랭크 1~3 인덱스로 `2.5/3.25/4 → 3/3.5/4초`를 표시한다.
이 수치와 공식 노트의 표기는 다르다. 26.19의 현재 공개 보고서는 공식 원문의
`1.75/2.5/3.25 → 2.25/2.75/3.25초`를 사용한다. 원래 스냅샷은 증거로 유지한다.

## JSON과 CI

```bash
# CI가 방금 생성한 public/data/version.json의 패치를 비교
npm run generate-patch-notes -- --current

# 한 해의 공개 패치를 소급 수집
npm run generate-patch-notes -- --backfill 26
npm run generate-patch-notes -- --backfill 25

# 지정한 두 패치 비교
npm run generate-patch-notes -- 26.18 26.19

# 지정 패치를 공식 원문으로 보완. 이후 같은 패치는 보관한 원문으로 재생성
npm run generate-patch-notes -- 26.18 26.19 --official
```

- `data/patch-notes/sources/<patch>.json`: 챔피언 원본 숫자 기록.
- `data/patch-notes/snapshots/<patch>.json`: 숫자·고정 용어·출처를 담은 비교용 스냅샷.
- `data/patch-notes/reviews/<patch>.json`: 매핑하지 못한 원본 키와 전후 숫자.
- `data/patch-notes/official/<patch>.json`: 공식 원문의 전후 문장·출처·언어별 검증 자료.
- `data/patch-notes/skill-catalogs/<patch>.<locale>.json`: 해당 판본의 스킬 이름·설명·이미지·쿨타임 메타데이터.
- `data/patch-notes/icon-catalogs/<patch>/<champion>.json`: 실제 스킬 경로·아이콘 출처·보관 이미지 연결.
- `public/patch-notes/<patch>.json`: 화면에 제공하는 변경 보고서.
- `public/patch-notes/index.json`: 최신 보고서와 과거 보고서 색인.
- `public/patch-notes/skills/<patch>.<locale>.json`: 공통 툴팁에 전달하는 패치별 스킬 상세 데이터. 43개 패치 × 3개 언어 = 129개.
- `public/patch-notes/icons/<content-hash>.webp`: 해당 패치에서 수집한 별도 스킬 아이콘.

이전 원본과 스냅샷은 덮어쓰지 않는다. 보고서는 보관한 스냅샷으로 재생성하며,
보고서 파일을 완성한 뒤 색인에 추가한다. 원자적으로 파일을 교체하므로 읽는
도중 일부만 작성된 JSON을 제공하지 않는다. 수집 도중 실패해도 완성한 패치의
기록은 유지하고 재실행 시 보관한 원본을 재사용한다.

현재 패치의 스킬 상세는 기존 앱의 정규화된 데이터를 사용한다. 과거 패치는
수집한 판본의 설명과 스냅샷 수치를 함께 보관한다. 툴팁 JSON도 한 번 보관하면
과거 수치·설명을 다시 만들지 않는다. 아이콘 연결을 보완할 때만 이미지 메타데이터를
갱신하여 다음 패치가 수집된 뒤에도 과거 상세 데이터가 유지된다. 읽을 때
패치·언어·원본 판본을 검증하여 현재 패치 수치를 과거 화면에 섞지 않는다.

원본 보관 경로는 `public/data` 정리와 독립되어 있고, `public` 밖이어서 빌드에
복사되지 않는다. 같은 패치의 추가 빌드와 핫픽스 비교는 현재 범위에 포함하지 않는다.

`.github/workflows/update-static-data.yml`은 매시간 17분에 DDragon 판본과 CDragon
빌드 표식을 검사한다. 새 자료가 감지되면 정적 데이터 생성 후 `--current`로
현재 보고서와 보관 범위 내 누락된 과거 보고서를 순서대로 생성한다. 수집한
현재 판본보다 미래인 upstream 패치를 섞지 않으며 연도 전환도 처리한다.
원본·스냅샷·보고서·스킬 상세·아이콘·색인을 함께 Git 보관 대상으로 넣고,
배포 산출물에서 보고서·스킬 JSON 복사와 내부 파일 제외를 확인한다. 공개 보고서와
스킬 상세 JSON·별도 아이콘은 PWA 설치 캐시에 포함한다. 검증·빌드 후 GitHub Pages로
자동 배포하며, 화면은 색인의 최신 보고서와 과거 보고서를 읽는다. master push와
수동 실행도 같은 전체 흐름을 수행한다.

## 지속 검증

완료한 체크 15개는 위 구현 계약으로 정리했다. 남은 TODO로 중복 관리하지 않는다.
과거 데이터의 불변성, 3언어의 패치·스킬 상세, URL·기록 복원, 툴팁 조작,
화면 폭·테마, CI 생성과 PWA 캐시는 계속 검증한다.

데이터는 `tests/data/patch-notes.test.ts`, 브라우저는 `e2e/patch-notes.spec.ts`,
PWA는 `e2e/pwa-updates.spec.ts`에서 확인한다.

기존 공통 `SkillTooltip`의 긴 함수는 별도 구조 개편 없이 노출 정책과 트리거
확장 부분만 수정했다. 기존 쿨타임 화면의 패시브·Q 툴팁과 스탯 아이콘도 함께
검증하여 공통 컴포넌트의 기존 동작을 확인했다.

캡처와 렌더링 검증 기록: `research/ui-reviews/patch-notes/2026-10-02/`.
