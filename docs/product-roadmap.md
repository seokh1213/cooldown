# 제품 로드맵과 남은 작업

2026-10-06 코드·보관 데이터 기준. 현행 TODO는 이 문서에서 관리한다.
날짜가 붙은 실험·감사 기록의 보류 항목은 당시 상태이며, 현재 구현을 확인한 뒤에만 옮긴다.

## 제품 목적

게임 시작 전에 내 챔피언과 상대 챔피언의 스킬을 빠르게 확인한다.
사용자는 핵심 쿨타임과 조건을 확인하고 게임으로 돌아갈 수 있어야 한다.

## 현재 화면

- **챔피언 쿨타임 `/`**: 기존 여러 챔피언 비교와 저장된 탭을 유지한다.
- **VS 라인전 비교 `/vs`**: 별도 메뉴에서 내 챔피언과 상대를 선택한다.
  왼쪽은 내 챔피언, 오른쪽은 상대로 고정하고 스크롤 중에도 초상화·이름·역할을 유지한다.
  P·Q·W·E·R 순서로 같은 스킬 키를 같은 행에 배치한다.
  각 스킬은 아이콘·키·이름과 `14 / 12 / 10 / 8 / 6`처럼 연속된 쿨타임 수치를 함께 보여준다.
  랭크 순서·단위 안내는 표 위에서 한 번만 제공하고, 스킬 제목을 누르면 상세가 펼쳐진다.
  게임 중 랭크를 하나씩 선택할 필요가 없으며, 충전 시간은 별도 줄로 구분한다.
  쿨타임 관련 원문 문장을 해당 스킬 아래에 표시하고, 긴 스킬 상세는 같은 셀 안에서 펼친다.
  원문 발췌는 자동 판독이므로 모든 조건을 망라하지 않는다. 전체 설명도 확인할 수 있다.
  같은 키의 스킬을 같은 역할로 간주하거나 짧은 쿨타임을 우세로 표시하지 않는다.
  쿨타임 페이지와 독립적으로 선택을 저장하며 URL 공유·교체·초기화를 지원한다.
  표시 수치는 스킬 가속 적용 전이다. 조건부 쿨타임 변화는 스킬 설명에서 확인한다.
- **백과 `/encyclopedia`**: 챔피언 이야기·스킨, 룬, 아이템, 소환사 주문을 조회한다. 아이템은 능력치, 효과별 설명, 확인된 공식,
  재사용 대기시간, 조합식 순서로 읽는다. 원본 설명은 펼쳐볼 수 있다.
- **패치 변경 내역 `/patch-notes`**: 패치별 보고서와 챔피언 스킬 변경을 확인한다.
- **지식 도우미**: 실행 버튼에서 열며, 게임 자료·검토 노트·상성 답과 제한적 모델 판정을 사용한다.
  대화 기록은 당시 카드·패치·언어를 함께 저장한다. 현재 자료로 과거 카드를 교체하지 않는다.
- **시뮬레이션 화면**: 걷어냈다(`20b55af66`). 스킬 계수 계산(Ability v2 simulation)은 스킬 상세의 계수 표가 그대로 쓴다.

## 정적 페이지의 정보 갱신

현재 동작은 [도우미 설계](advisor-answer-pipeline.md), [데이터·PWA 갱신](data-and-updates.md),

### 자동으로 갱신할 정보

`.github/workflows/update-static-data.yml`은 매시간 17분에 원본 확인과 검증·배포를
설정하고 있다. 스케줄은 실행 시각을 보장하는 실시간 서비스가 아니며,
검증 실패 시에는 마지막 검증 데이터를 제공한다.

VS의 스킬 수치는 기존 Ability v2 데이터를 읽는다. 아이템 설명 구조화와
확인된 공식 추출은 `normalizeItems`에서 수행하므로 정기 생성에도 적용된다.
아이템만 다시 생성할 때는 `npm run generate-item-data`를 사용한다.
이 명령은 `public/data/version.json`의 패치를 고정해 다른 데이터와 버전을 맞춘다.

### 사용자 기기에 저장할 정보

개인 매치업 메모와 핵심 스킬 고정은 시안까지 만들었다가 넣지 않기로 했다(2026-09-29).
쓰는 사람이 있다는 근거 없이 화면만 늘어난다. 실제 요청이 생기면 다시 본다.

### 검토가 필요한 정보

특정 상대와의 교환 방식, 유불리, 룬·아이템 추천은 쿨타임 데이터만으로 확정하지 않는다.
`knowledge/playbooks`와 `knowledge/tips`는 유지하되 현재 VS에서 자동 노출하지 않는다.

검토 지문·의존 자료 해시와 패치 변경 감지는 이미 구현했다.
새 패치 번호를 붙이는 것만으로 기존 조언을 검증된 최신 정보로 취급하지 않는다.
형태·탑승 조건을 갱신한 7개 스킬(클레드 Q/E/R·렉사이 Q/W/E·렐 W)은 옛 승인 규칙을 제외하고 현재 원문으로 조회한다.
현재 승인 규칙 858개는 출처 지문과 검수 기록이 일치하는 자료다.

## 완료한 작업

- B·C·D 선택에 따른 포커스·조작 영역·실패 안내를 반영했다. 이후 새 디자인 변경은 비포/애프터 시안으로 먼저 검토한다.
- 과거 대화는 저장 당시 snapshot으로 표시한다. 손상 기록 처리와 20개 대화·대화당 80개 턴 제한을 갖는다.
- 자료·모델·라우트 로드의 실패 상태와 재시도를 구분하고, 저장소는 손상 캐시를 버린 뒤 다시 요청한다.
- 제이스 QWER, 니달리 QWE, 엘리스 QWER, 나르 QWE, 렉사이 QWE, 렐 W, 클레드 Q의 두 형태를 연결했다.
  형태별 레벨 표를 저장·표시하고 렐의 공유 마나 비용, 클레드의 발사 간격과 랭크별 탄환 재충전을 구분한다.
  클레드 E/R의 탑승 제한도 공식 원문에 근거해 세 언어의 기존 설명과 정상 재생성 경로에 반영했다.
- 소나 P의 과거 `?` 문제는 현재 3언어 데이터에서 해결됐다. 미해결 토큰이 없고 레벨 수치 두 계열이 있다.
- 과거 소급 조사 두 파일을 `data/ability-research/26.18/`에 원본 그대로 보존했다. 생성기·로더 경로를 맞추고 조사 패치가 다르거나 없는 입력을 거부한다.
- 26.19 소급 조사를 새로 실행했다. 재실행은 이전 원문을 history에 보존한 뒤 발행하고, `--champ` 부분 조사는 전체 결과와 분리한다.
- 생성 아이템 노트 21개의 검토용 이름 34개를 `reviewRefs`로 보존했다. 생성된 최종 본문의 `refs`·`avoid` 검증을 유지하며 `llm:validate` 불일치는 0건이다.
- 도우미의 단일 스킬 질문은 명시한 형태의 원문·수치를 선택한다. 모호한 형태는 확인하며 기본 질문과 과거 기록을 유지한다.
- 번역 검수 prompt의 패치는 입력 manifest에서 전달한다. 이전 2인자 호출은 특정 패치를 주장하지 않는다.
- 호출 없는 옛 해설·피드백 모듈과 미사용 함수들을 제거했다. 과거 피드백 파일을 읽는 수동 변환기는 유지한다.
- 중복 테스트를 줄이고 데이터 전수 확인은 반복문 안에서 유지한다. 테스트 수에 상한을 강제하지 않고 실제 실패를 보호하는 검증을 남긴다.

구현·검증 근거는 [적용 기록](../research/reviews/karpathy-antislop-2026-10-06/APPLIED.md),
[파일·테스트 정리](../research/reviews/karpathy-antislop-2026-10-06/FILE-NECESSITY.md),
[중복 코드·자료 검토](../research/reviews/karpathy-antislop-2026-10-06/SOURCE-DUPLICATION.md)에 있다.

## 사용자 검증이 필요한 작업

1. 실제 사용자에게 상대 조합을 주고 30초 안에 필요한 쿨타임을 찾는지 확인한다. 코드 테스트는 이 사용자 검증을 대신하지 않는다.
2. 반복 조회하는 핵심 스킬과 개인 메모 수요를 확인한다(수요가 보이기 전에는 만들지 않는다).
3. 자주 사용하는 매치업부터 검토한 짧은 상대법을 추가한다.
4. 반복해서 확인하는 상황이 드러나면 해당 상황에 한정한 계산을 설계한다.

## 계속 지켜야 할 검증 기준

- 기존 쿨타임 선택과 VS 선택이 서로 덮어쓰지 않는다.
- VS 직접 진입·새로고침·공유·교체·초기화가 동작한다.
- 세 언어와 모바일에서 두 챔피언을 함께 볼 수 있고 가로 넘침이 없다.
- 스크롤 후에도 내 챔피언과 상대가 어느 열인지 식별되며, 모바일에서도 스킬 아이콘과 이름을 숨기지 않는다.
- 랭크 선택 없이 전체 쿨타임이 보이며, 3랭크 궁극기·6랭크 스킬·충전형 스킬을 구분한다.
- 기본 아트록스·피오라 조합은 900px 높이 데스크톱 첫 화면에서 P~R을 함께 확인할 수 있다.
- 아이템 효과 이름·설명·공식이 분리되고 능력치를 중복 출력하지 않는다.
- 확인되지 않은 계산을 임의의 숫자로 채우지 않는다.
- 원본 수치와 조언의 검증 상태를 구분한다.
