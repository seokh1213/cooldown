# lol.ps 통계 오라클

> 목적: 상성 조언에 "실제로 사람들이 뭘 하는지"를 근거로 넣는다.
> 지금까지 아이템·룬·스킬 선택의 근거는 데이터 규칙과 사람이 쓴 지식 카드뿐이었다.
> 승률·픽률 통계가 없어 "지금 뭐가 좋은지"를 말할 수 없었던 공백을 메운다.

## 1. 버전 고정이 설계의 축이다

통계는 패치마다 다르다. 그래서 **어떤 버전 기준인지 알 수 없는 통계는 쓰지 않는다.**

- lol.ps 는 게임 패치를 내부 `versionId` 로 관리한다. `/api/info/active-version.json` 이
  `{versionId, description, patchDate}` 목록을 준다. 26.17 은 versionId 154, 배포일 2026-08-26 이다.
- 수집기는 우리 `version.json` 의 패치와 같은 `description` 을 찾아 그 `versionId` 로만 조회한다.
  패치가 없으면 실패하고 사용 가능한 목록을 보여준다. 조용히 다른 버전 통계를 섞지 않는다.
- 출력 파일 이름에 조건을 모두 적는다: `lolps-v<versionId>-r<region>-t<tier>.json`
- 파일 안에도 `patchVersion`, `lolpsVersionId`, `lolpsPatch`, `lolpsPatchDate`, `regionId`,
  `tierId`, `fetchedAt` 을 남긴다.

지난 패치 통계가 필요하면 `--patch 26.16` 으로 받는다. 다른 파일로 저장되므로 섞이지 않는다.

## 2. 수집하는 것

| 항목 | 내용 |
|---|---|
| 스킬 순서 | 1·3·6·11레벨 구간별 찍는 순서, 선마 순서, 각 조합의 픽률·승률·표본 |
| 시작 아이템 | 조합 단위 (도란의 방패 + 체력 물약) |
| 신발 | 픽률·승률 |
| 코어 아이템 | 1~3코어 각각, 그리고 순서를 포함한 2~3개 조합 |
| 룬 | 핵심 룬, 주 트리 2~4슬롯, 보조, **완성된 페이지 조합**, 파편 3개 조합 |
| 소환사 주문 | 조합 단위 (점멸 + 순간이동) |
| 14분 지표 | 킬·데스·어시스트·CS·분당 피해·포탑 방패의 값과 **라인 내 순위** |

14분 지표가 "뭐가 힘든지"를 수치로 알려준다. 예를 들어 나서스 탑은 64종 중 CS 60위,
분당 피해 60위, 킬 52위다. 초반이 약하고 파밍도 느린 챔피언이라는 통계적 근거가 된다.

## 3. API 와 파라미터

엔드포인트는 lol.ps 웹 앱 번들에서 확인했다. 공개 문서가 없어 번들의 호출 코드를 읽었다.

```
/api/info/active-version.json                                  패치 → versionId
/api/champ/{championId}/skill.json?region&version&tier&lane    스킬 순서
/api/champ/{championId}/spellitem.json?...                     아이템·소환사 주문
/api/champ/{championId}/runestatperk.json?...                  룬·파편
/api/champ/{championId}/champ-lane-features.json?...           14분 지표와 순위
```

| 파라미터 | 값 |
|---|---|
| `lane` | 0 탑, 1 정글, 2 미드, 3 바텀, 4 서포터 (번들의 TOP/JUNGLE/MIDDLE/BOTTOM/SUPPORT) |
| `tier` | 사이트 기본값 2. 표본은 1 이 가장 넓다(아트록스 탑 26.17 기준 59,394판 대 21,311판) |
| `region` | 0 (사이트 기본값) |

**티어 라벨은 확정하지 못했다.** 번들에 개별 티어 상수(IRON 4 … CHALLENGER 12)는 있지만
집계 브래킷 id(1, 2, 3, 13)의 라벨을 찾지 못했다. 그래서 라벨을 추측해 적지 않고 id 와
표본 수를 그대로 남긴다. 기본값은 사이트와 같은 2 를 쓴다.

## 4. 요청 수를 줄이는 방법

챔피언 173종 × 5라인 × 4엔드포인트 = 3,460 요청이 되는데, 위키 포지션 데이터로 라인을 좁힌다.
나서스는 탑만, 잭스는 탑과 정글만 조회한다. 실제 수집은 **832 요청**으로 끝났고
챔피언·라인 203건, 표본 합계 289만 판을 담았다.

응답 원본은 `research/.oracle-cache/lolps/v154/r0/t2/lane0/...` 에 캐시한다(git 무시).
경로에 버전·지역·티어·라인이 들어가므로 재실행 시 같은 조건은 다시 받지 않는다.
`--refresh` 로 강제 갱신한다.

## 5. 사용법

```bash
npm run oracle:probe                          # API 표면 탐색 (엔드포인트 확인용)
npm run oracle:build                          # 현재 패치, tier 2
npm run oracle:build -- --tier 1              # 표본이 가장 넓은 브래킷
npm run oracle:build -- --patch 26.16         # 지난 패치
npm run oracle:build -- --limit 5             # 5종만 (연습)
npm run oracle:build -- --refresh             # 캐시 무시
npm run oracle:query -- --list                # 수집된 오라클 목록
npm run oracle:query -- --champ 나서스         # 챔피언 통계 출력
npm run oracle:query -- --champ Jax --lane jungle
```

## 6. 수집 결과 (26.17, region 0, tier 2)

| 항목 | 값 |
|---|---|
| 챔피언 | 173종 |
| 챔피언·라인 | 203건 |
| 표본 합계 | 2,894,521판 |
| 요청 수 | 832건 |
| 파일 크기 | 4.0 MB |

나서스 탑 예시(31,030판)는 선마 Q > W > E(픽률 90.7%, 승률 51.9%), 시작 도란의 방패와 물약,
신발 명석함의 아이오니아 장화, 코어 삼위일체 > 얼어붙은 심장 > 정령의 형상,
룬 기민한 발놀림 페이지, 주문 유체화 + 순간이동이다.

## 7. 조언에 연결한 방식

오라클은 **권장안 초안**과 **통계 근거 섹션** 두 곳에 들어간다. 우선순위는 이렇다.

1. 상성 한정 지식 카드 (사람이 검증한 매치업별 판단)
2. **오라클 통계** (해당 패치·라인의 실제 픽률·승률)
3. 챔피언 단위 지식 카드
4. 데이터 규칙 (역할군·방어 스탯)

오라클이 규칙보다 앞서는 이유는 메타 적합도를 담기 때문이다. 상성 한정 지식보다 뒤에 두는
이유는 통계가 "상대가 누구인지"를 구분하지 않기 때문이다. 시스템 규칙에도 이 순서를 명시해,
통계와 상성 지식이 어긋나면 지식을 따르도록 했다.

표본이 작은 항목은 버린다. 기본 기준은 픽률 8% 이상, 표본 200판 이상이고 항목별로 다르게 둔다.
`significant()` 가 이 필터를 담당한다.

출력 형식에 **스킬 순서** 소제목을 새로 넣었다. 통계가 생기기 전에는 답할 수 없던 항목이다.

분할 호출에서도 나눠 싣는다. 빌드 이유 호출에는 아이템·룬·주문 통계를, 라인전 호출에는
선마 순서와 14분 지표만 넣어 프롬프트를 아낀다.

### 실제 출력 (나서스 vs 피오라, gemma4:12b)

확정 구간은 전부 통계에서 나온다.

```
## 시작 아이템        도란의 방패, 체력 물약
## 첫 아이템          명석함의 아이오니아 장화, 처형인의 대검, 판금 장화
## 최종 아이템        삼위일체, 얼어붙은 심장, 정령의 형상
## 룬                기민한 발놀림, 승전보, 전설: 가속, 최후의 저항, 불굴의 의지, 재생의 바람
## 룬 파편            스킬 가속, 체력 증가, 체력 증가
## 소환사 주문        유체화, 순간이동
## 스킬 선마 순서     Q > W > E (11레벨까지 QWEQQRQWQWR)
```

서술은 통계를 근거로 인용한다.

> 시작 아이템: 피오라의 높은 유지력에 대응하기 위해 방어력을 제공하는 도란의 방패를 선택하며,
> 이는 67.3%의 높은 픽률과 50.6%의 승률을 기록하고 있습니다.
> 최종 아이템: 삼위일체 > 얼어붙은 심장 > 정령의 형상 순서의 조합은 56.3%의 승률을 기록하고 있습니다.

평가 기준(아트록스 vs 피오라)은 e2b·12b 모두 8/8 을 유지했다. 프롬프트는 분할 호출당 3.1k 토큰이다.

## 8. 한계

- **상성별 통계가 없다.** 수집한 것은 챔피언·라인 단위다. 상대별 승률은 별도 엔드포인트가
  필요하고 아직 찾지 못했다.
- **티어 라벨 미확정.** 4장 참고. id 와 표본 수로만 구분한다.
- **표본이 작은 조합이 섞인다.** 픽률이 1~2%인 항목까지 담기므로, 조언에 쓸 때는 표본 수를
  함께 보고 걸러야 한다.
- **출처가 비공식 API 다.** 공개 문서가 없어 번들에서 확인했다. 스키마가 바뀌면 수집기가
  깨질 수 있으므로 `oracle:probe` 로 먼저 확인한다. 서비스에 부담을 주지 않도록 요청 간격을
  기본 220밀리초로 두고 캐시를 쓴다.
