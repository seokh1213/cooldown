# 과거 패치 소급

> 현재 패치 데이터에 없는 스킬 설명을 직전 패치, 없으면 그 전 패치에서 찾는다.
> 찾은 것은 **덮어쓰지 않고** 어느 패치에서 왔는지와 함께 별도 파일에 담는다.

## 1. 결측은 두 종류다

지식 카드를 173종 쓰는 동안 스킬 설명이 비어 있는 자리가 계속 나왔다. 성격이 다르다.

| 종류 | 증상 | 원인 | 소급으로 해결되나 |
|---|---|---|---|
| 자리표시자 결측 | 본문에 `?` 나 `f1`, `dynamic:…` 이 남음 | 툴팁의 참조를 우리 파서가 못 풂 | 대개 아니다. 같은 자리가 과거에도 비어 있다 |
| 문장 소실 | 예전에는 있던 문장이 통째로 없음 | 라이엇이 설명을 줄임 **또는** 메커니즘이 실제로 삭제됨 | 문장은 찾아지지만 채택 여부는 확인이 필요하다 |

두 종류를 한 스크립트로 다루면 판정 기준이 섞인다. 그래서 도구를 나눴다.

## 2. `npm run llm:fetch-fallbacks` — 자리표시자 메우기

현재 패치에서 `?` 나 미해결 토큰이 남은 스킬을 모아, 직전 패치부터 거슬러 올라가며
같은 스킬을 **현재와 똑같은 조립 경로로 다시 만든다.** 그 패치에서 자리가 채워져 있으면 가져온다.

같은 경로를 쓰는 것이 핵심이다. `scripts/data-pipeline` 의 정규화·툴팁 조립을 그대로 거치므로
결측 판정 기준이 두 패치 사이에서 어긋나지 않는다. 다만 디스크의 현재 패치 데이터에는 쓰지 않는다.
과거 수치가 현재 데이터에 소리 없이 섞이면 안 되기 때문이다.

```bash
npm run llm:fetch-fallbacks              # 6패치까지 소급
npm run llm:fetch-fallbacks -- --scan    # 결측 목록만 보고 종료
npm run llm:fetch-fallbacks -- --depth 12
npm run llm:fetch-fallbacks -- --champ Kayn,Locke
```

출력은 `public/data/<patch>/llm/ability-fallbacks.json`.

### 26.17 결과

| 항목 | 값 |
|---|---|
| 결측 | 63건 (챔피언 49종) |
| 소급 성공 | 3건 — 벨베스 P, 나르 P, 로크 R (전부 26.15) |
| 미해결 | 60건 |

기대만큼 메워지지 않았고, 이유가 분명하다. 자리표시자 대부분은 라이엇 데이터의 공백이 아니라
**우리 파서가 못 푸는 참조**다. 과거 패치를 다시 조립해도 같은 자리가 같은 이유로 빈다.
카이사의 `f11.1`, 케인의 `dynamic:game_spell_Kayn_Q_main_f1` 이 그렇다.

그래도 3건은 실제 수치를 되찾았다. 로크 R 은 `ExecuteTooltipCalc` 때문에 처형 기준치 서술이
통째로 비어 있었는데, 26.15 본문에서 "체력이 10/11/12% 아래로 떨어지면 봉인" 을 되찾았다.

**남은 60건을 줄이려면 소급이 아니라 파서를 고쳐야 한다.** 소급은 그 판정까지 내려 준다.

## 3. `npm run llm:find-lost` — 사라진 문장 찾기

이쪽이 더 많이 건진다. DDragon 의 `championFull.json` 은 전 챔피언 설명을 한 파일에 담아
패치당 요청 한 번이면 되므로, 70패치를 거슬러 올라가도 부담이 없다.

```bash
npm run llm:find-lost                # 24패치
npm run llm:find-lost -- --depth 70
npm run llm:find-lost -- --champ Corki
```

출력은 `public/data/<patch>/llm/ability-lost-descriptions.json`.

### 비교 기준을 두 번 고쳤다

처음에는 DDragon 요약문끼리 비교했다. 오탐이 쏟아졌다. 라이엇이 요약을 줄여도 상세 툴팁에는
그 내용이 남아 있는 경우가 대부분이기 때문이다. **비교 기준을 우리가 실제로 쓰는 본문
(CommunityDragon 으로 조립한 `bodyHtml`)으로 바꿨다.**

그 다음에는 문장 대 문장 유사도를 썼는데 이것도 틀렸다. 라이엇은 한 문장을 여러 문장으로 쪼개거나
어순을 바꾸고, 그때마다 문장 단위 유사도가 뚝 떨어져 멀쩡한 설명이 사라진 것처럼 잡혔다.
**과거 문장의 글자 조각이 현재 챔피언 본문 전체에 얼마나 남아 있는지(`kept`)로 바꿨다.**
표현이 바뀌어도 고유한 낱말(폭탄 꾸러미, 저지 불가)은 남기 때문이다.

두 번 고치고 나서 26.17 기준 182건이던 후보가 50건으로 줄었다.

## 4. 자동으로 되살리지 않는 이유

문장이 사라진 이유는 자동으로 구분되지 않는다. 코르키가 그 증거다.

- 짐 꾸러미 설명은 24.9 까지 패시브에 있었다. `kept` 0.14 로 가장 확실한 후보였다.
- 게임 데이터에는 지금도 `Corki_ThePackage` 아이콘과 `PackageDuration` 값이 남아 있다.
- 그런데 **강화된 발키리 스킬(`CarpetBombMega`)은 25.1 과 26.1 사이에 사라졌다.**
  남은 것은 죽은 데이터고, 메커니즘 자체가 삭제된 것이다.

되살렸다면 없는 진입 수단을 있다고 쓸 뻔했다. 그래서 도구는 **확인 대기 목록**을 만들 뿐이고,
채택은 사람이 한다. `kept` 는 확신도가 아니라 확인 순서다.

반대 사례도 있다. 케인은 26.17 에서 Q·W·E·R 툴팁이 전부 깨졌고, 26.16 본문은 멀쩡하다.
여기서 되찾은 "그림자 암살자는 W 시전 중 이동 가능", "라아스트 W 는 적을 띄움" 은
현재 데이터 어디에도 없는 사실이라 지식 카드에 반영했다.

## 5. 지식 카드 작성에 연결

`npm run llm:source-pack -- --champ <챔피언>` 의 **5장 패치 소급**에 두 결과가 함께 실린다.

```
## 5. 패치 소급

### 과거 패치에서 메운 자리 (수치는 그 패치 기준)
[R] 연옥 — 26.15 본문
  … 표식이 남은 적 챔피언의 체력이 10/11/12% 아래로 떨어지면 봉인되고 …

### 예전에는 있었고 지금은 없는 설명 (확인 필요)
[P] 마법공학 탄약 (24.9까지) 폭탄 꾸러미를 집으면 이동 속도가 상승하고 …

### 소급해도 못 채운 자리: Q 살상돌격, W 몰아치는 낫, E 그림자의 길, R 그림자의 지배
이 스킬의 수치는 사실 카드의 계수·쿨타임을 보고, 본문 서술은 피한다.
```

마지막 줄이 중요하다. 소급해도 못 채운 자리는 **쓰지 말라고 알려 주는 것**이 최선이다.
작성자가 빈 툴팁을 보고 추측으로 메우는 것을 막는다.

## 6. 캐시와 부담

- DDragon `championFull.json` 은 응답이 1.8MB 라 설명만 추려서 캐시한다. 70패치에 약 10MB.
- CommunityDragon 챔피언 파일은 원본 그대로 캐시한다. 챔피언·패치 조합마다 한 번만 받는다.
- 둘 다 `research/.patch-cache/` 아래이고 git 에서 제외한다. `--refresh` 로 무시할 수 있다.

## 7. 한계

- **앱 데이터에는 반영하지 않는다.** 소급 본문은 LLM 계층 오버레이일 뿐이다.
  과거 패치 수치를 현재 툴팁으로 보여 주면 사용자에게 틀린 값을 말하게 된다.
  앱에 넣으려면 "26.15 기준" 같은 표기를 UI 에 함께 넣는 별도 결정이 필요하다.
- **문장 소실 판정에 오탐이 남는다.** `kept` 0.3~0.6 구간은 재작성과 삭제가 섞여 있다.
- **비교는 한국어 기준이다.** 로케일마다 번역 시점이 달라 다른 언어에서는 결과가 다를 수 있다.
