# 파일·테스트 정리 결과

**단위·데이터 테스트를 2,294개에서 1,210개로 줄였고, 모두 통과했다. 미사용 소스 5개도 삭제했다.**

## 승인 후 실제 적용

사용자의 추가 요청에 따라 작은 중복 제거에서 전체 테스트 유지보수 점검으로 범위를 넓혔다. 아래 수치는 그 재점검의 실행 전·후 기준이다. 테스트를 건너뛰거나 기본 실행 명령에서 제외하지 않았다.

**반복 질문·언어·구현 검사를 326개 실제 삭제했다.** 같은 라우팅 분기에 들어가는 문형, 챔피언 이름만 바꾼 복제, 언어별 동일 표시 검사, 단순 접근자와 항상 통과하는 빈 문자열 검사를 줄였다. 한 테스트 내부의 중복 예시 7개도 제거했다. 질문 분류·검색·대화 파일은 277→148개, 나머지 대화·조건 파일의 등록 사례는 126개 감소했다. 단위 테스트의 실제 삭제는 71개다.

**자료 전수 검사의 등록 테스트 759개를 공통 검사로 통합했다.** 챔피언·언어·패치·보정 자료를 표본 추출하지 않고 모두 검증한다. 실패 메시지에는 해당 챔피언·패치·항목을 남긴다.

| 전수 검증 영역 | 등록 테스트 전→후 | 유지한 범위 |
|---|---:|---|
| 도출 노트 | 369→6 | 365개 원문·nuance, 3개 생성 종류와 3개 언어 |
| 정적 스킬 자료 | 176→3 | 모든 챔피언의 세 언어 패시브, 영어 능동 스킬·계산 보고서 |
| 수동 스킬 보정 | 140→1 | 모든 대상·슬롯·출처·지문·태그·빈 보정 계약 |
| 패치 노트 | 87→3 | 모든 보관 패치의 전후 수치와 세 언어 스킬 자료 |

수동 보정 사유의 문체 강제 검사는 제거하고, 사유와 출처가 실제로 있는지는 검사한다. 도출 노트의 같은 카드 파생 계산은 365→363회로 줄였고, 정적 스킬 검사의 중복 영어 파일 읽기도 제거했다.

전체 수는 **2,294 − 326 − 759 + 1 = 1,210개, 47.3% 감소**다. 마지막 1개는 동시에 진행되던 작업에서 추가한 request-scope 회귀다. 최종 단위 539개·데이터 671개, 실패·취소·건너뜀 0개다.

**과거 카드 원본 7종·실제 답 생성기 6종 저장 복원, 저장 공간 실패와 재시도, 수치·단위, 부정·조건 정정, 부재 스킬, 오래된 대화 기억, 복수 요청을 유지했다.** worker 취소·로드 실패·캐시·배포 rollback·보안 검사의 고유 오류 경계도 남겼다. 모든 입력 문구나 언어 조합을 개별 테스트로 나열하는 방식은 줄였다.

`data-manifest.test.ts`는 기존 저장소 테스트에 합쳤다. 정상 patch·원본 버전 값은 동시 요청 검사에서 확인하고, 옛 스키마 거부는 실제 `ManifestRepository.get()` 경로에서 확인한다. 706줄의 툴팁 테스트는 일반 파싱·참조 계산 374줄과 레벨 계산 360줄로 나눴으며, 유효 검사 39개는 그대로다. 새 범용 테스트 helper는 만들지 않았다. 새 QA 테스트의 누락된 `rest` 필드도 공용 typed fixture로 보완했다.

**E2E는 188→183개, 모두 통과했다.** 같은 모바일 분기의 390px 중복 2개와 일반 smoke 3개를 통합했다. smoke의 고유 assertion 14개는 기존 흐름에 옮겼고, 검증 없이 스크린샷을 저장하던 23곳은 제거했다. 과거 카드·저장 실패·로딩 복구·키보드·테마·PWA 경계 검사는 유지했으며 제품 UI는 변경하지 않았다.

**미사용 소스 삭제:** `src/components/ui/select.tsx`, `src/lib/productMetrics.ts`, `src/lib/advisor/factPick.ts`, `src/lib/advisor/litePrompt.ts`, `src/lib/advisor/xmlAnswer.ts`. 활성 앱·스크립트·테스트의 import와 호출이 없음을 확인했다. 소스 585줄과 관련 환경변수·중복 선언 9줄을 제거했다.

종료 실험 3개의 결론은 기존 Git 이력에 남는다. 사실 선택은 코드 조립보다 정확도가 낮았고, 소형 모델 자유 서술은 실패했으며, XML 형식 준수도 사실 정확도를 개선하지 못했다. 남은 연구 도구에는 재실행·후속 계획·직접 사용 근거가 있어 추가 삭제하지 않았다. Python 연구 unittest 31개 모듈·74개 테스트도 모두 통과했다. `act_test.py`는 60문항 평가 자료 생성기로 분류하고 유지했다.

앞으로는 새 실패 경계나 실제 회귀를 잡는 테스트를 추가한다. 같은 분기에 들어가는 문구와 이름 복제는 대표 표본으로 유지하고, 자료 개수가 늘어나는 검증은 공통 불변조건 검사 안에서 전수 확인한다. 이 기준은 검증 범위를 판단하는 원칙이며 새 개수 제한이나 CI 우회 규칙을 추가한 것은 아니다.

**3 → 이 5개를 지워도 현재 앱이 크게 빨라지지는 않습니다.** 이미 브라우저 번들에 연결되지 않은 파일이므로, 정리 효과는 유지보수 대상과 혼잡 감소입니다. 동적 import와 worker까지 추적한 앱 의존 경로는 `src` 330개이며, 현재 기존 빌드의 `dist/assets` JS 청크는 25개입니다. 둘 다 첫 화면에서 전부 내려받는다는 뜻은 아닙니다.

자료 생성기에 필요한 tooltip parser나 타입 전용 파일은 브라우저가 실행하지 않아도 필요합니다. 작은 파일을 무조건 합치면 역할과 의존성이 섞이고, 파일을 나눠 필요한 시점에 읽게 하면 파일 수가 늘어도 초기 JS를 줄일 수 있습니다.

**4 → 연구 도구는 실험 종료 기준에 따라 다음 순서로 정리합니다.** `scripts/llm`의 307개 파일에는 자료 수집·지식 생성·검증과 모델 학습·평가·실험 재현 도구가 함께 있습니다. 자료 파이프라인은 패치 데이터·툴팁·이미지를 생성하고 검증하는 역할을 맡습니다. package 직접 진입점 45개와 문서에 기록된 수동 진입점 77개를 확인했습니다. Python 연구 테스트 32개도 있어, 앱 import가 없다는 이유만으로 삭제할 수 없습니다.

우선은 **미사용 후보 5개**, 다음은 **종료가 문서화된 실험 도구**입니다. 후자는 재현 필요와 현행 도구의 의존성을 확인한 경우에만 보관·삭제합니다. 진행 중인 연구 변경은 유지하며, 나머지 파일이 전부 필요하다는 증명까지 마친 것은 아닙니다.
