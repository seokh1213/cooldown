# 26.20 스킬 틱 전수조사

173챔피언의 P/Q/W/E/R 865슬롯을 Riot 툴팁과 LoL Wiki의 1,071개 스킬 문서 및 애니 소환수 문서 1개에 대조했다. 136슬롯에 확인된 반복 판정 145개를 추가했다. 6슬롯은 불확실한 이유를 표시하고, 나머지 723슬롯은 해당 자료에 스킬 자체의 피해·회복 틱이 명시되지 않은 것으로 분류했다.

136은 모든 항목이 완전히 밝혀졌다는 뜻이 아니다. 간격만 확인되면 간격만 제공하며, 지속시간이나 횟수는 비워둔다. `not_documented`도 틱이 절대 없다는 뜻이 아니다.

## 조사 범위와 근거

- 피해·회복, 연속 타격, 자원·중첩 변화, 보호막 및 명시적인 강화·감소 주기를 조사했다. 각 효과의 이름으로 피해 틱과 다른 반복 판정을 구분했다.
- 재충전 쿨타임, 서버 공통 통계 갱신, 시야·애니메이션·AI 탐색 타이머, 일반 소환수 평타 간격은 지속 피해 틱으로 분류하지 않았다. 티버의 피해 오라는 별도로 포함했다.
- MediaWiki API로 현재 문서와 리다이렉트를 수집했다. 모든 슬롯에서 주 문서를 확보했다. 보조 별칭 12개는 없는 문서로 남으며, 해당 슬롯의 주 문서 누락과 구분한다.
- `audit.json`은 865슬롯의 문서 URL, 위키 리비전 및 영구 링크, 원문 SHA-256, 검토 필드 SHA-256, 수치 탐색 표식을 보존한다. 긴 위키 원문은 저장소 및 앱에 포함하지 않는다.
- 앱에 넣는 값은 `knowledge/ability-ticks.json`의 검수 데이터다. 본문에서 ‘초’만 추출하거나 모델이 숫자를 생성하는 방식으로 만들지 않았다.
- 문서 검수 결과이며 게임 클라이언트의 프레임·타격 로그를 직접 계측한 결과는 아니다. 경계 시점·접촉 유지 여부의 예외를 문구로 함께 제공한다.

## 확정하지 않은 항목

- 브랜드 P: 4초 총피해와 틱당 피해 표기의 산술이 일치하지 않는다. 중첩별 적용 시점도 달라 횟수와 틱당 피해를 확정하지 않았다.
- 블라디미르 E: 미확인 주기는 충전 중 자신의 체력 소모다. 방출 피해는 같은 적에게 한 번만 적용된다.
- 케인 P: 전투 이탈 70초 뒤 내부 자원 초당 0.8 회복은 명시되나 실제 갱신 간격은 없다.
- 람머스 Q: 초당 이동 속도 증가량과 최대 6초 지속을 1초 갱신이라고 해석하지 않았다.
- 럼블 P: 기본 스킬 중단 4초 또는 R 중단 2초 뒤 열기 초당 10 감소는 명시되나 실제 갱신 간격은 없다.
- 사일러스 R: 레넥톤 R을 훔쳤을 때 마나 20 + 초당 5라는 조건부 효과의 실제 갱신 간격이 없다.

## 계산 시 주의한 사례

- 코르키 E: 0.25초 간격, 4초, 계속 적중하면 16틱. 표시 총피해 ÷ 16은 방어력 적용 전 1틱 피해다. 4틱에 최대 저항 감소, 마지막 적중 후 2초의 감소 잔류는 추가 피해 시간이 아니다.
- 코르키 W: 0.5초 간격, 불길 2.5초 = 5틱분. 이탈 뒤 피해 1초 잔류와 경계 판정 때문에 실제 적중 횟수를 5회로 보장하지 않는다.
- 카시오페아 W: 5/19초, 약 0.2632초 간격. 19틱 및 간헐적 18틱 사례를 제공한다. 0.25초·20틱으로 반올림하지 않는다.
- 워윅 R: 6틱의 홀수 피해 2/9, 짝수 1/9. 적중 시 효과는 1·3·5틱이다.
- 가렌 E·벨베스 E·루시안 R: 공격 속도나 치명타 등에 따라 횟수·간격이 달라진다. 고정 숫자로 대체하지 않는다.
- 말자하 R: 제압 피해 0.25초/2.5초/10틱과 바닥 지대 0.5초/5초/10틱을 분리한다.
- 우디르 각성 Q: 즉시 1회 + 0.2초마다 5회 = 총 6회다. 지속시간을 간격으로 나누어 5회로 만들지 않는다.
- 피들스틱 W·소라카 Q: 끝 틱 추가 피해 또는 회복량 분포가 달라 총량을 횟수로 균등 분할하지 않는다.
- 벨코즈 R: 피해 0.2초와 패시브 중첩 0.7초를 구분한다. 문서 2.6초와 공식 툴팁 2.5초가 달라 지속시간·총횟수는 확정하지 않는다.
- 멜 E: 피해 0.125초와 이탈 후 0.25초 잔류만 제공한다. 속박 지속시간 1.5초를 장판 지속시간으로 사용하지 않는다.
- 제이스 W·니달리 W·흐웨이 QE: 형태나 하위 스킬을 구분한다. 다른 형태에 동일 틱을 복사하지 않는다.

## 변경 및 갱신 절차

1. `npm run llm:ticks:collect -- /tmp/cooldown-tick-sources-<patch>.json`으로 현재 문서를 모은다. 출처는 재수집되지만 숫자를 자동 승인하지 않는다.
2. 원문·공식 툴팁을 대조해 `knowledge/ability-ticks.json`을 수정하고, 새 패치의 검토 해시를 보존한다. 미확인은 이유와 함께 남긴다. `npm run llm:ticks:record -- /tmp/cooldown-tick-sources-<patch>.json`으로 원문을 제외한 조사 기록을 생성한다.
3. `npm run llm:build -- --lang ko_KR`, `en_US`, `zh_CN`을 차례로 실행한다. 패치 또는 한국어 툴팁의 정확한 SHA-256이 달라지면 이전 값 대신 미확인 상태를 생성한다.
4. `npm run llm:ticks:audit`와 `npm test`를 실행한다. 모든 슬롯, 언어, 형태, 기록 복원, 버전 및 본문 변경 시 차단을 검사한다.
5. `npm run build` 후 `npx playwright test e2e/advisor-multi-skill-reference.spec.ts`로 모바일·데스크톱 카드와 대화를 검사한다. 실제 브라우저와 배포본도 확인한다.
6. `npm run llm:test:audit`로 테스트 목록을 갱신하고 기존 품질 회귀를 통과시킨 뒤 master에 반영한다. Advisor Regression Actions에 틱 데이터 검사를 추가했다.

## 구현·검증 기록

카드와 채팅은 동일한 구조화 데이터와 번역을 사용한다. 틱 정보는 접힌 ‘스킬 정보’ 밖에 표시하고, 근거 문서 링크를 제공한다. ‘W, E 틱’처럼 끝에 붙은 공통 조회 항목을 앞 스킬에도 적용하며, ‘W는?’ 후속 질문에도 틱 주제를 유지한다. 답변을 챔피언 이름별로 분기하지 않는다.

테스트: 틱 단위·대화 통합은 24개다. 확인·미확인 142슬롯 전체 조회, 세 언어 일치, 변신 형태, 모델 사용 여부에 따른 같은 근거 조회, 저장·복원 및 이름 속 음절 오인 방지가 포함된다. 기존 영상 팁 테스트로 ‘피들스틱’의 ‘틱’ 오인을 발견해 고쳤다. ‘내 E와 R이 쿨타임인데 어떻게 해?’를 수치 조회로 잘못 분리하는 경우도 기존 회귀로 발견해 막았다.

전체 자동 테스트 1,488/1,488, lint·타입 검사·프로덕션 빌드 통과. 집중 브라우저 검증 4/4 통과: 390/1280px, 다크 모드, 단일 카드와 자료 패널, 기록 복원, 후속 질문, 알려진/미확인/미기재 값, 키보드 근거 펼침, 44px 출처 링크를 확인했다. 실제 사용자 Chrome의 로컬 화면에서도 원래 W·E 질문과 ‘그럼 E는 몇 틱?’ 답변을 확인했다.

전체 품질 회귀는 5,893건 실측, 인프라 12/12, 누락·신규 실패·잘못 수락한 수치 0건이다. 통과 5,796건, 기존 실패 77건, 수동 검수 20건을 그대로 보존했다. 틱 메타데이터 때문에 dataHash가 변경되어 저장소 절차대로 전체 실측 기준을 갱신했다. [기준 갱신 근거와 실패 목록](baseline-refresh.json)에 상세히 기록했다. 실측 뒤의 출처 색상 보완은 UI만 바꿨으며 최종 소스의 전체 회귀는 master Actions에서도 실행한다.

UI 검수 기준: 기존 스킬 표 배치 유지, 틱 표제 중복 없음, 모바일 가로 넘침 없음, 출처 키보드 접근, 출처 링크 높이 44px 이상, 밝은·어두운 테마, 오류 없는 페이지. 의미 없는 장식·새 색상·애니메이션은 추가하지 않는다.

UI 세부 검증과 Delivery Gate는 [화면 검증 기록](ui-verification.md)을 참고한다. 배포 및 Actions 결과는 최종 검증 뒤 이 문서에 추가한다.
