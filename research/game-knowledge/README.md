# 챔피언 외 게임 지식 조사와 갱신 설계

2026-10-06 조사. 현재 앱 패치 `26.19`, DDragon `16.19.1`, CDragon `16.19`를 기준으로 했다.

이번 작업에서 출처 주소 수정, 문서 목록 조사, 공식 패치 URL 발견, 바론 원천 데이터 대조, 기존 노트 전체의 버전 백필, 제거 상태 답변, GitHub Actions 예약 감지를 구현했다. 38문서의 내용을 사실 단위로 작성·검수하는 절차와 새 수치 답변 연결은 다음 단계다. 조사 목록과 바론 예시는 앱의 승인된 지식이 아니다.

## 첫 수집 범위

기본 범위는 PC 소환사의 협곡 일반 드래프트·솔로/듀오 랭크·자유 랭크다. 신속 대전, 무작위 총력전, 아레나, 클래식, PBE는 규칙별로 별도 범위를 선언해야 한다.

1차는 40개 주제, 정규 문서 38개다. 다음 문서들은 존재를 확인했지만, 모든 문장과 수치의 현행성을 검수한 것은 아니다.

- 오브젝트 10개: Baron Nashor, Hand of Baron, Baron pit, Voidgrub camp, Touch of the Void, Hunger of the Void, Rift Herald, Eye of the Herald, Dragon pit, Dragon Slayer. 각 원소 드래곤·영혼·장로 효과는 해당 문서의 하위 규칙으로 나눈다.
- 정글·맵 9개: Monster, Jungling, Blue Sentinel, Crest of Insight, Red Brambleback, Crest of Cinders, Rift Scuttler camp, Jungle plants, Summoner's Rift. 몬스터 성장, 재생성, 버프 공유, 식물·지형 조건을 포함한다.
- 구조물·웨이브 6개: Turret, Crystalline Overgrowth, Inhibitor, Nexus, Minion, Farming. 포탑 방패·방어·보상, 억제기 복구, 미니언 생성·구성·성장을 포함한다. Crystalline Overgrowth는 Turret 문서의 절이다.
- 시야 7개: Sight, Fog of war, Brush, Stealth, Ward, Control Ward, Faelights. Fog of war는 Sight로 연결되므로 원문을 중복 수집하지 않는다.
- 경제·성장 8개: Gold income, Experience (champion), Champion gold bounties, Objective bounties, Death, Recall, Homeguard, Role Quests. 퀘스트는 역할마다 조건·보상을 분리한다.

2차는 세부 몬스터·미니언·장신구 12개와 전투 계산·상호작용 14개, 총 26개 주제다. 먼저 1차 답변 경로를 완성하고 넓힌다. 피해 계산과 군중 제어는 이미 있는 일반 규칙·스킬 지식과 중복될 수 있어 새 노트 생성 전에 대응 관계를 정한다.

항복·다시하기·닷지·랭크·채팅·핑 6개는 기존 지식을 유지하는 범위로 분리했다. Atakhan과 Feats of Strength 2개는 제거 기록만 유지한다. 문서나 분류가 남아 있다고 현재 게임에서 활성인 것은 아니다.

작업 전에도 `knowledge/game-meta.json`에 21개 항목과 advisor 번들의 일반 규칙·메커니즘이 있었다. 힘의 위업 제거 안내를 추가해 게임 메타는 22개다. 전체 검수 날짜 하나로는 사실별 마지막 변경과 출처 충돌을 표현할 수 없어 개별 버전 정보를 추가했다.

## 기존 노트 백필

사용자가 지정한 기본 기준 패치는 `26.19`다. 원본 1,559파일의 148,364개 노트·번역·구조화 규칙에 파일별 기본 메타데이터를 연결했다. 같은 기본값을 모든 번역에 복제하지 않고 파일별로 상속한다. 원본의 명시적 `verifiedPatch`, `evidence.patch`, 제거 기록이 기본값보다 우선한다. 원본 파일 해시도 기록한다. 백필은 새 사실 검수나 모든 번역의 승인으로 취급하지 않는다.

챗봇이 읽는 번들에는 챔피언 조언 4,078개, 팁 11개, 일반 규칙 70개, 메커니즘 79개와 승인 스킬 865개의 버전 정보를 직접 넣었다. 아이템 분류와 위키 챔피언 팁에도 정보를 붙였다. 버전 필드를 제외한 기존 번들 내용을 HEAD의 원본과 대조해 동일함을 확인했다. 승인 스킬의 초안 내부와 검수 원장은 바꾸지 않았다.

`baselinePatch`는 백필·수록 기준이다. `sourcePatch`는 기존 원천 패치, `verifiedThroughPatch`는 명시된 기존 검수 패치다. 예를 들어 26.17 검수 조언은 기준 26.19, 원천·검수 26.17을 함께 유지한다. 알 수 없는 마지막 변경·검수 패치는 null이다. `lifecycle.basis = backfill`인 활성 상태는 초기 기본값이며 새로운 활성 여부 검수의 증거가 아니다. 범위가 확인되지 않은 노트의 `scope`는 null이다.

아타칸·힘의 위업의 `lifecycle.state = removed`, `removedInPatch = 26.1`은 공식 노트와 현행 위키를 대조한 기록이다. 이 요소는 이름과 제거 상태를 검색에 남긴다. 직접 질문과 검색 문서 모두 상태와 제거 패치를 안내한다. 예전 효과를 현재 효과로 전달하지 않는다. 향후 재도입하면 상태 기록을 갱신하며, 과거 노트는 보존한다.

다시 실행할 때는 `npm run llm:backfill-note-versions`를 쓴다. 새 advisor 번들과 승인 스킬 번들을 생성할 때도 같은 메타데이터를 붙인다. 파일별 원장은 검수·추적용이고 큰 원장 전체를 브라우저에 싣지는 않는다.

배포 전 브라우저 확인에서 몬스터 공격력 질문에 생성 시간만 답하는 문제가 발견됐다. 승인된 상세 능력치·스킬 자료가 없는 질문은 세 언어 모두 자료 미확인 안내로 답한다. 직접 조회와 검색 문서 조회에 같은 처리를 적용했다. 제거 상태는 상세 질문보다 우선한다. 중국어 클라이언트 문자열의 `game_character_displayname_sru_atakhan = 厄塔汗`을 확인해 검색 별칭에도 추가했다.

26.18은 실제 원천·검수 이력에 남아 있다. advisor 조언의 명시적 검수 패치는 26.18 341개, 26.17 3,368개이며 일반 규칙·아이템 분류·위키 팁의 원천도 26.18이다. 26.19 수록 기준으로 바꾸는 작업은 이 자료의 새 사실 검수를 의미하지 않는다.

## 출처의 역할

**CDragon은 추출할 수 있는 수치·계산식, 위키는 조건·동작·현재 설명, 공식 노트는 변경의 시점과 의도**를 맡는다. 출처 간 충돌은 해당 사실만 보류하고 해결 근거를 남긴다. 항상 한 출처가 이긴다는 순서를 만들지 않는다.

[DDragon 공식 문서](https://developer.riotgames.com/docs/lol)는 챔피언·아이템·룬·소환사 주문·아이콘 등의 정적 자료를 제공한다. 문서화된 일반 JSON API에는 바론과 유충의 스탯·AI·효과를 완전하게 읽는 몬스터 지식 엔드포인트가 없다. 패치가 출시돼도 데이터가 즉시 갱신되지 않을 수 있다.

[CDragon의 바론 파일](https://raw.communitydragon.org/16.19/game/data/characters/sru_baron/sru_baron.bin.json)에는 체력·성장, 공격력·성장, 저항력, 공격 속도, 보상과 일부 스킬 계산식이 있다. 일반 Root와 URF Root를 구분해야 한다. 서버의 생성 타이머·AI·틱 수·적용 조건을 이 파일 하나에서 모두 확정할 수는 없다.

바론의 일반 Root는 기본 공격력 175와 성장 20이다. 위키의 레벨 성장식으로 계산하면 11레벨 350.5, 18레벨 515다. 기본값을 실제 출현 시 공격력으로 답하거나 성장 계수를 단순히 `레벨 × 성장`으로 계산하면 틀린다.

같은 파일에는 예전 시간당 체력·공격력 필드도 남아 있다. 필드 존재를 현재 실행 경로의 증거로 취급하지 않는다. 사거리도 위키 955와 raw 900이 달라 단위·측정 기준을 확인해야 한다.

동일한 [공식 26.1 노트](https://www.leagueoflegends.com/en-us/news/game-updates/patch-26-1-notes/)와 [현재 바론 위키](https://wiki.leagueoflegends.com/en-us/Baron_Nashor)에도 차이가 있다. Territorial 끌어당김은 공식 100% AD, 위키 140% AD이고, All-Seeing 균열은 공식 총 140% AD, 위키 고정 1000이다. raw 끌어당김 계산 계수 1.0은 공식과 맞지만, 실제 호출 여부는 별도로 확인해야 한다. raw 균열의 첫 타격·틱 식만으로 총 틱 수를 정하지 않는다.

주변 전체에 초당 저항력 감소를 준다는 공식 설명도 위키에서는 구현되지 않은 것으로 의심한다. 위키 Patch History의 최신 항목만 읽는 방식으로 이런 충돌이나 빠진 버그 수정까지 해결할 수는 없다.

## 공식 패치 노트 발견

처음 14.1은 공식 사이트 검색으로 찾고 원문에서 세 가지 바론 형태와 유충 도입을 확인했다. 지속 운영에서는 검색 결과 순위나 직접 만든 URL에 의존하지 않는다.

1. [robots.txt](https://www.leagueoflegends.com/robots.txt)의 sitemap index에서 언어별 사이트맵을 찾는다.
2. [영문 사이트맵](https://www.leagueoflegends.com/en-us/sitemap_loc.xml)의 실제 URL 중 PC LoL 패치 노트 경로를 고른다. 이번 발견 범위는 9.1부터 26.19까지 167개이며, 26.1~26.19는 모두 있다. 과거 모든 패치가 이 사이트맵에 있다는 뜻은 아니다.
3. 주제의 위키 Patch History에서 패치 문서로 이동하고, 해당 문서의 공식 외부 링크를 읽는다. 사이트맵에 빠진 과거 노트도 이 경로로 보완한다. 공식 도메인만 허용한다.
4. 각 공식 글의 본문과 중간 패치 업데이트를 저장하고 모드·절별로 분류한다. 같은 URL의 핫픽스 변경도 다시 감지한다.

26.1은 `patch-26-1-notes`, 26.13 등은 `league-of-legends-patch-26-13-notes` 형식이다. 숫자로 주소를 조립하면 빠진다. 앱·공식 패치 `26.x`와 DDragon/CDragon `16.x` 대응은 현재 버전 메타데이터로 보존한다.

목록의 URL 167개를 발견한 것과 본문 167개를 모두 검수한 것은 다르다. 이번 파일은 URL 인덱스이며 본문 검수 완료를 선언하지 않는다. 바론 직접 언급뿐 아니라 Epic Monsters 등 공통 변경도 관련 주제에 연결해야 한다.

## 사실 단위 구조

문서별 요약 하나 대신 사실마다 다음을 갖게 한다.

- `id`, `entity`, `property`: 예를 들어 `baron.stats.attackDamage`와 `baron.spawn.initial`을 분리한다.
- `scope`: 게임·맵·모드·형태·대상. 기본 조건 외에는 명시한다.
- `value`: 숫자와 단위, 시간·레벨·스탯 의존식, 최소·최대 범위. 자연어에만 수치를 저장하지 않는다.
- `conditions`, `effects`, `exceptions`: 살아 있는 팀원만 버프 획득, 사망 시 소멸 등 질문에 필요한 조건과 예외.
- `evidence`: 위키 리비전·절, 펼쳐진 원문 해시, CDragon 빌드·JSON 경로, 공식 노트 URL·절·본문 해시.
- `lastChangedPatch`: 해당 사실의 마지막 변경을 확인한 패치. 아직 확정하지 못하면 null.
- `verifiedThroughPatch`: 이후 변경이 없는지 확인한 패치. 단순 수집이나 URL 발견으로 올리지 않는다.
- `sourceFetchedAt`, `lastReviewedAt`: 수집과 사실 검수의 날짜를 구분한다.
- `status`, `sourceHash`, `factHash`: 승인 여부와 검수 근거. 승인 시 원문·후보 해시를 함께 기록한다.

예를 들어 마지막 버프 지속 시간 변경이 오래된 패치라도 현재까지 확인됐다면 현행 사실이다. 전체 문서의 마지막 패치나 위키 수정 날짜를 그 사실의 변경 패치로 복사하지 않는다. 초기 데이터에 마지막 변경을 추정해서 채우지 않는다.

수치 필드와 조건이 별개 사실이라도 연결 관계를 기록해야 한다. 버프의 획득 조건이 바뀌면 그 조건에 의존하는 답변도 무효화한다. 조건을 버리고 수치만 재사용하지 않는다.

## CI 운영 제안

기존 `.github/workflows/update-static-data.yml`은 매시 17분에 DDragon 버전과 CDragon 빌드·캐릭터 표식을 보고, 표식이 같아도 하루 한 번 무거운 데이터 갱신을 실행한다. 공식 글 수정과 위키 리비전은 지금 표식에 포함되지 않는다. `llm:fetch-gameplay`도 현재 워크플로의 자동 수집 단계가 아니다.

[Watch Game Knowledge](../../.github/workflows/watch-game-knowledge.yml)를 추가했다. 매일 UTC 00:37, 한국 시간 09:37에 실행하며, `Update Static Data`의 master 실행 성공 뒤와 수동 실행도 지원한다. 원격 저장소에 반영되기 전에는 예약 실행이 활성화되지 않는다. 이번에는 로컬에서 검증했으며 원격 Actions 실행은 하지 않았다.

2026-10-06 13:20 UTC 확인에서는 기존 매시 예약의 실제 실행이 최근 24시간 3회였고 모두 성공했다. [GitHub는 예약 실행의 지연·누락 가능성을 문서화한다](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule). 정시·매시 실행 보장으로 표현하지 않는다. 원격 반영 뒤의 실행·배포·실제 챗봇 검증은 `validation.json`에 별도로 기록한다.

구현된 검사는 1차의 정규 위키 문서 38개와 제거 문서 2개, 최근 공식 노트 6개와 고정된 14.1·26.1, CDragon 몬스터 파일 7개를 본다. 현재 총 55출처다. 초기 비교 기준은 로컬에서 전부 수집해 Git에 남겼다. 원문과 보고서는 Actions artifact로 14일 보관하며 기준 해시는 Git에서 유지한다. 이 대상이 모든 기존 챔피언·아이템 노트의 외부 출처를 감시하는 것은 아니다. 챔피언 스킬 변경은 기존 전용 CI도 계속 맡는다.

`npm run llm:watch-game-knowledge`는 기준을 변경하지 않고 검사한다. `npm run llm:watch-game-knowledge -- --initialize`는 기준을 다시 만든다. 기준 갱신은 원문 비교 기준의 변경이며 사실 승인과는 다르다. 보고서는 `research/.cache/game-knowledge/watch/`에 남는다. 수집 실패가 있으면 작업은 실패하고 기존 기준을 보존한다. 검사 결과만으로 노트 본문·승인·확인 패치를 갱신하지 않는다.

아래는 구현된 감지를 사실 작성·승인으로 이어갈 운영 절차다. 현재는 변경 보고서와 원문 준비까지 구현했고, 사실별 종속성 분석·작성·검수 대기·승인 필터는 아직 연결하지 않았다.

1. 위키 정규 제목의 리비전·원문과 gameplay 절의 펼쳐진 HTML을 비교한다. 템플릿·모듈 변경은 본문 리비전을 바꾸지 않고 수치를 바꿀 수 있기 때문이다. 원문·펼친 결과·의존 템플릿을 같이 보관한다.
2. 공식 사이트맵으로 새 글을 발견하고, 최근 글과 아직 열린 핫픽스 확인 범위의 본문을 다시 받는다. `lastmod`만으로 변경이 없다고 판단하지 않는다.
3. CDragon은 패치 경로와 빌드 ID를 고정하고 관련 몬스터·맵 파일만 비교한다. 동일 패치의 파일 변경도 해시에 반영한다.
4. 변한 절과 종속 사실만 검수 대기 목록·원문 diff·다음 작성 입력으로 만든다. 순수한 수치 변화인지 문장 수정인지 정규식만으로 승인하지 않는다. 로컬에서 구조화·검수하고 원문·후보 해시로 승인한다.
5. 변경된 사실과 종속 답변은 현행 답변에서 제외한다. 변경 없는 사실은 근거 해시가 맞을 때 재사용한다. 수집 실패는 빈 데이터로 덮어쓰지 않고 불완전 검사로 보고한다. 마지막 확인 패치를 임의로 올리지 않는다.
6. 실제 답변 경로의 회귀 검사와 스키마 검증을 거친 승인 사실만 번들로 내보낸다. 현재 새 예약 검사는 Actions 요약과 artifact만 기록하며 이슈·메시지를 발행하지 않는다.

첫 기준은 로컬에서 만든다. 이후 CI에는 LLM 인증 없이 감지·후보 입력 준비·검증만 맡기고, 변경 항목의 작성과 사실 승인은 기존 챔피언 메커니즘과 같은 로컬 절차를 쓴다. 챔피언의 P/Q/W/E/R 스키마 자체를 일반 규칙에 억지로 적용하지는 않는다.

원문 기준과 승인 원장은 Git 또는 영속 저장소에 둔다. 14일짜리 Actions artifact는 검토 편의를 위한 보고서이며 유일한 기준 자료로 삼지 않는다. 검수 대기 상태와 답변에서 빠진 사실 수도 작업 요약에 표시한다.

## LLM과 실제 답변 연결

`src/lib/advisor/gameMeta.ts`가 지금 주제 전체를 빠르게 답하므로 새 JSON을 검색 문서로만 추가하면 바론 질문이 기존 짧은 답변에서 끝날 수 있다. 먼저 질문의 속성을 고르고 승인된 구조화 사실을 조회하는 경로를 만들고, 기존 메타의 같은 사실을 그 결과로 생성하거나 연결한다.

승인 사실을 검색 문서와 LLM 문맥으로도 변환한다. 검색 단위는 사실 또는 조건을 보존하는 작은 묶음이다. 개별 수치 질문은 구조화 필드로 직접 답하고, 설명 질문은 관련 사실·조건·예외·출처를 함께 전달한다. 충돌·제거·미검수 기록은 활성 검색 문서로 내보내지 않는다.

한국어 검수 내용을 바꾸면 그 사실에 의존하는 번역도 무효화하도록 연결해야 한다. 번역은 원문 의미와 수치·조건이 같은지 검사한 뒤 해당 `factHash`에 연결한다. 서로 다른 모드의 규칙을 한 답변에 섞지 않는 질문 검사도 필요하다. 기존 번역 전체를 이번 백필로 재검수했다고 선언하지 않는다.

## 이번 주소 수정과 검증

챔피언 분류·아이템 분류·챔피언 팁·이동기·일반 게임 규칙 수집기의 Fandom API와 새로 기록하는 출처를 현행 `/en-us/` 위키로 바꿨다. 게임 규칙의 미니언 제목을 `Minion`으로 바꾸고, 챔피언 팁 조회는 리다이렉트를 따른다. 군중 제어 답변의 출처 링크도 바꿨다. 과거에 수집한 JSON의 출처를 새로 검수한 것처럼 일괄 바꾸지는 않았다.

격리된 실제 수집에서 챔피언 분류 3개, 아이템 분류 325개, 챔피언 팁 1개, 이동기 1개, 일반 게임 규칙 6문서·117항목을 얻었다. 테스트 데이터의 챔피언은 3개이고 팁·이동기 수집은 limit 1이다. 전체 챔피언 전수 검수 결과는 아니다. 아이템 대응 누락 경고 40개가 있어 주소 수정만으로 대응률이 완전하다고 보지 않는다.

수집기의 기존 게임 규칙 파서는 불릿 위주로 읽고 표·복잡한 템플릿을 보존하지 못한다. 새 일반 지식 수집에는 그대로 재사용하지 않는다. [MediaWiki parse API](https://www.mediawiki.org/wiki/API:Parsing_wikitext)로 raw와 펼친 내용을 받아 숫자·표·조건을 유지해야 한다.

주소 수정의 실제 위키 수집, 버전·제거 안내와 변경 감지의 단위 시험, 전체 단위 시험, 데이터 시험, 앱·스크립트 TypeScript 검사와 변경 파일 ESLint를 수행했다. 다음 구현은 수집한 38문서를 사실 단위로 작성·검수하고, 신규 수치 질문과 승인 필터에 연결하는 것이다.
