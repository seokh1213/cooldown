# 슬롯을 생략한 패시브 질문 점검

## 사용자 보고와 완료 조건

| 질문 | 필요한 결과 | 확인 |
| --- | --- | --- |
| 아크샨은 평타 한대 치면 어떻게되지? | 두 번째 공격과 그 공격을 취소했을 때의 이동 속도 증가를 P 카드·대화 본문에서 설명 | unit/data, Chrome, e2e |
| 같은 질문에 `(내가 할 때)` 추가 | 운용 노트·관점 선택으로 넘어가지 않고 같은 사실 조회 | unit/data |
| 아크샨 평타 세대 맞추면? | 세 번째 적중의 추가 마법 피해와 챔피언 대상 보호막 조건 | unit/data, e2e |
| 파이크는 체력 템 가면 어떻게되지? | 추가 최대 체력 → 추가 공격력, 체력 14당 공격력 1 | unit/data, Chrome, e2e |
| 파이크 체력템을가도되나? 패시브나 이런곳에 뭐 있엇던것같은데 | 회복 계수 800% 대신 전환 조건·비율을 첫 답으로 표시 | unit/data |
| 아크샨 → 파이크 → 이름 없는 후속 질문 | 주제를 바꾸고 현재 챔피언의 패시브 유지 | unit/data, e2e |
| 대화를 저장·복원한 뒤 평타 질문 | 패시브 주인과 조건 유지 | unit/data, e2e |
| 기본 체력·이동 속도, 명시한 Q, 룬·아이템 판정, 구매 추천 | 새 패시브 조회가 기존 요청을 가로채지 않음 | unit/data |

## 원인

두 효과 모두 기존 카드 본문·요약에 있었다. 슬롯을 말하지 않은 평타·구매 효과 질문을 챔피언 전체 운용이나 아이템 추천으로 분류했다. 파이크 질문은 그 결과가 요청 검사에서 거절되기도 했다. 따라서 새 지식을 생성하거나 모델을 교체하는 대신, 해당 이벤트와 본문의 관계를 연결했다.

## 변경

- 공통 `passiveMechanicPlan`을 직접 계획기와 앱 대화 계획기에서 공유한다.
- 평타의 횟수·취소·효과를 기존 패시브 문장에 연결하고, 선행 공격과 대상 조건을 함께 보존한다.
- 구매한 능력치와 패시브의 전환·증가 관계를 기존 요약·본문에서 읽는다. 챔피언 이름이나 전환 숫자를 답변 코드에 하드코딩하지 않는다.
- 결과가 확정된 패시브 질문은 기본 스탯 조회와 구분한다.
- 질문과 관련 없는 구조 필드(회복 계수·피해 유형·CC 없음)는 간단한 판정 카드에서 제외하고 전문은 접어 둔다.
- 추천·교전 질문, 룬·아이템의 개별 효과 질문, 다른 주제로 넘어간 뒤의 낡은 챔피언 기억은 이 경로로 가져오지 않는다.

## 근거

- [라이엇 아크샨 스킬 소개](https://www.leagueoflegends.com/en-au/event/akshan-abilities-rundown/): 두 번째 공격을 취소했을 때 이동 속도 증가.
- [라이엇 12.3 패치](https://www.leagueoflegends.com/en-us/news/game-updates/patch-12-3-notes/): 취소 이동 속도 수치 변경.
- [PC 파이크 패시브 판정](https://wiki.leagueoflegends.com/en-us/Template:Data_Pyke/Gift_of_the_Drowned_Ones): 레벨 성장 외 추가 체력은 공격력으로 전환, 체력 14당 공격력 1.
- 앱의 v26.19 한국어·영어·중국어 패시브 카드 본문·요약을 실제 답변의 근거로 사용한다.

## 검증

- 최초 아크샨 관련 17건: 수정 전 3/17, 수정 후 17/17.
- 최종 아크샨·파이크 관련 40건 통과. 세트·마스터 이·루시안·블라디미르, 영어·중국어, 주제 변경, 저장 복원, 잘못된 패시브 연결 방지 포함.
- 전체 unit/data 1,994건, type-check, lint, Pages 빌드 통과.
- 실제 Chrome에서 원래 아크샨·파이크 질문을 입력하고 카드·답문·아이콘을 확인했다.
- 모바일 390px·데스크톱 1280px e2e 2건 통과. 원래 질문, 저장 복원, 세 번째 적중, 파이크 전환, 이름 생략 후속 질문을 검증했다.

## 범위

이 조회는 패시브에 해당 근거가 있는 경우에 적용한다. 아이템의 모든 상호작용, 피해량 계산, 전투 추천까지 해석하는 기능은 아니다. 추가 효과는 확인된 자료를 확장한 뒤 같은 조회 흐름으로 연결할 수 있다.
