# 학습된 요청 범위 판정

## 바뀐 경로

앱의 대화 진입점에서 요청 범위를 한 번 분류해 `ResolvedQuestion.requestIntent`로 전달한다. 소개·전체 능력치·스킬 소개는 이전 항목을 상속하기 전에 답을 만든다. 콤보·상대법·노트 주제도 이 값을 먼저 사용한다. 수치와 게임 지식은 생성하지 않고 검증된 카드에서 읽는다.

분류기는 글자 1–3그램과 단어 특징을 사용하는 다항 로지스틱 회귀다. 언어별 단어 목록을 실행 중에 매칭해 범위를 바꾸지 않는다. 챔피언 이름은 질문에 실제로 적힌 이름/별명을 마스킹한다. 이름 개수에 따른 편향을 막기 위해 같은 학습 문장을 0·1·2개 이름 상태로 균형 학습한다.

범위: 소개, 전체 스탯, 지정 스탯, 스킬 소개, 콤보, 상대법, 운용 조언, 스킬 하나, 잡담, 도우미 소개, 기타. 별도 모델이 노트 주제 여덟 가지를 판정한다. 0.8B가 없거나 사용자가 다운로드를 거절해도 실행된다. 가중치 합계 622,592바이트.

## 한계와 남은 규칙

이번 변경은 전체 규칙 삭제가 아니다. 확률 0.6 이상·차이 0.2 이상일 때 새 분류를 적용하고, 모호한 질문이나 모델 파일 로드 실패는 기존 경로에 맡긴다. 기존 경로의 규칙, 챔피언·항목·레벨 추출, 대상 추가/제외, 상성의 관점·조건 처리, 복합 질문 분리는 남아 있다. 범위가 확실한 질문에 한해 단어 규칙이 학습 결과를 덮어쓰지 못하도록 했다.

개발 문장 73개는 첫 평가 후 개선 과정에 사용했다. 시험 문장 66개는 학습 파일과 중복을 검사하며, 오류가 발견되면 정확히 같은 문장을 학습에 복사하지 않고 관련 표현을 보강했다. 이 결과는 수작업 문장 모음의 범위에서 유효하며 실제 사용자 전체의 정확도를 뜻하지 않는다. `app-report.json`에는 분류의 기각 여부, 전후 대화 12턴의 실제 답이 함께 남는다.

스킬 자료 재사용 시험에서 “오공 R 스킬정보 알려줘”가 전체 스킬 소개로 잘못 분류됐다. 지정 슬롯과 스킬 정보를 함께 묻는 학습 예시 40개를 추가했다. 실행 코드의 단어 규칙은 추가하지 않았다. 소개 다음에 슬롯을 바꿔 묻는 별도 한국어·영어·중국어 대화 14턴은 모두 지정한 스킬에 답하고 기억을 갱신한다. 기존 고정 시험 66개의 정답은 61개에서 64개로 늘었고, 채택한 판단 53개는 모두 정답이었다. 기존 대화 평가도 12/12를 유지했다.

## 재현과 갱신

```sh
uv run --python 3.13 --with numpy==2.5.3 --with scikit-learn==1.9.1 python scripts/llm/offline-classifier/train-request.py
npx tsx scripts/llm/offline-classifier/evaluate-request.ts
node --import tsx --test tests/data/advisor-request-intent.test.ts tests/unit/request-intent.test.ts
```

예시의 정답은 `scripts/llm/offline-classifier/request-training.json`에 둔다. 개발·시험 문장은 별도 파일이다. 새 표현을 추가할 때 정규식 대신 정답 예시를 추가하고 모델을 다시 학습한다. CI의 단위 시험은 학습 파일·학습 코드·주제 생성기의 해시와 가중치 해시를 검사해, 예시만 바뀌고 모델이 낡은 상태로 배포되는 것을 막는다.

초기 배포는 작은 문자 로지스틱 판정을 먼저 적용했고, 임베딩이나 kNN과 비교해서 선택한 것은 아니다. 이후 [다국어 판정기 비교](comparison/README.md)에서 문자 TF-IDF·SVM·kNN과 두 임베딩 모델을 포함한 10가지 조합을 평가했다. 의미 임베딩 + 로지스틱은 추가 질문에서 좋았지만, 실제 대화에는 기존 경로와의 충돌이 남았다. 임베딩 후보는 아직 운영에 적용하지 않았으며, LoRA·생성 LLM 판정은 비교하지 않았다.
