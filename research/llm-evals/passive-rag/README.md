# 아크샨·파이크 패시브 RAG 생성 실험

2026-10-03. 현행 코드 기준 `afd68b6ac`, 패치 26.19. 운영 앱의 생성 기능은 변경하지 않았다.

## 질문과 완료 조건

원래 질문, 띄어쓰기 변형, 취소, 보호막, 기본/추가 체력, 잘못된 숫자 유도, 계산, 주제 변경, 이름 없는 후속 질문을 준비했다. 총 30턴은 아크샨·파이크 24턴, 다른 챔피언으로 전이하는 4턴, 없는 효과를 묻는 2턴이다. 독립 맹검이나 무작위 대표 표본이 아닌 작성자 선정 탐색 세트다.

## 비교 방법

1. **현행:** 앱의 `answerDialogue`, 기존 자료와 오프라인 판정기. 생성은 없다. q4 모델 판정 경로 전체를 30턴 새로 측정한 결과는 아니다.
2. **한국어 전체 P 주입:** 검색 오류를 제외하고 정답 패시브 본문·요약을 바로 제공한다.
3. **한국어 RAG:** 코드로 대화의 챔피언만 확인하고, 그 챔피언의 스킬 5개 전체에서 의미 검색한 상위 2개를 제공한다. 기존 답변·문형별 정답 선택기·기대 조건을 생성 프롬프트에 넣지 않았다.
4. **영어 전체 P 주입:** 짧은 영어 지시문과 기존 영어 패시브 원문. 번역 모순과 긴 지시가 원인일 수 있는지 대조했다.
5. **영어 문장 RAG:** 기존 영어 스킬 본문을 두 문장씩 나누고 상위 2개를 검색했다. 지시문 언어·근거 언어·단위를 함께 바꾼 탐색 방법이므로 결과를 아톰화 하나의 효과로 해석하지 않는다.
6. **짧은 한국어 근거 대조군:** 아크샨은 요약을 뺀 P 본문, 파이크는 요약의 추가 체력 전환 문장과 본문의 전환 비율만 제공했다. 챔피언별로 모든 질문에 같은 근거를 주었으며 검색 성능 평가가 아니다. 8턴에 대해 일반 chat과 공식 앱 토크나이저로 만든 raw 프롬프트도 비교했다.

첫 선별은 Ollama Qwen3.5 0.8B Q8_0, 실제 앱 확인은 앱의 Qwen3.5 0.8B q4 WebGPU 워커를 사용했다. 생성에서는 기존 코드대로 LoRA 게이트가 꺼져 있다. 탐욕 복호화, thinking 끔, 최대 160토큰으로 측정했다. 원문 결과를 그대로 남겼고 실패를 코드 답변으로 대체해 성공으로 세지 않았다.

검색은 설치되어 있던 Snowflake Arctic Embed 2의 의미 벡터로 수행했다. 앱 q4 실험에는 그 검색 결과와 동일한 프롬프트를 넘겼다. **앱의 기존 검색 LoRA로 챔피언 스킬 검색까지 실행했다는 뜻은 아니다.** 이 별도 임베딩 모델을 웹 앱에 추가하는 결정도 하지 않았다.

## 결과

다음은 필요한 사실·조건·숫자를 모두 충족하고 새로운 사실을 만들지 않은 답의 수다. 단어 일치 검사가 아닌 원본 출력의 수동 판독이며 판정 기준·통과 ID는 [manual-review.json](manual-review.json)에 있다. 형식·반복·잘린 답과 자연스러움은 별도로 보았다. 검색을 포함한 아래 첫 표는 공식 질문 접두사 보정 전의 탐색 결과이며, 보정 후 확인은 이어지는 검색 감사 절에 기록했다.

위 시간은 각 백엔드의 이번 환경 측정치다. 임베딩은 일괄 처리했고 준비 시간은 pack에 따로 남겼다. 모델 다운로드·적재 시간과 화면의 타이핑 효과를 합친 전체 사용자 지연이 아니다. 서로 다른 장치·백엔드 속도의 보편적 비교도 아니다.

- 한국어 RAG는 정답 P를 29/30턴에서 1위로 찾았다. 원래 아크샨·파이크 질문도 모두 P가 1위였다. 검색에 성공해도 조건 보존은 실패했다.
- 영어 문장 검색은 상위 2개에 P가 있는 턴이 21/30으로 줄었다. 원래 파이크 질문에는 E·Q를 골랐다. 따라서 영어 문장 RAG의 실패에는 검색 실패도 포함된다.
- 정답 P를 직접 줘도 오답이 나와서 검색만 개선하면 된다는 설명을 배제했다.
- 짧은 근거 대조군에서 chat과 공식 raw 템플릿의 본문은 8/8 동일했다. Ollama 대화 템플릿만 잘못 적용되어 실패했다는 설명도 지지되지 않았다.
- q4는 한국어 RAG에서 질문 반복으로 1회, 영어 문장 RAG에서 2회 중단했다. 실제 원문에는 조건 반전·계수 혼동·근거 복사도 남았다. 내용이 맞은 취소 답변조차 제목과 같은 말을 반복하여 현행 답보다 자연스럽다는 이득이 없었다.
- 짧은 근거를 준 q4는 원래 파이크 질문에 `14당 1의 전환 비율을 적용하여 추가 공격력`으로 정확히 답했다. 그러나 같은 근거를 두고 기본 체력도 전환된다고 답하고, `800%로 전환됩니다`라고 반복했다. 아크샨 원래 질문은 취소 효과 대신 한 대의 피해가 50%라고 잘못 답했다. 이 네 번은 같은 근거로 원래 질문·기본 체력·잘못된 계수 유도를 함께 확인한 대조군이다.

### 공식 질문 형식으로 검색 재확인

초기 검색에는 Snowflake 모델 카드가 권하는 `query: ` 접두사가 빠졌다. 이를 확인한 뒤 문서에는 접두사를 붙이지 않고 질문에만 붙여 30턴의 검색을 다시 계산했다. 한국어는 P 상위 2개 적중 29/30을 유지했고 영어 문장은 18/30이었다. 보정한 근거로 원래 질문·반례 8턴을 두 방법에서 다시 생성한 결과는 한국어 1/8, 영어 문장 0/8이었다. [공식 사용법](https://huggingface.co/Snowflake/snowflake-arctic-embed-l-v2.0)의 질문 형식을 적용해도 조건 보존 문제가 남았다.

원래 아크샨·파이크 질문과 파이크 800% 질문의 한국어 생성 프롬프트는 보정 전후 **문자 단위로 동일**했다. 따라서 해당 앱 q4 원본은 보정한 검색에서 선택한 동일 근거의 생성 결과로도 읽을 수 있다. 같지 않은 영어 근거나 다른 질문의 q4 결과까지 보정 후 실측으로 부르지 않는다. 반복 실행 대신 프롬프트 동일 여부를 기록했다.

합계는 Ollama 152회와 실제 앱 q4 20회, 총 **172회 실제 생성**이다. 실험 준비·채점·브라우저 적재는 생성 횟수에 넣지 않았다.

## 남은 오류도 기록

현행 코드도 완벽하지 않다. `그럼 두 번째까지 다 치면?`, `미니언한테 세대면 보호막도 생겨?`, `아니 챔피언이면?`처럼 평타 표현을 생략한 이어 묻기, 체력 140을 공격력 10으로 계산하는 질문, 기본 체력 전환 여부 등은 누락되었다. 이번 실험에서 이를 해결했다고 주장하지 않는다. 단순히 생성을 켜면 이 누락이 고쳐진다는 증거도 없었다.

원문에도 정리가 필요하다.

- 한국어 아크샨 P 요약은 세 번째 적중을 **추가 물리 피해**, 본문은 **추가 마법 피해**로 적었다. 영어 요약은 피해 유형을 특정하지 않고 본문은 magic damage다. 생성기가 요약의 잘못된 유형을 따라간 사례가 있다.
- 한국어 파이크 P 요약은 **추가 최대 체력**, 본문에는 **최대 체력을 모두**라고 적었다. 현재 코드 답변은 요약의 추가 조건을 보존하지만, 본문을 자유 생성에 통째로 넣으면 기본 체력과 혼동할 수 있다.
- 짧고 명확한 근거만 준 뒤에도 `기본 체력까지 전환된다`, `800% 전환이다`, `체력 140은 공격력 140이다`라는 오답이 남았다. 자료 모순만으로 모든 생성 실패를 설명할 수 없다.

## 결정

이 두 질문은 RAG로 구성할 수 있지만, **현재 0.8B가 근거에서 안정적으로 한국어 답을 생성한다고 확인되지 않았다.** 생성 기본 활성화는 보류한다. 챔피언으로 검색 범위를 좁히고 근거를 찾는 흐름은 유지할 가치가 있다. 발동 조건·숫자·기본/추가 능력치가 확정된 답은 지금처럼 코드로 먼저 보존하는 편이 낫다.

다음 개선의 대상은 원문 모순 정리, 짧은 근거의 검색, 생략한 후속 질문·단순 계산이다. 자유 생성 검사를 단어 포함 여부로 승인하면 `800%입니다 (근거: 14당 1)` 같은 오답을 통과시킬 수 있으므로 그 방식은 적용하지 않는다.
