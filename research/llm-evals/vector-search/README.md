# 이름 없는 질문의 자료 찾기 — 벡터 검색 (2026-09-26, 싣지 않음)

챔피언·아이템 이름이 없는 질문("스마 충전 몇 초마다 차?", "how often does a new set of creeps spawn")은 룬·주문·게임 요소
규칙 70 · 게임 원리 9 · 게임 메타 21, 언어마다 100건에서 찾는다. 지금은 낱말로 찾는다(룬·주문 이름 → 게임 메타 낱말 →
게임 원리 낱말 → BM25 + 제목 거르기). 벡터로 찾으면 나은지 쟀다.

- 시험: 720문항(`queries.jsonl`, Claude 에이전트가 작성) — 언어마다 문서 100건 × {바꿔 말하기 1 · 이름 넣기 1} + 답 없는 질문 40.
- 잣대: **맞음** = 답이 있으면 정답 문서를 보였고 없으면 아무것도 안 보였다. **오답 노출** = 틀린 문서를 보였다(가장 해롭다).
  문턱은 절반(문서 id 로 가름)에서 고르고 나머지 절반에서 쟀다. [엄격] = 오답 노출이 지금 앱보다 늘지 않는 문턱.
- 판: 지금 앱(`corpus.ts current`), 0.8B(앱이 받는 Qwen3.5-0.8B q4 + kev 그래프의 `hidden`, 평균·마지막 토큰·요약 프롬프트,
  LoRA 0·1, `embed.py qwen`), 전용 임베딩 multilingual-e5-small(`embed.py e5`, 브라우저 판 q8 약 120MB), 섞은 판(지금 앱이
  못 찾으면 벡터). `score.py` 가 전부 낸다.

## 먼저 찾은 것: 지금 앱의 낱말 찾기 버그 둘 (고침)

| | 맞음 | 오답 노출 |
|---|---|---|
| 고치기 전 | 388/720 | 136건 |
| **고친 뒤** | **396/720** | **82건** |

- `findMechanics` 가 영문 낱말을 부분 문자열로 찾았다 — "da**mage**" 의 Mage, "**ad**ds" 의 AD, "m**id**" 의 id. 영어 질문이
  챔피언 분류 절로 갔다. 영문은 낱말 경계로 바꿨다.
- `hitsToAnswer` 의 제목 거르기가 영어 기능어("the")를 제목 낱말로 쳤다 — "Press **the** Attack", "Walk on **the** water".
  기능어를 빼고 영문은 낱말 경계·대소문자 무시로 바꿨다.

## 벡터 (test 355문항, 고친 뒤 기준)

| 판 | 정답 1위 · 3위 안 | 맞음 | 오답 노출 | 바꿔 말하기 | 이름 넣기 | 답 없음 |
|---|---|---|---|---|---|---|
| 지금 앱 | — | 0.541 | 0.121 | 0.09 | 0.88 | 0.85 |
| 0.8B 요약 프롬프트(가장 나은 0.8B 판) | 0.40 · 0.52 | 0.389 | 0.473 | 0.10 | 0.63 | 0.51 |
| [엄격] 지금 앱 + 0.8B | — | 0.544 | 0.121 | 0.09 | 0.89 | 0.85 |
| e5 | 0.57 · 0.66 | 0.566 | 0.366 | 0.35 | 0.76 | 0.64 |
| 지금 앱 + e5(중심 빼기) | — | 0.586 | 0.186 | 0.23 | 0.91 | 0.69 |
| **[엄격] 지금 앱 + e5(중심 빼기)** | — | **0.569** | 0.127 | 0.15 | 0.89 | 0.85 |

- **0.8B 은닉 상태는 검색 벡터로 못 쓴다.** 평균·마지막 토큰은 1위 0.10~0.16, 요약 프롬프트가 0.40. 섞어도 +0.003.
  문장 벡터로 배운 적 없는 모델이라 예상대로다.
- **e5 는 바꿔 말한 질문을 잡는다**(0.09 → 0.35). 그러나 맞는 문서와 틀린 문서의 유사도가 갈리지 않아(BM25 때와 같은 문제)
  오답 노출을 지금만큼 묶으면 얻는 것이 +2.8%p 에 그친다. 느슨하게 두면 +5.9%p 에 오답 노출이 2.5배.
- 지금 앱이 "자료 없음" 으로 답한 196문항 중 e5 상위 3건 안에 정답이 있는 것은 41%(0.8B 22%). "혹시 이것을 찾으셨나요?"
  후보로만 보이는 쓰임은 있으나 120MB 를 더 받게 할 만큼은 아니다.

결론: 벡터는 싣지 않는다. 낱말 찾기 버그 둘을 고친 것이 이번에 가장 큰 개선이다. 남은 오답 노출 82건 중 절반은
흔한 낱말이 규칙 이름인 경우("와드 없는 모드에서 킬로 트로피 모으는 룬" → 와드, "피 채워 주는 룬" → 회복)이고,
바꿔 말한 질문은 은어 사전(챔피언 별명 사전처럼, 예: 스마 → 강타)이 더 싸게 잡을 수 있다.

```
npx tsx scripts/llm/vector-search/corpus.ts dump
npx tsx scripts/llm/vector-search/corpus.ts current research/llm-evals/vector-search/queries.jsonl
uv run --python 3.13 --with sentence-transformers --with numpy python scripts/llm/vector-search/embed.py e5
uv run --python 3.13 --with onnxruntime --with tokenizers --with huggingface_hub --with numpy \
  python scripts/llm/vector-search/embed.py qwen ~/.cache/cooldown-kev/onnx-b3i/model_q4.onnx   # 로컬 CPU 약 15분
uv run --python 3.13 --with numpy python scripts/llm/vector-search/score.py
```

## 개선 둘: 물은 갈래로 좁히기 + 은어 사전 (싣음)

규칙은 dev 절반의 오답만 보고 고쳤고, 은어 사전은 시험 문제를 보지 않은 Claude 에이전트가 롤 지식으로 썼다
(`knowledge/search-aliases.json`, 문서 82건 · 은어 약 400). 사전에서 dev 오답과 기존 374문항(route-large, 대부분 챔피언
질문)을 가로챈 말만 뺐다 — 눈덩이·snowball(스노우볼 굴리기), backing(backing off), 节奏·治疗·终极·秘籍 같은 일상어,
프리징·다이브 같은 넓은 전략 용어(규칙 찾기가 챔피언 찾기보다 먼저라 상성 질문을 가로챈다).

| test 355문항 | 맞음 | 틀린 자료 | 바꿔 말하기 |
|---|---|---|---|
| 낱말 버그 둘 고친 뒤 | 192 | 43 | 13/150 |
| + 물은 갈래로 좁히기 | 192 | 35 | 13/150 |
| **+ 은어 사전 + 룬 질문은 게임 원리 절로 보내지 않기** | **212** | **31** | **29/150** |

전체 720문항: 처음 388 → 447, 틀린 자료 136 → 54. e5 벡터를 섞은 가장 나은 판(test 0.569 · 틀린 자료 0.127)보다
은어 사전 판(0.597 · 0.087)이 낫고 120MB 도 안 든다.

- 물은 갈래로 좁히기(`narrowToAsked`): 질문이 "룬"·"스펠" 이라고 밝혔으면 그 갈래 규칙만. "와드 없는 모드에서 … 룬" 이
  와드로, "피 채워주는 룬" 이 소환사 주문 회복으로 가던 것. 걸린 규칙이 게임 요소뿐이고 게임 메타가 잡히면 메타 먼저.
- 은어: 영문은 낱말 경계, 두 글자 이하 한글은 앞뒤가 한글이 아니거나 조사일 때만("플레이" 의 플 ≠ 점멸).
