# 파이크·아크샨 원래 질문과 후속 대화 검증

## 결론

구조화한 자료로 원래 질문의 조건을 읽고 수치 계산과 후속 질문까지 답할 수 있다. 단, 자료를 만드는 것만으로 대화가 좋아지지는 않았다. 연구용 검색 어댑터의 수치 정정·짧은 후속 질문·조건 부정·카드 조립도 함께 고쳐야 했다.

**앱의 배포 경로에는 아직 연결하지 않았다.** 아래 개선 결과는 실제 앱 대화 함수에 연구 어댑터를 결합한 로컬 실행 결과다. Ollama나 0.8B 생성은 호출하지 않았다. 승인된 JSON 및 원본 툴팁은 변경하지 않았다.

## 방법

- 답변을 보기 전에 18개 대화, 32턴의 질문·필수 조건·금지 조건을 고정했다. 질문 해시는 `2c09f0897619d2481c7568045be9184e81eb9c03fa6d1a9e11e23c83dfd523a8`이다.
- 현행 `answerDialogue`와 연구 `answerReviewed`를 서로 독립된 대화 상태로 실행했다.
- 매 턴 `dehydrateTurn → JSON 저장 → reviveTurn`으로 실제 앱의 대화 턴 저장·복원을 거쳤다. 연구 어댑터의 주제 기억은 별도 `retrievalMemory`로 넘겼다. 브라우저 새로고침 뒤 이 주제 기억을 복구하는 앱 연결은 아직 없다.
- 865개 승인 슬롯의 원문·후보 해시를 확인한 인덱스를 사용했다.
- 판정기 없이 실행하고, 같은 질문을 로컬 오프라인 판정기를 켠 상태에서도 실행했다. 생성 모델과 외부 검색 없이 테스트했다.
- 답변 문장 전체를 직접 읽었다. 키워드가 우연히 맞는 답은 별도 의미 검수에서 제외했다. 수정 후에는 근거 슬롯과 카드의 챔피언/슬롯이 일치하고 저장한 마지막 답변이 실제 답변과 같은지도 검사했다.

## 결과

| 기준 | 현행 앱 | 구조 자료 사용, 수정 전 | 수정 후 연구 경로 |
|---|---:|---:|---:|
| 고정 키워드 기준 | 11/32 | 22/32 | 32/32 |
| 전체 문장을 읽은 의미 검수 | 9/32 | 21/32 | 32/32 |

오프라인 판정기 경로도 수정 후 32/32다. 연구 답변으로 교체한 29턴은 모두 질문에 해당하는 스킬 카드와 일치한다. 아이템 질문으로 주제를 바꾼 뒤 모호하게 이어 묻는 경우 등 3턴은 기존 경로를 사용했다.

키워드 기준의 오탐은 따로 보존했다. 현행 앱은 “미니언 세 대에 보호막?”에 미니언 규칙 목록을 답했는데, 그 목록에 검사 단어가 있어서 통과했다. 또 보호막 설명에 함께 나온 3회 적중 피해를 물리 피해라고 적었지만 승인된 본문은 마법 피해다. 원래 기준과 원시 결과를 바꾸지 않고 [의미 검수 기록](pyke-akshan.semantic-review.json)에 두 건을 기록했다.

이 숫자는 이 두 챔피언에 대해 준비한 질문의 성적이다. 모든 챔피언이나 자유로운 대화의 정확도를 뜻하지 않는다.

## 원래 질문과 실제 확인 내용

| 질문 | 확인한 답변 내용 |
|---|---|
| 파이크는 체력 템 가면 어떻게되지? | 추가 최대 체력 증가를 추가 공격력으로 전환, 14:1 비율 |
| 체력 140이면? → 280은? | 추가 공격력 10 → 20으로 갱신 |
| 체력 140 말고 280이면? | 정정한 280을 사용해 20으로 계산 |
| 추가 체력 0 / 150 / 14.5 | 추가 공격력 0 / 10.714 / 1.036 |
| 기본·성장 체력도 전환돼? | 추가 체력 전환 범위에 넣지 않음 |
| 체력도 공격력도 늘어? | 추가 체력 증가를 전환이 대체함 |
| 아크샨은 평타 한대 치면 어떻게되지? | 추가 공격이 이어지며, 추가 공격을 취소하면 이동 속도를 얻음 |
| 두 발을 다 쏘면 이속도 얻어? | 추가 공격 취소 조건에 해당하지 않음 |
| 첫 평타를 발사 전에 취소하면? | 추가 공격 취소와 조건을 구분 |
| 미니언 세 대? → 아니 챔피언 세 대면? | 대상 조건을 수정하여 보호막 규칙을 조회 |
| 쿨 남았으면? / 쿨이 안 남았으면? | 재사용 대기 중 / 사용 가능 조건을 구분 |
| 한 대만 쳐도 보호막? | 3회 적중·챔피언·보호막 사용 가능 조건을 제시 |
| 파이크 → 아크샨 → 그럼 두 발 모두? | 체력 전환 답을 섞지 않고 아크샨의 공격 조건을 유지 |
| 아크샨 → 도란검 가격 → 그럼 280짜리? | 이전 패시브 계산을 이어 붙이지 않고 현행 경로로 반환 |

원래 두 질문 자체는 이번 수정 전 현행 코드도 답하고 있었다. 이번 구조화의 추가 이득은 전환 계산, 대상·취소·쿨타임 조건 보존, 생략된 후속 질문에 있다.

## 고친 부분

1. “280은?”, “쿨 남았으면?” 같은 제한된 후속 문형에서 이전 주제를 이어받는다. 다른 챔피언·아이템 질문으로 전환되면 끊는다.
2. “140 말고 280”의 정정한 수치를 사용하고 0도 계산한다. 복수 수치나 음수는 추정 계산하지 않는다.
3. “쿨이 안 남았다”와 “쿨이 안 돌았다”, 첫 공격 취소와 추가 공격 취소를 구분한다. 조건을 충족하지 않는 답 뒤에 발동 효과를 붙이지 않는다.
4. “두 번째 공격 취소하면 뭐가 좋아?”를 아이템 추천으로 버리지 않고 공격 결과로 읽는다. “미니언 세 대”도 명시된 챔피언 패시브 근거를 우선 조회한다.
5. 글만 교체하던 연구 어댑터에서 근거 스킬 카드와 마지막 답변 기억도 함께 만든다. 기존 경로의 능력치·미니언 카드나 안내가 남지 않게 했다.

## 검증과 남은 범위

- 관련 단위 시험 **48/48**, 스크립트 타입 검사 및 수정 파일 ESLint 통과.
- 기존 고정 51턴은 **50/51** 유지, 퇴보 0, 기존 승인 성공 사례 손실 0. 오로라 질문 1건의 기존 실패는 그대로다.
- 제공된 툴팁과 승인 규칙에 대한 검증이다. 별도의 게임 엔진 실행이나 실제 게임 판정 검증은 아니다.
- 임의의 여러 수치를 합산하거나 중간 레벨의 미확정 공식을 계산하지 않는다. 기존 중첩 수처럼 주어지지 않은 상태도 만들어내지 않는다.
- 연구 답변에는 일부 영어 수식 문구와 조건 헤더가 남아 있다. 사실 조회는 검증했지만 자연스러운 생성 문장이나 화면의 시각적 품질은 이 시험 범위에 포함하지 않았다.
- 앱 연결·브라우저 검증·배포는 이번 작업에서 실행하지 않았다.
