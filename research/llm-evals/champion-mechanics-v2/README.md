# 승인된 메커니즘 JSON 답변 비교

## 현재 상태: 실제 앱에 연결

2026-10-04 승인된 865개 스킬 규칙을 앱 자료와 실제 대화 계획기에 연결했다. 이전 실험 결과는 아래에 그대로 보존한다. 현재 흐름·비교 결과·브라우저 검증·제한은 [앱 통합 보고서](integration-review.md)를 참고한다.

## 새 표현에 대한 후속 검증

원래 질문을 보며 수정한 파이크·아크샨 32/32 결과 뒤, 답변 코드를 바꾸지 않고 새 59턴을 시험했다. 경로 보존 검사 6턴을 제외한 내용 질문의 완전 답변은 **현행 9/53 → 연구 20/53**, 개선 12턴·퇴보 1턴이다. 다른 챔피언은 2/12 → 5/12였다. “두 번째 안 쏘면”을 반대로 읽고 숫자 쉼표·개수를 틀리게 적용하는 문제가 있어 서비스 적용이 충분히 검증된 상태는 아니다. [새 표현 검증 보고서](variations-v1-review.md)와 [전체 의미 검수](variations-v1.semantic-review.json)를 함께 확인한다. 아래 고정 51턴의 결과는 그 질문셋에 대한 역사적 측정이며 새 표현의 결과를 대체하지 않는다.

## 결과

2026-10-04, **865개 스킬 전수 승인 후** 고정된 41개 대화·51턴을 다시 비교했다. 평가 기준은 구현 전에 [questions.json](questions.json)에 고정했고 변경하지 않았다. 별도로 새 승인 스킬용 [16개 대화·18턴](full-approval-questions.json)을 답변 확인 전에 고정했다. 답변에 필요한 내용이 있는지, 금지한 잘못된 내용이 없는지, 보호 대상 답변이 현행과 같은지 검사한다.

| 실행 경로 | 현행 조건 충족 | 승인 규칙 검색 조건 충족 | 개선 | 퇴보 |
|---|---:|---:|---:|---:|
| 모델 판정기 없이 기존 어휘 경로 | 26/51 | 50/51 | 24턴 | 0턴 |
| 기존 오프라인 판정기 사용 | 26/51 | 50/51 | 24턴 | 0턴 |
| 추가 신규 질문 / 어휘 경로 | 2/18 | 7/18 | 5턴 | 0턴 |

검색 대상은 원문·후보·계약 해시가 현재 자료와 맞는 승인 스킬 865개다. 기존 51턴 중 33턴에서 승인 규칙을 사용하고 18턴은 현행 답변을 유지했다. 추가 18턴에서는 8턴을 승인 규칙으로 답했다. [전체 승인 비교](full-comparison.json), [오프라인 판정기 비교](full-offline-comparison.json), [추가 질문 비교](full-approval-additional-comparison.json)에 실제 답변과 실패 조건이 있다.

전수 승인 이전의 91개 한정 실험은 50/51이었다. 당시 34턴을 규칙으로 답하고 17턴을 현행으로 유지한 [이전 결과](comparison.json)는 역사 자료로 보존했다.

이 수치는 이번 질문셋의 조건 충족률이다. 승인된 스킬의 조건·계산·후속 질문을 중심으로 만든 질문셋이므로 전체 챗봇 정확도나 일반 사용자 만족도를 뜻하지 않는다. 자연스러운 문장과 카드 UI를 평가한 점수도 아니다.

## 개선 사례

| 질문 | 현행 | 승인 규칙 검색 |
|---|---|---|
| 파이크 체력 140짜리 템이면 공격력 얼마나 올라? → 그럼 280짜리는? | 필요한 계산 누락 | 추가 공격력 10 → 20. 이전 전환 주제 유지 |
| 파이크 기본·성장 체력도 전환돼? | 전환 적용 범위 누락 | 추가 체력 전환에 포함되지 않음을 명시 |
| 아크샨 평타 두 대 다 치면 이속도 올라? | 후속타 취소 조건 구분 부족 | 추가 공격을 발사하면 취소 조건에 해당하지 않음을 명시 |
| 아크샨 미니언 세 대면 보호막? → 아니 챔피언이면? → 쿨 남아 있으면? | 대상·쿨 조건과 후속 질문 처리 누락 | 챔피언 대상, 3회 적중, 보호막 사용 가능 조건 유지 |
| 모데카이저 궁으로 능력치를 빼앗고 상대를 처치하면? | 주인과 유지 기간 등 필요한 내용 누락 | 상대 능력치 감소·시전자 증가, 처치 후 상대 부활까지 유지하는 규칙 조회 |

파이크 체력템 전환과 아크샨 평타 한 대 질문 자체는 현재 앱도 이번 기준을 충족했다. 새 자료의 이점은 수치 계산, 반대 조건, 대상 변경, 생략된 후속 질문에서 더 뚜렷했다.

기존 51턴의 남은 실패는 오로라 패시브 질문이다. 전수 승인 후 검색 수정본은 이 질문에서 기존 답변으로 돌아가며 챔피언 대상 조건과 정령 설명을 빠뜨린다. 이전 91개 실험에서는 “정령” 대신 “영혼”을 써 실패했다. 어느 실행에서도 점수를 올리려고 기준을 수정하지 않았다.

추가 18턴의 실패 11턴은 이즈리얼 W의 표식/마나 환급, 질리언 R의 부활 단계, 카서스 E의 반복 효과, 생략된 후속 질문 등을 충분히 답하지 못한 경우다. 스탯·비용·쿨타임 조회로 잘못 넘어가거나 짧은 동작 표현을 검색하지 못하는 문제가 있다. **자료 전수 검수와 폭넓은 질문 대응은 서로 다른 결과다.** 새 자료가 검색기와 질문 해석기를 자동으로 개선하지는 않았다.

## 실험 과정과 경로

첫 비교는 35/51, 개선 12턴·퇴보 3턴이었다. 파이크 질문 다음에 아이템 가격이나 추천으로 주제를 바꿨는데도 이전 패시브를 다시 답하는 문제였다. 아이템·상성·규칙 주제로 전환했을 때 기존 답변 경로를 유지하도록 수정한 뒤 50/51, 퇴보 0턴을 확인했다. [첫 비교](initial-comparison.json)와 [최종 비교](comparison.json), [오프라인 판정기 비교](offline-comparison.json)를 함께 보존한다.

전체 승인 직후는 49/51, 퇴보 1턴이었다. 카이사 평타 세 대 질문에서 챔피언 이름의 문자 겹침이 엉뚱한 플라즈마 소모/아군 조건을 선택했다. 이미 판독한 챔피언 언급을 규칙 검색 점수에서 제외하는 수정과 회귀 시험을 추가했다. 질문 기준은 그대로 두고 50/51, 퇴보 0턴을 재확인했다. [수정 전 51턴](full-comparison.before-search-fix.json), [수정 전 추가 18턴](full-approval-additional-comparison.before-search-fix.json)도 보존했다.

실제 앱의 `answerDialogue`를 기준선으로 실행하고, 매 턴 앱의 `dehydrateTurn`·`reviveTurn`으로 대화를 저장·복원했다. 브라우저가 요청하는 자료는 같은 `public/data` 파일에서 제공했다. 새로운 생성 모델이나 0.8B 문장 생성은 사용하지 않았다.

실험 경로는 챔피언·스킬·주제를 확인한 뒤 **조건·효과·원문 인용을 묶은 규칙 전체**를 검색한다. 효과 문장만 떼어 검색하지 않는다. 파이크 같은 명확한 단순 비율은 출처의 숫자를 코드로 계산한다. 모든 텍스트 조건을 실행 가능한 게임 규칙으로 해석하지 않는다.

여러 챔피언, 상성·추천, 수은·정화 같은 숨은 상호작용, 한국어 외 질문, 수치 조회, 여러 변신 형태, 표시 전용 슬롯, 미승인·오래된 근거는 기존 답변 경로를 유지한다. 아펠리오스 E, 제이스 형태, CC 해제, 영어 질문, 챔피언·아이템·스탯 주제 전환도 질문셋에 포함했다.

**앱 런타임에는 아직 연결하지 않았다.** 이 결과는 연구용 비교 경로에서 확인했다. 서비스 적용 시에는 승인 자료 배포, 기존 카드와 본문 일치, 조건 설명의 문장 정리와 UI 확인이 추가로 필요하다.

## 재실행과 CI

```sh
npm run llm:mechanics-eval -- research/llm-evals/champion-mechanics-v2/full-comparison.json --check
npm run llm:mechanics-eval -- research/llm-evals/champion-mechanics-v2/full-offline-comparison.json --judge=offline --check
```

[quality-reference.json](quality-reference.json)은 이번에 성공한 승인 규칙 답변 33턴을 원문·후보 해시와 함께 보존한다. CI는 현행 대비 퇴보뿐 아니라 이 새로운 성공 기준의 퇴보도 잡는다. 원문이 바뀐 사례에는 옛 기준을 강제하지 않으며, 질문 기준을 바꾸면 별도 검토를 요구한다. CI는 모델 호출 없이 첫 번째 경로를 실행한다.

추가 18턴은 보완 평가로 보존하며 현재 CI 성공 기준에 합치지 않았다. 갱신 과정은 [유지 관리 문서](../../champion-mechanics/MAINTENANCE.md)를 따른다. 데이터의 검수 승인은 전부 끝났다. 앱 적용 전에는 신규 질문의 검색·질문 해석과 기존 카드/본문의 일치를 다듬어야 한다.
