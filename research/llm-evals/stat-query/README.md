# 능력치 질문을 구조화된 조회로 변환

## 원인과 변경

`체력회복량`은 체력으로 인식됐고, `아니아니 회복량`은 오프라인 판정기를 거치면 오공의 회복 효과 유무로 답했다. 판정기 없이도 첫 오류가 재현됐으므로 모델만의 문제는 아니다. 조회 항목을 바꿔도 카드의 중복 판정 키가 같았다.

조회 계약을 추가했다. 명확한 능력치 조회는 모델·검색보다 먼저 처리하고 항목, 대상, 레벨을 독립적으로 갱신한다.

```json
{"kind":"championStat","champions":["MonkeyKing","DrMundo"],"field":"healthRegen","level":1}
```

| 확인 항목 | 결과 |
| --- | --- |
| 체력 → 체력회복량 → 회복량 정정 | 두 대상 유지, 문도 7 / 오공 3.5, 5초당 기본 재생 |
| 체력·재생·방어력·마저·공격력·공속·이속 | 동일 계약, 항목만 변경 가능 |
| 레벨만 변경, 대상 한 명으로 축소 | 나머지 조회 조건 유지 |
| 영어·중국어 | 두 대상과 11레벨 유지하며 재생 조회로 전환 |
| 스킬 회복·아이템·마나·상대법·관통 규칙 | 기본 재생 조회로 강제 변환하지 않음 |
| 저장 후 복원·이전 버전 비교 카드 | 조회 조건 복원 |
| 새 챔피언 소개·새 비교 쌍·10명 비교 | 옛 대상 혼입 방지, 인원 제한 없음 |
| 자료에 없는 레벨 | 1레벨로 대체하지 않고 범위 안내 |
| 카드 중복 판정 | 항목·레벨이 다르면 별도 자료 |

집중 시험 21건, 전체 1,590건 통과. 타입, 린트, 빌드 통과. Chrome에서 보고된 3턴과 후속 스탯 변경을 확인했다. 단어 규칙이 처리하는 명확한 조회는 판정기 호출을 필요로 하지 않는다. `model` 설정 시험은 판정기를 실제 실행한 정확도 측정이 아니라, 그 설정에서도 명확한 조회가 판정기를 호출하지 않는지 검증한다.

## 0.8B 학습에 붙일 형식

이번 변경은 코드의 해석과 대화 기억 수정이다. 모델 가중치는 학습하거나 교체하지 않았다.

현재 모델의 큰 질문 갈래 판정과 별도로 능력치 항목을 분류하도록 학습할 수 있다. 입력은 현재 문장과 코드 기억, 출력은 조회 항목과 변경한 조건이다. 챔피언 ID와 조회 가능한 항목·레벨은 코드가 검증하고 실제 수치는 카드에서 꺼낸다. 수치를 모델의 학습 정답에 넣지 않는다.

권장 학습 자료는 단일 질문, 항목만 바꾸기, 레벨만 바꾸기, 대상 축소·추가, 정정, 스킬 회복과 기본 재생의 대조 문항이다. 실제 질문의 변형들을 모으고 같은 대화·표현 계열은 학습과 평가에 나눠 섞지 않는다. 평가에는 항목 정확도 외에 대상 누락, 레벨 유지, 다른 종류의 질문을 능력치 조회로 오인하는 비율을 따로 둔다.

## 범위

현재 카드의 7개 능력치와 1·6·11·18레벨을 조회한다. 마나·마나 재생 등은 추가 자료 연결이 필요하다. 기본 체력 재생은 스킬·패시브·아이템의 추가 회복을 합산한 값이 아니다. 이 시험은 모든 자연어 표현을 이해한다는 증거가 아니다.

```sh
node --import tsx --test tests/data/advisor-stat-dialogue.test.ts
npm test
npm run type-check
npm run lint
npm run build
```
