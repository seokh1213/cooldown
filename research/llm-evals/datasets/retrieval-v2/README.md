# 검색 질문 은행 v2

기존 `vector-search` 질문 821개는 회귀 은행으로 유지한다. `facts.tsv`의 새 사례 81개를 한국어·영어·중국어로 작성해 `questions.jsonl`에 243개를 보관한다. 영어·중국어에도 `qKo`가 있다. 사람이 독립적으로 수집한 실사용 질문은 아니며, 같은 사례의 번역 3개는 독립 표본으로 세지 않는다.

분할은 모델 결과를 보기 전에 동결했다. 신규 질문은 train 129개, dev 30개, test 84개다. `manifest.json`에 문서 192개의 주제 묶음과 입력 해시가 있다. 해제 판정과 저항 계산은 test, 생명력 흡수는 dev에 둬서 같은 원리의 문서와 번역이 학습·평가 양쪽에 들어가지 않게 한다. 학습 양성과 hard negative 모두 train 문서만 사용한다. train에 배정된 무근거 질문은 대조 학습에서 제외한다.

새 test는 28개 사례의 번역 84개이며, 이 중 4개 사례·12개 질문은 근거가 없다. dev는 무근거 3개 사례·9개 질문을 포함한다. 개발 검증에는 기존 dev 주제의 36개 질문도 함께 사용한다. 기존 Qwen은 과거 문서를 이미 학습했으므로, 이 분할을 Qwen에도 새로운 주제라고 해석하지 않는다.

`gold`는 질문에 답할 근거가 있는 문서 ID다. 다섯 사례에는 사전에 확인한 대체 문서 ID도 허용한다. `sourceSha256`은 원문 스냅샷의 한국어 문서 해시다. `expectedAnswerability`는 답변 가능 여부를 별도로 기록한다. 보호막 흡혈 질문은 확인 불가를 설명하는 문서를 검색하는 것이 맞으므로 `gold`가 있으면서 `unknown`이다. 검색 성공이 수치 답변의 정당성을 보장하지 않는다.

모델 선택은 dev Recall@3, 동률이면 Recall@1, 다시 동률이면 앞선 epoch다. 답변 임계값도 dev에서만 선택하며, dev 오답 0개를 만족하는 후보 중 정답 수를 최대화한다. 실제 배포의 고정 임계값 결과도 함께 남긴다. test 결과로 epoch나 임계값을 바꾸지 않는다.

공통 품질 워크플로에는 test 84개만 `retrieval`·`retrieval-v2` suite로 등록한다. 기본 Gemma와 학습 Gemma는 같은 FP32 조건으로 비교하고, 별도로 Gemma q4와 현행 Qwen q4도 측정한다. 현행 100문서 인덱스와 같은 Qwen으로 갱신한 192문서 인덱스를 구분한다.

실행 절차는 [검색 학습 러너](../../../../scripts/llm/gemma-retrieval/README.md)에 있다. 데이터 패치가 바뀌면 원문 해시와 라벨을 검토하고 새 버전으로 동결한다. 기존 실험의 test를 반복해서 보고 조정했다면 후속 작업에서는 회귀 은행으로 취급한다.
