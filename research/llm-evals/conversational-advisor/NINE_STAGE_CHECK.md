# 자료 계획 처리기를 11개에서 9개로 정리

2026-10-01 · 코드 `303004ce5` · 자료 26.19

이름 한 개·두 개·셋 이상의 새 상성을 처리하던 세 함수를 `answerNewMatchup`으로 합쳤다.
대상을 고르는 `resolveTarget`과 계획을 조립하는 부분을 분리해서 같은 상성 계획을 한 곳에서 만든다.
단순히 세 처리 함수를 새 함수에서 차례로 부르는 방식으로 감싼 것은 아니다.
내/상대 관점, 곁들인 정글 이름 제외, 일반 상대법과 능력치 비교의 구분은 유지했다.

## 현재 구조

대화의 네 단계(기억 복원 → 질문 계획 → 근거 조립 → 답변·기억 기록)는 동일하다.
그 안에서 대화 기억만으로 해결하지 못한 단일 질문의 기본 처리기는 다음 9개다.

| 책임 | 처리기 |
|---|---|
| 지식 4개 | 벡터 검색, 룬·주문 규칙, 이름 오타 정정, 게임 사실 |
| 상성 2개 | 저장된 상성 이어 묻기, 새 상성의 대상 선택·계획 |
| 개별 대상 2개 | 아이템·게임 원리, 챔피언·스킬·비교 |
| 노트 1개 | 마지막 낱말 검색 |

이어 묻기는 저장된 관점·조건을 사용하고, 새 상성은 대상을 확정하는 책임이므로 두 처리기로 유지했다.
기존 `plan`의 `pickMatchupSides` 공개 import는 유지했다.

## 검증

- 집중 시험 4개 추가: 이름 수별 내/상대 유지, 일반 상대법의 대상 추정 방지, 비교 질문의 불필요한 주제 판정 방지, 조사와 모델 관점의 우선순위.
- 기존 계획·대화 시험 177개 통과. 기대값과 모델 호출 순서는 수정하지 않았다.
- 전체 1,455개 시험, 타입 검사·린트·빌드·diff 검사 통과. 단독 빌드에서 기존 청크 크기 경고 외 새 경고 없음.
- 실제 앱 0.8B 워커를 새 판정·검색 캐시로 실행해 동일한 74턴을 다시 측정했다.
- [직전 실제 모델 결과](master-model-74.json)와 계획·본문·기억이 **74턴 모두 동일**했다.
- 경로 74/74, 후속 40/40, 내용 27/30, 상태 6/6 유지. 호출 26회·재사용 1회·실패 대체 0회.
- 콘솔 오류·경고 0건. [최신 실행의 점수·호출·전후 비교 지문](nine-stage-model-check.json).

이 정리는 처리기의 책임과 유지보수를 개선한다. 모델 호출은 26회로 동일하므로
모델 속도나 답변 품질이 추가로 올랐다는 주장에 사용하지 않는다.
`nine-stage-model-check.json`의 각 지문은 `JSON.stringify([plan, text, memory])`의 SHA-256이다.
변경 없는 원문은 `master-model-74.json`에 보존되어 있다.

## 추가 개선 후보

1. **대상·의도 해석을 한 결과로 공유**: 지금도 `dialogueFacts`, `dialogueMatchup`, 기본 계획기가
   이름·슬롯·현재 대상을 일부 따로 해석한다. `ResolvedQuestion`에 명시 대상, 기억에서 보충한 대상,
   질문 종류, 조건, 주제를 담고 각 자료 처리기가 읽도록 바꾸면 중복 판단을 더 줄일 수 있다.
   이번에는 해당 경계까지 바꾸지 않았다.
2. **확실한 조회에서만 판정 생략**: 이름과 수치 항목이 확정된 질문은 자료 조회로 바로 계획한다.
   대화 기억 계층이 이미 일부 처리한다. 남은 경로는 판정·검색 호출 기록으로 선별하고,
   오타·새 주제·언어별 모호한 표현의 회귀를 먼저 확인해야 한다.
3. **이유를 담은 자료와 표현 선택**: “왜?”에 이미 본 문단을 반복하는 경우가 있다.
   검증 노트에 위협·이유·행동을 분리해 두고 현재 조건에 맞는 이유를 선택하면 직답을 개선할 수 있다.
   말투의 변형은 준비된 문장 후보를 선택하는 방식부터 비교할 수 있다.

## 0.8B의 문장 생성

정상적인 자료 답변은 코드와 준비된 자료가 조립하고, 0.8B는 판정·검색을 맡는다.
생성 코드는 `useAdvisor.respond` → 워커의 `generate`에 남아 있으며 자료 준비 전의 예외 경로가 있다.
자료가 준비되고 모델 사용에 동의한 정상 경로에서는 마지막 노트 처리기까지 코드 답을 돌려준다.
이번 74턴에서도 생성 호출은 0회였다.

[최초 생성 실험](README.md)의 짧은 호응 한 문장 검증은 0/71이었다.
그 실험에는 허용 문장 목록이라는 제약이 있었고, 근거 없는 사실이나 메타 설명을 덧붙인 사례도 있었다.
이는 해당 모델·프롬프트·검증 방식의 결과이며 0.8B 모델 전체가 글을 생성할 수 없다는 뜻은 아니다.
새로운 제한 생성 방식을 적용하려면 사실·관점 보존, 검증 통과율, 응답 지연을 별도로 비교해야 한다.
