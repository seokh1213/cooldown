# 질문 해석 공유·사실 검사·0.8B 생성 실험

2026-10-01, 기준 커밋 `3e61cb587`, 패치 26.19. 로컬 Chrome DevTools와 실제 Qwen3.5 0.8B WebGPU 워커로 측정했다. 모델 오류에 따른 오프라인 판정 대체는 없었다.

## 이번에 반영한 세 가지

1. **질문 해석 공유**: 하위 질문마다 이름·별명·원문 위치·슬롯·수치 초점을 읽고 대화 사실 조회, 상성 계획, 기본 자료 계획이 함께 쓴다. `잭스인데 fiora W가 빠졌어`처럼 이름과 언어를 섞어도 스킬 주인을 원문 위치로 찾는다. 서로 분리한 질문끼리는 해석 결과를 공유하지 않는다.
2. **명확한 수치 조회의 판정 생략**: 챔피언과 슬롯이 명시된 사거리·쿨타임·소모값·계수, 한 가지 룬/소환사 주문의 쿨타임을 먼저 카드로 답한다. 교전 조언·가속 계산·정정·전체 스킬 소개·모호한 대상은 기존 대화 계획을 거친다. 영어·중국어 조회도 포함한다.
3. **상성 근거 검사**: 은행과 노트 조립이 같은 검사로 스킬 주인, 명시적 피해 유형, 저항 전체를 무용하다고 하는 단정, 아무무 E의 피해 감소에서 곧바로 관통 우선을 도출하는 근거를 걸러낸다. 문제가 있는 문장만 빼고 나머지는 유지한다. 피해 유형에서 문장을 만드는 코드도 “방어력은 한 푼도 값을 하지 않는다” 대신 해당 스킬 피해와 기본 공격·다른 적을 구분한다.

아무무 E의 피해량 감소와 방어력은 서로 다른 효과다. 관통이 방어력을 상대한다는 사실만으로 E의 피해량 감소에 대응해 관통부터 사야 한다는 우선순위는 도출되지 않는다. 현재 [Riot Data Dragon의 아무무 툴팁](https://ddragon.leagueoflegends.com/cdn/16.19.1/data/ko_KR/champion/Amumu.json)을 근거로 해당 연결을 보수적으로 제거했다.

전체 은행의 88,288개 칸을 훑어 해당 근거 12문장을 찾았고, 실행 시 필터 뒤에는 0문장이 남았다. 원본 은행을 통째로 재생성하지 않는다. 이 검사는 명시된 유형과 문형에 한정되며, 영어/중국어 의미 검사나 모든 전략·숫자의 사실성을 증명하지 않는다.

## 생성 실험

대화 흐름 `answerDialogue`에 선택적으로 생성기를 주입한다. 앱의 기본 경로는 생성기를 넘기지 않는다. 실험은 다음 순서로 돈다.

1. 기존 계획으로 대상·주제·근거 답변과 기억을 먼저 확정한다.
2. 한 상성의 짧은 근거만 전달한다. 수치 조회, 확인 질문, 여러 질문, 저장된 스킬 부재/준비 조건은 생략한다.
3. 0.8B가 최대 두 문장의 요약 후보를 생성한다. 요약 전용 복호화에서는 프롬프트 문장 복사를 반복으로 막지 않는다. 토큰 상한과 반복 중단은 유지한다.
4. **출처 문장과의 일치 검사**를 통과한 후보만 요약으로 붙인다. 공백·마침표 외의 의역은 승인하지 않는다. 숫자·대상·조건·부정·새 조언을 바꾸면 탈락한다. 첫 근거 문장을 빼고 결과만 말하는 것도 탈락한다.
5. 실패·오류·반복이면 기존 답변을 반환한다. 통과해도 전체 근거와 카드, 표시된 주제·조건 기억은 그대로 남는다. 검사 전 생성 조각은 화면에 흘리지 않는다.

자유 의역의 의미를 코드가 완전히 검증할 수 있다고 주장하지 않는다. 따라서 **검사 탈락은 모두 오답이라는 뜻이 아니다**. 안전하게 승인할 근거가 부족하다는 뜻이다.

23턴씩 두 방법을 비교했다. 그 안에 스킬 조회 후 상성으로 돌아오기, 부재 조건 정정, 별도 챔피언 조회, 처음 요약 프롬프트 조정에 쓰지 않은 `d08` 5턴을 포함했다. 각 방법에서 10턴만 생성하고 나머지 13턴은 생략했다.

| 방법 | 생성 | 검사 통과 | 생성 지연 중앙값 | 본문·기억 유지 |
|---|---:|---:|---:|---:|
| 자유 요약 | 10 | 0 | 2.75초 | 23/23 |
| 원문 문장 선택 | 10 | 4 | 2.66초 | 23/23 |

사전 프롬프트·복호화 비교 24회와 정식 비교 20회, 총 44회의 실제 생성을 실행했다. 사전 시험에서 “다리우스 E”를 “가렌 E”로 바꾸거나, 허용하지 말라는 처치/초기화를 유지해야 한다고 뒤집는 출력이 나왔다. 복호화 변경만으로 그 문제가 해결되지 않았다. 원문 문장 선택에서 통과한 네 결과는 기존 첫 문장을 고른 것이어서, 코드가 같은 문장을 바로 보여 주는 것보다 낫다는 증거가 없다.

**결정:** 세 개선은 적용한다. 요약은 재실행 가능한 실험 경로로 남기고 기본 챗봇에는 켜지 않는다. 2~3초의 지연과 낮은 통과율을 감수할 품질 이득이 아직 없다. 0.8B의 실제 문장 생성 능력을 시험한 결과이며, 문장 번호 선택을 자유 생성으로 포장한 결과가 아니다.

## 재현

로컬 `npm run dev` 페이지의 Chrome 콘솔에서 실행한다. 프로덕션 Pages에는 실험 스크립트를 올리지 않는다.

```js
const { createEvaluation } = await import('/scripts/llm/conversational-advisor/browser.ts');
const evaluation = await createEvaluation();
for (const c of evaluation.questions) await evaluation.runCase(c.id, 'combined');
const { evaluateSummaries } = await import('/scripts/llm/conversational-advisor/summaryBrowser.ts');
const singles = evaluation.questions.filter(c => c.turns.length === 1 &&
  evaluation.results.find(r => r.id === c.id)?.plan.kind === 'matchup').map(c => c.id);
const ids = [...singles, 'd01', 'd03', 'd08'];
const paraphrase = await evaluateSummaries(evaluation, 'paraphrase', ids);
const extractive = await evaluateSummaries(evaluation, 'extractive', ids);
evaluation.runtime.close();
```

은행 검사: `npx tsx scripts/llm/audit-matchup-facts.ts /tmp/matchup-facts.json`.
