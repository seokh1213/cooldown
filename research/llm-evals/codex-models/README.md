# Codex gpt-6-sol 대 gpt-6-luna — 번역 속도·품질 (2026-09-27, 패치 26.19)

곧 할 번역 두 가지에 쓸 모델을 고르려고, 두 모델에 같은 프롬프트·같은 묶음을 보내 재고 맹검했다.

- **과제 1 규칙 본문 영어 → 중국어**: `rule-notes.json` 의 `rules[].notes`. `scripts/llm/translate-rules-zh.ts` 의 프롬프트·용어표·대조를 글자 그대로 옮겼다.
  표본 60문장(70규칙 중 60규칙에서 한 문장씩, 규칙을 돌아가며 뽑음), 20문장 × 3묶음.
- **과제 2 상성 답 한국어 → 영어·중국어**: `scripts/llm/translate-matchups.ts` 의 프롬프트와 코드 대조(한글 남음·길이비·이름 빠짐)를 그대로 옮겼다.
  표본 10쌍(르블랑 대 에코·흐웨이·나피리·사일러스 / 쓰레쉬 대 잔나·카르마·레오나·라칸 / 탈론 대 카르마·사일러스) = 79칸.
  스크립트 기본 `--batch 4` 대로 4·4·2쌍 3묶음 × 2언어. 스크립트의 3단계(Claude 뜻 대조)는 돌리지 않았다 — 맹검이 그 몫이다.
- 부르는 법: `codex exec --json --ephemeral --skip-git-repo-check -s read-only -m <모델> -C <임시폴더> -o <출력> -`.
  스크립트 인자에 `--json` 만 더했다(입력·출력·추론 토큰 내역을 받으려고). 답은 스크립트처럼 `-o` 파일에서 읽는다.
- 순서: 9묶음을 섞고 묶음마다 두 모델을 바로 이어 돌렸다(먼저 도는 모델을 번갈아). 속도만 한 번 더(2회차, 모델 순서를 뒤집어) 돌려 조건마다 6번씩 쟀다.
  동시 실행 없음(하나씩). Codex 오류·한도는 한 번도 없었다(36번 모두 정상 종료).
- 품질: 항목마다 두 번역을 A/B 로 섞은 묶음(`blind-*.json`, 218항목)을 Claude 채점 에이전트 2명(general-purpose)에게 따로 주었다.
  10점 척도, 정확성(수치·조건·주체·스킬 이름) 최우선, 그 서버 공식 용어, 자연스러움. 채점자 2는 파일 순서를 거꾸로 받았다.
  열쇠(`blind-key.json`)는 채점이 끝난 뒤 이 폴더로 옮겼다. 채점 대상은 1회차 번역이다.

## 차이가 난 곳 (맹검 풀고 본 것)

**luna 의 오류**
- 규칙: `grounded`(지면 고정)를 `击飞`(에어본)로 옮겼다(5·5점). `takedown` 을 `击杀` 로만 옮겨 어시스트를 빠뜨린 곳이 2건 있었다. 기민함의 5%/6% 조건을 잘못 합쳤다.
- 상성 en: "아군이 뒤에서 싸우는 구도" 를 `playing from behind`(지고 있을 때)로 옮긴 곳이 2건 있었다.
- 상성 zh: "마무리를 미루지 않도록" 을 "急着上前收尾"(서둘러 마무리하지 말라)로 뒤집었다(5·4점).
  사일러스 E `潜掠/强掳` 를 `潜掠 / 压制` 로 적은 곳이 3건, 나피리 E `剔骨本能` 을 `剔骨` 로 줄인 곳이 2건 있었다.
  **`潜掠 / 压制` 는 코드 대조를 통과했다** — `namesIn` 이 `/` 앞 이름(潜掠)만 보기 때문이다. `剔骨` 은 대조가 잡았다.

**sol 이 잃은 곳**(규칙에서만)
- `努努 R`·`赛恩 Q`·`璐璐 W`·`牛头酋长 E` 처럼 원문 스킬 이름을 챔피언 + 슬롯으로 바꿔 7점을 받은 항목이 여럿이다.
  그런데 이것은 프롬프트의 지시("Champion abilities stay as "champion + slot"")를 따른 결과다. luna 는 이 지시를 대개 어기고 공식 스킬 이름을 적어 점수를 얻었다.
  앱이 원하는 쪽이 슬롯 표기라면 sol 의 규칙 점수는 오히려 낮게 잡힌 셈이다.
- `靴子`(클라이언트는 `鞋子`), `传奇装备`(클라이언트는 `传说`), 위키 단계명(on-deal-pre-drain)을 영어로 둔 곳이 있었다.

## 결론

- **과제 1(규칙 → 중국어): gpt-6-sol.** luna 가 묶음마다 약 6초(20%) 빠르지만, 전체가 7분 대 9분이라 차이가 의미 없다.
  luna 는 `grounded → 击飞`, `takedown → 击杀` 처럼 규칙의 조건을 바꾸는 오류를 냈다. 규칙 본문은 조건 하나가 전부라 이런 오류가 가장 치명적이다.
  스크립트 기본값이 `gpt-6-luna` 이므로 `--model gpt-6-sol` 로 돌려야 한다.
  슬롯 표기 지시가 원하는 바가 아니라면(luna 가 공식 스킬 이름을 쓴 쪽이 채점자에게 더 좋게 보였다) 프롬프트를 먼저 고친다.
- **과제 2(상성 → 영어·중국어): gpt-6-sol.** 속도는 사실상 같다(중앙값 기준 luna 가 4~5초 빠르나 튐이 커서 평균은 비슷하거나 느리다).
  sol 은 158칸에 큰 오류가 없었고 코드 대조도 전부 통과했다. luna 는 zh 에서 뜻 반전 1건, 공식 이름 오류 5건, en 에서 뜻 어긋남 2건을 냈다.
  이 가운데 `潜掠 / 压制` 는 코드 대조를 빠져나갔다. 스크립트 기본값(`CODEX_MODEL`)이 이미 `gpt-6-sol` 이다.
- 곁가지: `translate-matchups.ts` 의 `namesIn` 이 `도주 / 억압` 같은 두 이름 스킬의 첫 이름만 대조한다. 뒤 이름 오류를 잡으려면 둘 다 보아야 한다(이번 작업 범위 밖이라 고치지 않았다).
- 한계: 표본이 작고(규칙 60, 상성 79칸 × 2언어) 두 채점자가 모두 Claude 다. 평균 차이 0.1~0.2점은 대부분 비긴 항목 속에서 드문 큰 오류가 만든 것이라, "sol 이 크게 낫다" 가 아니라 "luna 가 가끔 조건을 틀린다" 로 읽어야 한다.
