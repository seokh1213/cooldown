## A — 대화 상태 (`scripts/llm/kev-agent/eval-a.ts`)

## B3 — 판정 칸을 더 잘게, 앱에 연결 (2026-09-25 밤)

"그 밖" 한 칸에 아이템과 게임 규칙이 섞여 있어, 이어 묻기에서 "방어력 올려?"(앞 상성의 이어 묻기)와
"항복 몇 분부터?"(새 질문)를 가르지 못했다. 판정을 나누고 대화 흐름 판정을 더했다. 학습 자료는 전부 코드 틀
문장과 사람이 다시 붙인 라벨이다(토큰 비용 없음).

- 갈래: route-train "그 밖" 258문항을 사람이 item·rune·spell·game·chat 으로 다시 붙였다(`b3/other_labels.py`).
  시험 세트 route-large 의 "그 밖" 75문항도 따로 붙였다(`b3/large_other_labels.py`, `route-large3.json`).
- 대화 흐름(act): "앞에서 M 으로 E 상대법을 물었다" 뒤의 새 말이 followup·more·enemy·mine·flip·new 중 무엇인가.
  틀 문장 1,959(`b3/build_b3.py`, 시험 챔피언 19명 제외). 시험은 손으로 쓴 60문항(`act-test.jsonl`, 세 언어, 틀과 다른 말투).

작은 헤드가 약한 곳(이어 묻기를 새 질문으로, 상대↔내 챔피언 혼동)은 코드가 먼저 가른다(`conversation.ts`):

- 새 질문: 아이템·게임 규칙 문서 이름, 게임 메타 낱말(항복·닷지·LP·정수·가격·스킨·몇 분에 나와 …)만 가른다.
  판정기의 "new" 는 쓰지 않는다. sub-v1 의 game·chat 을 판정기 둘이 동의할 때 새 질문으로 치는 판도 재 봤지만

### 앱에 넣은 것

- `src/lib/advisor/conversation.ts`: 상태(`matchupStateOf`), 판정(`planTurn`·`sideOfNewName`·`actFromWords`), act 질문 꼴.
- `AdvisorPanel.ask` 3단계: 방금 답한 상성이 있고 이번 말의 이름이 하나 이하면 이어 받는다. "앞서 말한 가렌 vs 다리우스 기준입니다" 안내.
- "더 자세히": 미리 쓴 답이면 처음 답에 싣지 않은 칸(`precomputedMore`), 노트 조립이면 물은 칸을 전문으로.
- 판정기 "그 밖" 이 게임 규칙(sub-v1)이고 검색이 비면 모델이 지어내지 않게 "자료에 없다" 고 답한다(`noGameData`).
- 오타 교정 버그: 이어 묻는 말의 낱말이 이름으로 고쳐졌다(그럼·그런→그웬, 나서는→나서스, 자꾸·사야→자야, 나아→나미).
  흔한 첫머리 낱말을 빼고, 상성 대화 중에는 두 글자 낱말을 오타로 보지 않는다.
- 브라우저(모델 없음)에서 "가렌으로 다리우스 상대법 → 그럼 한타 때는? → 다리우스 입장에서는? → 왜? → 피오라는? →
  항복 몇 분부터 돼?" 가 차례로 가렌 vs 다리우스 한타 · 다리우스 vs 가렌 · 같은 쌍의 남은 칸 · 다리우스 vs 피오라 · 새 질문으로 갔다.

### B3 LoRA (kev-0.8B ← B2 에서 이어 학습, 브라우저 이식 전)

route3(9갈래 한 번에) 1,391 + act 1,959 + topic 600, 2 epoch, MPS 약 6시간. 어댑터는 세션 scratchpad `runs/b3-v1`.

| | 헤드(route-v2+sub-v1, act-v1) | **B3 LoRA** |
|---|---|---|
| 갈래: 챔피언 4갈래 | 266/299 (8.9) | **288/299 (9.6)** |
| 갈래: 그 밖 5갈래 | 36/75 (4.8) | **53/75 (7.1)** |

입장 뒤집기·더 자세히·상대/내 챔피언 가르기를 맡아 손 시험에서 7.8 → 8.0, B3 는 8.5.

## B3 를 브라우저에 — 변경분만 올리고 그래프를 바꿔 끼운다 (2026-09-26)

Hugging Face 에 모델을 새로 올리지 않는다. 원본 가중치(`model_q4.onnx_data`, 550MB)는 지금처럼 onnx-community 에서
받고, **LoRA 를 덧붙인 그래프 파일 하나(22.4MB, LoRA fp16 21.6MB 포함)** 만 우리 사이트(`public/models/kev/b3-v1/`)에서 받는다.

- `b3/lora_onnx.py`: 원본 q4 그래프의 MatMulNBits 186곳마다 `+ lora_scale · (x·Aᵀ)·(Bᵀ·α/r)` 를 붙이고 은닉 상태 출력
  `hidden` 을 더한다. 재양자화가 없다. `lora_scale` 0 이면 logits 가 원본과 정확히 같다(최대 차 0.0).
- 워커: transformers.js 의 사용자 캐시로 `…/onnx/model_q4.onnx` 요청만 우리 그래프로 바꿔 준다. transformers.js 에게는
  `lora_scale` 입력을 숨기고 0 을 채워(생성은 원본 그대로), 판정만 세션을 직접 불러 1 을 넣고 `hidden` 을 읽는다.
- kev 헤드(`public/models/judge/kev-b3`)는 은닉 상태 1024 위의 PointerHead. `?advisorModel=kev` 로만 고른다(시험 중).
- B3 는 Qwen3.5-0.8B-**Base** 에서 학습했는데 앱 그래프는 **Instruct** 변환이다(가중치 대조: Instruct 와 상대 오차 0.082 =
  q4 오차, Base 와 0.094~0.113). 그래도 대화 흐름은 줄지 않았다.

| | 갈래 9칸 374(판정기만) | 대화 흐름 60 | 판정 1회 |
|---|---|---|---|
| B3 맥(MLX bf16, Base) | 334 | 52 | — |
| B3 파이썬 CPU(Instruct q4 + LoRA) | 316 | 54 | — |
| **B3 브라우저(WebGPU, 같은 그래프)** | **316** | **54** | 0.76~1.25초 |

브라우저가 파이썬과 문항마다 같은 답을 냈다. 앱에서 "가렌으로 다리우스 상대법 → 정글이 자꾸 탑으로 오는데 그럴 땐? →
반대로 하면? → 피오라는? → 그럼 템은? → 오공으로 하면 좀 나아? → 항복 몇 분부터 돼? → 아리 가격 얼마야?" 가 모두 맞는
쌍·자료로 갔다(한 턴 2.4~5초).

- kev 판정기의 "new" 는 믿지 않는다. 믿는 판이 평균은 조금 높았지만(270턴 8.2) 실제 대화에서 "정글이 자꾸 탑으로 오는데
  그럴 땐?" 을 새 질문으로 보내 검색 길로 빠졌고, 0.8B 가 "정글은 탑으로 오지 않습니다 …" 를 지어냈다.
- **남은 위험**: 이름 없는 질문의 검색 길(`sendWithSearch`)에서는 0.8B 가 글을 쓴다. 이 길 자체를 막는 것은 따로 할 일.
- 자동화 Chrome 에서는 550MB 캐시 쓰기가 실패해(`Cache.put` 550MB 단독으로도 실패, 200MB 는 됨) 매번 새로 받았다.
  실제 브라우저에서 두 번째 방문에 다시 받지 않는지 확인이 남았다.
