# 대화 기억을 사용한 아톰 선택 재실험 — 2026-10-01

## 비교 방법

현재 앱의 `planDialogue`로 7개 대화, 20턴을 계획했다. 챔피언 변경, 스킬 상태 정정,
상대 변경, 다른 챔피언의 수치 조회 후 이전 상성으로 돌아오기를 포함한다.
19턴은 상성 조언이고 말파이트 R 쿨타임 1턴은 수치 조회여서 아톰 비교에서 제외했다.
질문과 결과는 `questions.json`, `results.json`에 있다.

같은 계획·기억을 세 방식에 주었다.

1. **현재 답변**: 앱과 동일한 `selectMatchupReply`, 실제 26.19 상성 답 은행, `scope: topic`.
2. **낱문장 선택**: 기존 상위 모델이 만든 원자의 주제·스킬·관점으로 최대 3문장을 선택.
   원자 자체의 `when.enemyIds`는 적용하지만, 원문에만 남은 적용 조건은 가져오지 않는다.
3. **출처와 연결한 선택**: 같은 원자를 선택 색인으로 쓰되, 현재 `selectPlaybook`이 허용한
   부모 노트에서만 고르고 현재 원본 문맥을 함께 복원한다. 같은 출처는 한 번만 표시한다.

스킬 이름·이름 위치·사용자 조건으로 스킬 주인을 구분한다. 적합한 출처가 없으면
이번 요청의 현재 답변을 사용한다. 조건 정정은 코드 기억을 그대로 사용한다.
모델 판정·문장 생성은 호출하지 않았다. 앱 기본 경로에 아톰 선택을 연결하지 않았다.

## 관찰

| 측정 | 낱문장 선택 | 출처와 연결한 선택 |
|---|---:|---:|
| 비교한 상성 턴 | 19 | 19 |
| 선택한 문장 / 부모 노트 | 54 | 30 |
| 현재 부모 노트의 적용 조건·관점에 맞지 않는 선택 | 8 | 0 |
| 현재 답변으로 복귀 | 1 | 1 |
| 답변 길이 중앙값, 글자 | 142 | 333 |

`0`은 부모 노트의 조건 필터를 적용한 결과다. 독립적인 사실 판정이나 사람의 품질 점수가 아니다.
서로 선택 단위와 양이 달라 8/54와 0/30을 전체 답변 정확도로 해석하면 안 된다.

구체적으로 좋아진 부분:

- 잭스 대 피오라에서 아트록스 한정 노트의 문장이 들어오는 일을 막는다.
- 상대가 원거리에서 근접으로 바뀌면 원거리 상대용 노트의 적용 조건도 다시 검사한다.
- 피오라 W 질문에 피오라의 W를 선택하고, 스킬 사실과 대응 행동의 연결을 유지한다.
- 26.18 원자 본문을 그대로 내는 대신 현재 26.19 원문을 사용한다.

남은 문제:

- 부모 노트를 통째로 복원하면 묻지 않은 설명까지 따라온다. 현재 상성 답 은행이 더 직접적으로
  내 챔피언의 행동을 설명하는 사례도 있다. 이번 실험으로 현재 답변보다 전체 품질이 높다고 결론 내리지 않는다.
- 사용자 W 부재/존재는 저장되지만, 원자에는 이 상태를 요구하는 구조 필드가 없다.
  따라서 이미 빠진 W를 다시 빼라는 원문을 자동으로 제외하는 단계는 아직 만들지 않았다.
- 이유 질문에서 적합한 원자가 없는 경우가 있었다. 그 1턴은 현재 답변으로 복귀했다.
- 기존 원자는 26.18이다. 출처 id가 남아 있어도 과거 원자 메타데이터가 현재 원문을 완전히 설명한다고
  보장할 수 없다. 새 원자에는 원문의 해시·검증 패치가 필요하다.
- 탐색하면서 선택 규칙을 조정한 작은 세트다. 별도의 보류 질문에 대한 맹검 품질 평가는 하지 않았다.

## 다음 구조

원자를 **조건 + 근거 + 행동**의 판단 단위로 만들고, 각 단위에 다음을 명시하는 것이 유력하다.

- 챔피언·스킬 주인과 플레이/상대 관점
- 필요한 상태: 예를 들어 `enemy.W = ready`
- 함께 포함해야 하는 근거와 선행 조건의 id
- 서로 충돌하는 행동과 적용하지 않을 조건
- 원문 id·해시·검증 패치

코드가 상태에 맞는 판단 단위를 고르고, 필요한 근거를 함께 조립하면 문단 전체를 복원하는 양을 줄일 수 있다.
0.8B의 생성 없이 이 단계를 먼저 검증할 수 있다. 새 필드로 상위 모델의 원자를 다시 만드는 실험은 아직 하지 않았다.

## 함께 고친 대화 오류

이 실험의 대화 재생에서 발견해 기본 경로도 고쳤다.

- `내 챔피언은 잭스로 바꿨어 피오라 W…`가 예전 아트록스 관점을 유지하던 오류.
- `내 챔피언이 럭스면…`의 `럭스면`을 이름으로 못 찾던 경계와 명시적 내 챔피언 지칭.
- `베인으로 잭스 … E 반격을 어떻게 상대해?`를 E 수치 비교로 보내던 오류.
