# 제외·부정·관점 변경 질문 점검

## 범위와 완료 기준

- 18개 대화 30턴을 먼저 만들고 이전 코드에서 실행했다. 대상/항목 제외, 이름만 이어 묻기, 스킬 상태의 부정, 내 챔피언 교체, 조건과 독립 요청, 10명 수치 비교를 포함한다.
- 첫 수정 후 다른 표현으로 9개 대화 17턴을 추가했다. 영문 축약 부정, 진행 중 쿨타임, 이중 부정, 전체 제외, 실제 이름 오타를 검사한다.
- 수치는 실제 카드와 일치해야 하며, 제외한 대상·항목을 조회하지 않아야 한다. 스킬 상태는 해당 상성에만 남아야 하고 사용할 수 없는 스킬을 권하지 않아야 한다. 자료에 없는 조건과 지나치게 넓은 요청은 안내한다.
- 실제 `answerDialogue`를 실행하고 매 턴 저장·복원을 거친다. 새 모델과 생성은 켜지 않았다. 코드 경로(`none`)와 기존 오프라인 판정기(`offline`)를 각각 검사했다.

## 본문 직접 검토

자동 조건 통과 후 답변 본문도 직접 읽었다. 외부 평가자 검토는 아니다.

- “E가 없는 게 아니야. 상대 궁 대응은?”은 상태만 올바르면 일반 진입 조언을 그대로 남길 수 있었다. 궁 이름이 포함돼도 궁 방어의 답이라는 보장은 없다. 방어 질문은 해당 상대 스킬의 근거 노트를 선택하도록 바꿨다. 이제 제드의 표식이 붙은 동안 사용 가능한 아리 E 매혹으로 콤보를 끊는 근거를 보여준다.
- 영문 `his ult`는 상대 R로 연결한다. E가 없는 상태에서는 제드 E 둔화 설명을 궁 대응으로 대신하지 않는다.
- E 사용 불가인 제드 궁 대응은 현재 노트에서 다른 방법을 확인하지 못했다는 답을 유지한다. 조건을 지키는 점은 개선됐지만 이 상황의 실전 도움은 여전히 제한된다.
- 10명 수치 조회와 미지원 5레벨 안내는 이전에도 통과했으며 유지됐다. 세 쌍 이상의 상성 조언에는 지원 범위와 질문 예시를 안내한다.
- 내 챔피언을 교체한 두 상성은 질문·답 제목·VS 링크 모두 새 챔피언 관점을 사용한다.

## 재현과 화면 검증

```sh
node --import tsx scripts/llm/eval-dialogue-coverage.ts /tmp/edge-after.json research/llm-evals/dialogue-coverage/edge-questions.json 7560a23af
node --import tsx scripts/llm/eval-dialogue-coverage.ts /tmp/edge-validation-after.json research/llm-evals/dialogue-coverage/edge-validation.json 7560a23af

npm run test:e2e -- e2e/advisor-dialogue-edits.spec.ts e2e/advisor-stat-coverage.spec.ts e2e/advisor-matchups.spec.ts
```

집중 단위 시험은 제외·추가·빈 선택·부정·조건 정정·그룹 관점·독립 질문·이름 오타를 검사한다. 이름을 잇는 “그리고”가 두 상성을 깨지 않는지도 확인한다. 브라우저 시험은 실제 표시된 답, 새로고침 뒤 조회 유지, 사용할 수 없는 E 제외, 정정 뒤 궁 대응, 새 관점의 두 카드/링크를 확인한다. 로컬 Chrome에서도 E 부재 → 정정 대화를 실제로 실행해 본문을 확인했다.

배포 CI에서 새로고침 시험이 첫 실행에 실패하고 재시도에서 통과한 경합을 추가로 발견했다. 자료 다운로드를 의도적으로 보류해 확인하니 저장 기록 복원이 끝나기 전에 전송 버튼이 활성화됐다. 첫 질문이 턴을 먼저 만들면 기록 복원이 생략되고, 질문 처리 함수도 복원 전의 빈 대화를 가지고 있었다. 저장된 대화를 복원하는 동안은 초안을 입력할 수 있고, 복원이 끝난 뒤 전송하도록 바꿨다. 새 대화를 선택하면 기존 기록 복원을 취소한다. 기록 없는 첫 질문은 기존처럼 자료를 기다리며 처리한다. 이 조건을 실제 다운로드 보류 시험으로 고정해 재시도 없이 확인한다.

## 한계

복잡한 부정과 생략을 모두 이해하는 자연어 모델은 아니다. 검증한 표현에서 대상·항목·상태를 코드가 구조로 저장한다. 근거 노트 자체의 모든 전략을 새로 검증하거나 0.8B의 생성 품질을 평가한 실험은 아니다.
