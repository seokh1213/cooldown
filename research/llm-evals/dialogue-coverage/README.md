# 요청 누락·대화 유지·답변 품질 점검

## 완료 항목

1. 여러 능력치와 독립 요청: 순서 있는 `fields` 목록을 표·결론·본문·기억·저장 기록·계약 검사에서 공유한다. 단일 항목의 기존 `field` 기록은 그대로 복원한다. 여러 요청 중 한 요청이 미지원이거나 확인 질문이 필요해도 나머지는 답한다.
2. 섞어 묻는 대화: 상성별 조건/표시 주제를 보관하는 목록과 현재 한 상대/두 상대 선택을 구분한다. 한 상대 선택 → 스탯 조회 → 이전 두 상대 복귀에서도 각각의 E/R 상태를 복원한다. 완료된 답은 즉시 저장하고 페이지 이탈 시 남은 저장을 처리하여 빠른 새로고침에도 기억을 보존한다.
3. 품질 점검: 조회 대상과 항목뿐 아니라 실제 숫자, 스킬 사실, 부재 조건, 실행할 수 없는 조언, 반복, 거절 후 안내를 검사한다. [직접 검토 기록](quality-review.md)은 자동 통과율과 별도로 남긴다.

## 비교 조건

- 이전 코드: `00f286fa6`, 자료 패치: 26.19, 언어: 한국어.
- 같은 질문·같은 정적 자료·같은 평가기로 이전 코드와 변경 코드를 실행했다. 이전 코드는 별도 `/tmp` 소스 사본에서 다시 실행하여 `before.json`을 재생성했다.
- 실제 `answerDialogue` 경로와 `dehydrateTurn → JSON → reviveTurn` 저장 복원을 매 턴 실행했다.
- 모델 없는 경로(`none`)와 기존 오프라인 판정기(`offline`)를 각각 평가했다. 0.8B 생성이나 새 학습 모델은 켜지 않았다.
- 개발셋 18개 대화·43턴, 이후 만든 검증셋 8개 대화·18턴. 검증셋에서 발견한 제외 표현/대상 생략 문제도 고쳤으므로 **최종 검증셋은 블라인드 평가가 아니다.**

## 재현

```sh
node --import tsx scripts/llm/eval-dialogue-coverage.ts
node --import tsx scripts/llm/eval-dialogue-coverage.ts research/llm-evals/dialogue-coverage/validation-after.json research/llm-evals/dialogue-coverage/validation.json
node --import tsx scripts/llm/eval-request-contract.ts /tmp/request-contract.json
node --import tsx --test tests/data/advisor-request-coverage.test.ts
```

로컬 코드 평가 한 회는 약 1초였다. 코드에서 먼저 실패를 좁힌 뒤 Chrome에서 최종 화면을 확인했다. 브라우저 회귀 시험은 390px/1440px에서 두 결론 표시, 중복 문장 제거, 새로고침 뒤 18레벨·문도만·체젠만 후속 질문과 상성 링크를 확인한다.

빠른 새로고침 시험에서 기존 400ms 지연 저장이 대화를 잃는 오류도 발견했다. 완료 후 즉시 저장으로 수정했고, 생성 중에는 기존 지연 저장을 유지한다. 검증된 대화의 JSON 복원과 실제 브라우저의 저장 타이밍은 별도 검사다.

## 남은 품질 한계

- 근거 노트에 대안이 없으면 답을 만들어 내지 않는다. 아리 E 없는 제드 궁 대응 사례는 미확인 안내를 준다. 조건 준수는 좋아졌지만 이 사례의 실전 도움은 여전히 제한적이다.
- 기존 조언의 세밀한 교전 타이밍과 아이템 추천 범위가 새로 검증된 것은 아니다. 정적 패치 자료·노트 범위 안에서만 답한다.
- 임의의 긴 자연어 문장을 완벽하게 분리하는 파서는 아니다. 새 표현은 이 질문셋과 집중 테스트에 추가해 회귀를 확인할 수 있다.
