## 수치 질문 132개

기존 master 경로에서 정답 문서 도달 92/132, 수정 경로에서 109/132였다. 개선 17건, 퇴보 0건이다. 수정 경로가 전달한 동일 문서·프롬프트에서 원래 웨이트는 숫자·단위 완전 일치 64/132, 신규 QA 웨이트는 90/132였다. 문서가 없는 11건씩은 NOT_FOUND로 기록했고, 나머지 242건은 실제 Mac WebGPU 생성이다.

종전 고정 입력 시험의 **92/132**와 이번 **90/132**는 입력 문서·문맥이 달라 직접적인 점수 하락으로 비교할 수 없다. 92는 100점 만점 점수가 아니다.

**직접 응답 안전 검사는 132건 중 1건만 허용했고, 허용한 오답은 0건이었다.** 문서의 같은 숫자를 복사해도 질문한 속성·조건·단위가 틀릴 수 있어, 문서에 숫자가 있다는 이유로 응답하지 않는다. 신규 웨이트가 실제 앱 답변 전반을 개선했다고 결론 내릴 수 없다. 현재 효과가 입증된 범위는 요청 분류 수정과 제한된 수치 추출 성능이다.

## 실제 앱 워커 검증

배포용 Vite 워커에서 활성 그래프 적재 → QA 수치 생성 → 일반 범위 생성 → 검색 임베딩을 순서대로 실행했다. 636,148,447바이트 적재, 수치 `0.25초`, 유효한 범위 JSON, 유한한 1,024차원 임베딩을 확인했다. 검증 전 수치 chunk는 0건이었다. 신규 그래프의 실측 장치는 Mac Chrome WebGPU이며 Pascal 장치의 신규 QA 그래프는 아직 별도 확인하지 않았다.

집중 단위 검사 27개, 관련 데이터 검사 125개, 앱 타입 검사·변경 파일 린트·Vite 빌드가 통과했다. 비교에 사용한 로컬 서버 4개와 전용 평가 브라우저는 종료했다.
