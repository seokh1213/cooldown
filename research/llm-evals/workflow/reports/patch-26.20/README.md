# 26.20 데이터 전환 복구

2026-10-07. 실행 실패는 CommunityDragon이 복구된 뒤 발생했다. [실패 실행](https://github.com/seokh1213/cooldown/actions/runs/37602385469)의 `llm:carry`에서 암베사 스킬 본문 지문 변경을 발견해 콤보 검수를 요구했고, 생성 자료의 커밋과 배포 전에 중단했다. 중단 당시 서비스는 26.19를 유지했다.

## 변경 자료와 검수 범위

- 26.20 정적 자료·세 언어 스킬 카드·아이콘과 패치 변경 기록을 생성했다. 패치 기록의 수치 추출은 9개 대상·15개 변화이며, 매핑하지 못한 14개 조각을 검토 대상으로 보존한다. 공식 노트 전체를 수치화했다는 뜻이 아니다.
- 콤보 원본 173명 중 본문이 바뀐 12명만 공식 노트와 현재 스킬을 대조해 개별 검수 패치를 갱신했다. 본문 불일치 보호는 유지하며 오류에는 변경된 챔피언 이름을 모두 표시한다. [챔피언별 근거](../../../../champion-combos/README.md)를 따른다.
- 메커니즘 865개는 849개 의미 동일 이월과 16개 변경 슬롯 검수로 구분한다. 이미지 판본만 바뀐 경우 의미 지문을 유지하지만 실제 형태 ID·재사용 대기시간 등은 계속 변경으로 잡는다. [16개 슬롯 검수 기록](../../../../champion-mechanics/26.20-v1/reports/changed-slots-review.json)을 보존한다. 게임 내 재현이나 독립 검수자는 사용하지 않았다.
- 군중 제어 865개는 기존 숫자 정규화 지문이 모두 같고, 본문 변화가 있는 슬롯을 유형·대상·발동 조건 기준으로 대조해 이월 근거를 남겼다. 영상 노트 44개도 참조 스킬이 같고 관련 변경이 없는지 확인한 뒤 허용 패치에 26.20을 명시했다. 이후 미검수 패치는 자동 포함하지 않는다.
- 상성 캐시 7,262쌍 중 5,838쌍은 세 언어 원천 카드와 현행 코드의 이전·현재 재료가 같을 때만 이월했다. 바뀐 아이템을 언급한 쌍도 제외했다. [쌍별 비교 기록](../../../../champion-combos/26.20-matchup-carry.json)을 보존한다. 생성 당시 오래된 지문을 무조건 새 지문으로 덮어쓰는 경로는 추가하지 않았다.
- 닐라 대 스몰더는 R 회복 수치 변경 때문에 자동 이월에서 제외됐다. 이후 현재 카드로 콤보·진입 타이밍·한타 세 주제만 세 언어에서 별도 검수했다. 필요 없는 ‘유일한 도주 수단’ 단정을 제거했고 미검수한 다른 다섯 주제는 복원하지 않았다. 따라서 최종 보존은 자동 5,838쌍 + 수동 검수 1쌍이다. [수동 검수 기록](../../../../champion-combos/26.20-nilah-smolder-review.json)을 따른다.

## 전환 때 드러난 테스트 입력 문제

아이콘 기대값을 활성 판본에서 읽도록 바꿨다. 형태 파일 이름·합성 이미지 품질·실제 이미지 로딩 검사는 유지했다. 과거 부분 메커니즘 스키마 실험은 26.19 소스 카드를 별도로 동결했으며 현재 제품의 865개 규칙은 26.20을 사용한다.

능력치 질문의 초기 기억 195개는 현재 대화용임을 은행에 명시했다. 과거 패치의 사용자 기억을 실제 앱에서 거절하는 보호는 유지한다. 질문·정답과 채점 규칙은 바꾸지 않았다. 초기 기억 정책 때문에 바뀐 ID는 원본 파일·행으로 대응해 이전 결과를 확인한다.

전체 회귀 실행은 5,809개 측정을 끝냈고 12개 인프라 검사·전체 커버리지가 통과했다. 자동 계약 5,789개 중 5,758개 통과, 기존 요청 분류기 실패 31개가 그대로 남았으며 과거 답변 20개는 수동 검토 상태다. [이전 패치와의 대응 기록](comparison.json)에서 새 회귀 0개, 기존 실패의 임의 승격 0개, 채택한 잘못된 수치 0개를 확인하고 완결된 결과를 26.20 기준 파일로 복사했다. 엄격한 동일 데이터·질문·채점기 비교 규칙은 유지한다.

### 지속시간 질문 수정

실제 배포 확인용 질문을 준비하면서 ‘릴리아 R 수면 시간’이 지속시간 대신 CC 종류만 답하는 문제를 재현했다. ‘수면 지속 시간’은 졸음 단계만 고르고, 영어 `duration`은 부분 문자열 `ratio` 때문에 계수로 분류됐다. CC 시간 표현을 수치 경로로 보내고, 졸음/수면은 부분 규칙 검색보다 현재 툴팁의 시간 문장을 사용하며, 영어 계수 어휘에는 단어 경계를 둔다. 숫자는 코드에 넣지 않고 현재 카드에서 읽는다.

한국어 두 표현·영어·중국어의 실제 대화에서 26.20 수면 시간 2.5/2.75/3초를 확인했다. CC 종류·강인함·발동 순서와 피해·계수 질문의 구분도 함께 시험한다. 이 제품 코드 수정 뒤에는 같은 26.20 기준을 대상으로 원격 전체 회귀를 다시 비교한다. 기준 측정의 원래 출처 해시와 시각은 그대로 보존한다.

마지막 제품 빌드의 실제 브라우저에서도 릴리아 수면 시간, 크산테 피해 감소율, 바론, 아타칸 제거 여부, 체력 비교와 후속 방어력 비교, 징수의 총 999 표시의 7개 질문을 통과했다. 현재 배포 자료·릴리스 메타데이터·고정 데이터 사본·패치 내역의 26.20 일치도 함께 검사한다. 원격 배포 완료 여부는 Actions와 공개 사이트에서 별도로 확인한다.
