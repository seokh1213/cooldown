## 워크플로우와 데이터 정리

혼합 JSONL의 train/dev 예시가 역사적 질문 수집기에 들어가던 오류를 고쳤다. 해당 행과 중첩 train/dev 목록은 평가에서 제외한다. 자동 회귀 4,076개 턴·37개 묶음은 유지되고, 수동 역사 은행은 1,919개에서 952개가 됐다. 제거된 967개는 평가 입력으로 섞인 학습·선택 자료다. 삭제한 학습 자료가 아니라 평가 은행에서 제외한 자료다.

```sh
npm run llm:test:audit
npm run llm:test -- --profile regression \
  --baseline research/llm-evals/workflow/reports/regression/baseline.json \
  --out research/.cache/quality/current
npm run llm:test -- --profile infrastructure --out research/.cache/quality/infrastructure
npm run llm:test -- --profile ui --out research/.cache/quality/ui
```

완결된 수정본을 CI 기준으로 저장했고 `reports/regression/provenance.json`도 함께 보존했다. 이것은 현재 미해결 계약을 품질 승인하는 변경이 아니다. 다음 변경에서 이미 성공한 계약·보호 답변이 나빠지는 것을 차단한다. 분류기 교체 비교의 `--pipeline-baseline`은 이 provenance와 실측 데이터 해시를 검증하며 request-v1 교체 또는 stat-v1 추가/교체만 허용한다. 다른 자료·QA 웨이트 변경에는 새 대조군이 필요하다.

같은 체크아웃에서 모델을 동시에 실행하지 않는다. 서로 다른 동결 체크아웃을 사용하며 25개 측정마다 결과를 로컬 저장한다. Colab을 다시 쓸 때는 기존 60초 수집기·SHA 검증·필수 최종 결과 로컬 확인 후 런타임 종료 절차를 유지한다. 이번 작업에는 활성 Colab 런타임이 없다.
