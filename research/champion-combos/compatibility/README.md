# 콤보 변경 감지와 배포

스킬 변경 자체로 전체 생성을 중단하지 않는다. 원문과 노트의 지문을 비교해 노트마다 `unchanged`, `compatible`, `needs-review`로 분류한다. 원천·기준 자료가 손상됐거나 형식이 잘못된 경우는 계속 실패한다.

## 최초 백필과 자동 유지 범위

173명, 353개 콤보와 라인전 2개를 26.20 원문 스냅샷에 연결했다. 이는 기존 승인 자료의 기준을 보관하는 백필이며, 모든 노트를 새로 의미 검수했다는 뜻은 아니다. 기존 직접 검수 패치·날짜는 보존한다.

각 콤보의 `dependencies`에는 참조 스킬, 피해 수치 의존 여부, 근거가 있다. 초기에는 패시브를 포함한 모든 스킬과 기본 스탯을 보수적으로 비교한다. 검수자가 의존성을 좁힌 경우에만 미참조 스킬 변경을 무시한다. 아이콘 판본과 전체 모집단에 따른 스탯 백분위는 비교하지 않는다.

현재 피해량과 무관하다고 원문 대조한 자동 유지 대상은 **암베사 콤보 2개**다. 다른 351개는 수치 변경도 우선 검수 대기로 처리한다. 자동 승인 대상을 모든 콤보로 확대하지 않았다.

숫자를 전부 삭제하지 않는다. `의 물리/마법/고정 피해` 바로 앞의 제한된 산술식에서 피해 수치만 가리고, 남은 원문·스킬 태그·CC·쿨타임·형태·스탯을 그대로 비교한다. 중첩, 지속시간, 처치 경계, 미분류 문구는 보류한다.

기존 패치 수집기의 `data/patch-notes/sources/<patch>.json`도 함께 비교한다. 암베사 패시브의 피해 상한과 추가 공격력 계수 **두 원본 필드**만 `damageSourceKeys`로 연결했다. 툴팁이 같아도 다른 원본 필드가 바뀌면 보류한다. 원본 필드 추가·삭제는 보류하고, 챔피언 원본 자료 자체가 없으면 오류로 중단한다. 공식 패치 노트는 검수 근거이며 원문 변경을 빠짐없이 설명했다는 증거로 사용하지 않는다.

## 검수 대기와 답변

보류한 노트는 실행 번들에서 제외한다. 해당 챔피언의 옛 콤보 노트도 제외하고, 번역에는 실행 번들에서 허용한 노트만 싣는다. 해당 챔피언이 포함된 기존 상성 답변 캐시는 이월하지 않으며, 브라우저에서도 캐시 대신 현재 자료를 조립한다. 다른 챔피언의 자료와 최신 수치는 계속 생성한다.

명시적 콤보 질문에는 검수 중임을 한국어·영어·중국어로 안내한다. 부분 보류이면 확인된 연계만 보여 준다. `comboReview`는 게임 요소의 활성·제거 상태와 별도다.

`verifiedPatch`와 `reviewedAt`은 직접 검수 기록이다. 실행 노트의 `compatibility.checkedThroughPatch`와 원문 지문은 자동 호환 확인 기록이다. `version.verifiedThroughPatch`는 이 호환 확인 패치까지 반영하지만 원천 검수 패치는 바꾸지 않는다.

## GitHub Actions와 재검수

`npm run llm:combo-review`는 변경 전후 원문·노트별 판정·지문을 `research/.cache/combo-review/report.json`에 기록한다. 정적 데이터 workflow가 이를 실행 요약과 `combo-compatibility-review` artifact로 보관한다. 모델이나 인증 토큰은 필요하지 않다. 기존 단위·자료·브라우저·회귀 검사는 유지한다.

검수자는 보고서의 원문 변경과 공식 패치 노트를 해당 챔피언의 **모든 콤보 및 라인전 노트**와 대조하고, 필요하면 노트·의존성을 수정한 뒤 아래 명령으로 그 챔피언만 승인한다. 승인 명령은 CI에서 실행하지 않는다.

```sh
npm run llm:combo-approve -- --champion Ambessa --reason '공식 패치와 원문 변경을 모든 연계의 발동 조건·순서와 대조한 근거'
npm run llm:bundle
npm run llm:note-tr
npm run llm:carry -- --force --matchups-only
npm run llm:combo-review
```

승인 근거와 전후 지문은 `knowledge/combo-review-ledger.json`에 남는다. 다른 챔피언의 검수 이력은 바꾸지 않는다. 최초 백필 스크립트는 기준 파일이 이미 있으면 실패하므로 다음 패치를 무심코 재승인할 수 없다.

## 확인 기준

- 현재 355개 노트 유지, 검수 대기 0개.
- 실제 26.19→26.20 원문·CDragon 수치 재생: 변경 없음 287개, 자동 호환 확인 2개, 보수적 검수 대기 66개. 상세 결과는 `patch-26.20-replay.json`에 있다. 이는 현재 정책으로 과거 변경을 재생한 시험이며, 66개를 새로 승인한 결과가 아니다.
- 실제 암베사 피해 변경은 유지하고, 가상 충전 상한 3→4 변경은 두 콤보를 보류한다.
- 의존 수치·지속시간·형태·스탯·미분류 변경 및 노트 편집은 보류한다. 손상된 기준 자료는 오류로 중단한다.
- 실제 생성기에서 보류 원문·옛 콤보·번역의 재노출을 차단하며, 실제 대화와 상성 답변 경로도 확인한다.

## 로컬 검증 기록

미분류 암베사 패시브 원본 필드만 바꾸고 툴팁은 그대로 둔 상태에서 실제 번들·번역·캐시 이월·검수 보고서를 실행했다. 암베사 2개만 보류하고 다른 353개 노트를 발행했으며, 전체 단위 검사 1,418건이 통과했다. 이후 원본 데이터와 LLM 파일 528개가 정확히 복원된 것을 확인했다.

모바일·데스크톱 및 검수 대기 안내를 확인한 브라우저 검사 3건, 빌드·타입·lint가 통과했다. 정상 상태의 회귀 측정 5,809건은 최신 성공 배포본과 답변·판정·개별 검사가 모두 같았다. 인프라 검사 12건, 측정 누락 0건, 새 회귀 0건이다.

호환 메타데이터가 데이터 지문을 바꾸므로 완결된 실측 결과로 회귀 기준을 갱신했다. 기존 실패 31건과 수동 검토 20건은 그대로 남기며 품질 승인을 뜻하지 않는다. 지문·비교·검증 근거는 `regression-migration.json`에 기록했다.

같은 원문으로 번들·번역·캐시 이월을 다시 실행해도 생성 시각만으로 새 자료를 만들지 않는다. 실제 반복 실행에서 LLM 파일 528개의 바이트가 모두 같았고, 별도 생성기 시험에서는 노트가 바뀔 때 내용과 생성 시각이 함께 갱신되는 것을 확인했다.
